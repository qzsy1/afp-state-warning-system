# 五设备真实采集预检与工业网卡

## 统一 Readiness 合同

“立即检查”和“开始采集”使用同一份带配置指纹的 `ReadinessReport`。每个已启用接口依次记录：

1. `port_present`：物理端口存在且已绑定；
2. `endpoint_compatible`：端点、协议以及工业网络路径兼容；
3. `driver_open`：驱动或 DLL 已实际打开设备；
4. `protocol_identified`：设备身份和版本化协议档一致；
5. `channels_complete`：全部期望通道均有有效帧；
6. `values_valid`：数值、单位、量程和参考刺激语义通过；
7. `freshness_stable`：每个通道在检查窗口内连续更新且未陈旧；
8. `ready`：以上正式必需层全部通过。

端口存在、TCP 可连接、DLL 存在或任一通道有值都不是完整就绪。界面明确显示 `ready`、`partial`、`no_valid_frame`、`stale`、`network_path_invalid` 和 `hardware_protocol_unverified`，并显示失败层的修复动作。

`formal` 会话失败关闭：当前配置指纹对应的所有已启用接口必须为 `ready`。`degraded_engineering` 仅用于故障证据采集，必须显式停用具体接口并确认影响；该会话强制 `capture_only`，不能生成正式预测、停机建议、放行或判废结论。

## 模拟源与真实硬件状态隔离

模拟采集只执行 `source_open → schema_compatible → channels_complete → values_valid → replay_ready` 五层数据源检查。它不枚举 USB、HID、串口、PLC、ABB 或 UVC，也不会显示或覆盖上一次真实硬件失败。模拟文件缺列时只显示“模拟数据源/通道映射”错误。

真实硬件与模拟源分别缓存。真实检查缓存绑定 `acquisition_mode + execution_host/device_id + runtime_revision + config_fingerprint`；切换模式只切换可见缓存，不复用另一模式的结果。执行电脑、helper、服务运行修订或配置发生变化后，旧真实检查显示为过期并阻止正式开始。

## 无实物时如何解释发现结果

发现结果严格区分四类证据：`driver_available`（驱动/DLL可加载）、`endpoint_present`（系统当前枚举到端点）、`identity_verified`（设备身份符合设备档）和 `protocol_ready`（完整有效协议数据已到达）。前一层不能替代后一层：

- `detected=false` 占位项、只有 UVC DLL、通用 HID 或蓝牙虚拟 COM 不会自动绑定，也不表示设备在线；
- 串口绑定保存 VID/PID、序列号、位置和设备档身份。相同设备从旧 COM 迁移到新 COM 时显示 `moved_requires_confirmation`，确认前不能正式开始；
- PLC/ABB 的 `tcp_probe_reachable` 只表示某条路径接受了 TCP。只有物理工业路径有效且协议响应通过，才是设备就绪；FlClash/TUN 接受连接仍为 `network_path_invalid`；
- UVC 厂商调用失败保留失败阶段、原始返回码和 last-error 码。没有厂商权威码表时不猜测错误含义。

当前没有连接传感器时，`endpoint_present=false`、`not_connected` 或 `no_valid_frame` 通常可通过接线/供电恢复；但错误网卡、设备身份不明、M3232 协议未验收、PLC寄存器/字序、ABB资源路径、SMRF通道类型以及UVC标定等问题，接线后仍需配置或现场协议验收。

## Windows 物理工业网卡

PLC 和 ABB 应接入专用物理以太网卡。现场操作步骤：

1. 在 Windows 网络适配器中为该物理网卡配置设备网段的静态 IPv4 地址。例如设备为 `192.168.125.x` 时，可使用未冲突的 `192.168.125.y/24`；不要使用 APIPA `169.254.x.x`。
2. 保持设备网段为直连路由，并在接口卡中选择这块网卡。检查报告必须记录所选网卡标识、Windows 最佳路由、实际源地址和 `direct_physical` 路由类型。
3. 实际源地址必须属于所选网卡并与设备处于配置网段。PLC Modbus/TCP 和 ABB RWS 套接字会绑定该源地址。
4. 排除 FlClash、Clash、TUN/TAP、Wintun、VPN、WireGuard、OpenVPN、Hyper-V、VMware、VirtualBox、回环接口和 `198.18.0.0/15` 代理测试网段。即使这些路径能返回 TCP 成功，也必须报告 `network_path_invalid`。
5. 修改网卡、端点、通道映射、设备档、执行端或软件运行修订后必须重新执行立即检查；旧报告因缓存身份不匹配而不能用于开始采集。

## 五设备语义检查

- PLC：选用版本化设备档，记录 Modbus 单元标识、FC03、寄存器地址、字序、字节序、倍率、单位、有效范围及参考刺激/公差。有限浮点值若与参考值不符仍失败。
- ABB：记录 RWS 授权结果、机械单元、robtarget 路径、Base 坐标系、RAPID 任务/模块/速度变量和单位。首个位置点没有来源时间差，不能把默认零速度当作有效速度；至少第二个连续点才可完成线速度就绪。
- SMRF：核对 HID 产品、序列号、VID/PID、命令响应、异或帧校验、八路通道类型、冷端补偿和校准偏置。设备报告类型与默认全 K 型冲突时必须确认或采用设备配置；断偶、超量程和校验失败按通道报告。
- UVC：分别检查 DLL 存在、设备打开、连续有效帧、256×192 尺寸、量程码、`raw/64-50` 温度换算、ROI 和参考温度公差。只有 DLL 没有相机时为 `no_valid_frame`，不能通过。
- M3232：按《M3232压力传感器集成说明》先做只读安全抓帧。实物协议证据完成前，即使 JSON 矩阵仿真产生 `薄膜压力`，也保持 `hardware_protocol_unverified`。

## 现场检查清单

- 设备电源、线缆、物理端口和 Windows 驱动均已核对；
- PLC/ABB 静态地址、子网掩码、最佳路由与实际源地址符合直连要求；
- 五份设备档和接口通道映射与当前现场修订一致；
- 全部期望通道在检查窗口内至少连续两次有效更新，无缺失、无效或陈旧；
- 正式开始前保存 Readiness 报告；如配置有任何变化，重新检查。
