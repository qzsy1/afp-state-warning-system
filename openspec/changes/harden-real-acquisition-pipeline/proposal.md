# Proposal

## Why

当前系统的模拟、界面和传输回归已覆盖大量软件路径，但真实五设备联采仍存在会直接影响数据与预警可信度的确定性风险：真实模式缺少统一采样时钟、异步设备会形成不完整且不同步的数据行、M3232 通道与实物帧合同不闭合、预测门禁会被历史缺失永久阻断，且端口可达、单通道有值和真实可用仍可能被混为同一状态。无实物复检还证明模拟源状态会复用真实硬件状态、代理TCP可达会误导发现摘要、仅有驱动或占位端点可能被当作可绑定设备，旧运行修订的检查缓存也可能污染当前页面。必须在现场正式采集前建立端到端、失败关闭且可审计的真实采集合同，并把模拟与真实证据边界彻底隔离。

## What Changes

- 为真实五设备采集建立统一单调采样时钟、独立驱动缓存、逐通道原始时间戳、新鲜度和确定性组帧合同；原始高频流与固定 10 Hz 模型流分离。
- 补齐 M3232 实物协议获取、帧校验、`薄膜压力` 规范通道及从驱动到 CSV 的端到端合同；禁止以 JSON 模拟帧替代实物协议验收。
- 将接口检查拆分为物理绑定、端点打开、协议身份、全部必需通道、数值有效性、新鲜度和连续稳定性，禁止“任一通道有值”代表完整就绪。
- 将模拟数据源检查与真实硬件Readiness拆成独立状态空间；模拟模式不得探测物理设备、显示缓存硬件错误或覆盖真实检查证据，模拟缺失通道只能报告为数据源/映射问题。
- 新页面和本机管理入口安全默认选择模拟采集，模拟采集中的五类逻辑接口立即显示为“模拟接口正常/物理检查不适用”，并与模拟数据源是否已打开、通道是否完整分别呈现；真实采集必须由操作员显式切换，失败接口保留规则诊断入口，并在授权模型可用时允许提交同一证据执行LangChain增强诊断。
- 将“驱动可用、占位端点、物理端点存在、设备身份确认、协议数据就绪”定义为不可互相替代的证据；未检测端点、蓝牙虚拟串口和代理TCP表面可达不得被自动提升为真实设备绑定或设备在线。
- 让检查结果绑定采集模式、执行端、运行修订和配置指纹；任一维度变化必须使旧结果失效，所有管理员/公共状态投影必须保留完整的新状态语义。
- **BREAKING**：真实采集和预测改为失败关闭。已启用的必需接口或模型通道不完整、陈旧、频率不兼容或走代理/虚拟网卡时，不再沿用此前的部分成功状态；只有显式停用或明确批准的降级方案才能继续。
- 预测只使用检查点声明的输入子集和采样频率；以最近连续 24 个完整模型点作为预测门禁，以 24 点历史加 24 点实测作为首个完整预警窗口。缺失、陈旧或越界数据必须显示不可判定，不能显示正常。
- 明确四项工艺参数是受控输入而不是预测输出，薄膜压力在当前检查点中仅采集保存；只有新检查点和健康指标明确声明后才能参与预测或预警。
- 建立真实数据质量、CSV/时间戳/MySQL/helper/服务器行数对账、停止终结、失败恢复和证据保留合同。
- 建立本机、真实局域网、授权公网、第二台 Windows 电脑和五类实物设备的分级 Go/No-Go 门禁，并把自动化、协议仿真和现场证据严格区分。
- 将新增需求映射进现有 harness；自动化可验证项必须失败关闭，缺少实物或异机证据时发布报告必须保持现场未验证，不能宣称真实采集通过。

## Capabilities

### New Capabilities

- `deterministic-real-acquisition`: 真实设备独立采样、统一时钟组帧、逐通道时间戳与新鲜度、原始流和模型流频率边界。
- `physical-sensor-readiness`: 模拟/真实检查隔离、五类物理设备的发现与身份、通道完整性、工业网络直连、M3232 实物帧、状态投影及严格启动门禁。
- `live-prediction-safety`: 检查点输入输出范围、连续窗口、频率适配、工艺参数来源、不可判定状态和真实预警影子运行。
- `capture-persistence-integrity`: CSV、时间戳、helper、服务器和 MySQL 的行级一致性、原子终结、失败恢复与审计证据。
- `real-acquisition-release-gate`: 本机、局域网、公网、异机和五设备现场验收的分级证据及发布 Go/No-Go 规则。

### Modified Capabilities

- 无。当前项目尚无已归档主规格；本变更会与进行中的 `usb-dock-interface-discovery`、`remote-acquisition-transport` 和 `release-regression-gate` 保持边界一致，并在归档顺序上解决潜在重叠。

## Impact

- 采集核心：`visualization_app/acquisition.py`、`smrf_hid.py`、五类设备驱动、通道映射和状态模型。
- 推理与预警：`app.py`、`online_inference.py`、健康指标运行时、检查点元数据和实时 API。
- 远程链路：local helper 的采样/保存/上传解耦、服务器批次接收、WebSocket/HTTP 状态投影和前端执行端提示。
- 持久化：原始 CSV、时间戳文件、层/试样合并、helper-local 与 server-target MySQL、pending retry 和完整性摘要。
- 网络与部署：工业网卡静态地址/直连路由、代理与虚拟网卡排除、LAN/公网域名与 helper 固定配对地址、运行修订与检查缓存失效。
- 前端与状态API：模拟源就绪和真实硬件Readiness使用独立渲染与缓存；公共状态完整投影 `network_path_invalid`、`hardware_protocol_unverified` 等状态。
- 验证：新增驱动集成、确定性时钟、缺失/陈旧/重连、10/50 Hz 重采样、行数对账、真实设备刺激和长期耐久检查；更新 harness 追踪矩阵与交付证据。
