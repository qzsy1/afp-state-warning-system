# Design

## Context

动机见 [proposal.md](proposal.md)。当前真实采集在单线程内依次读取五类驱动，只在模拟模式使用单调时钟；任一驱动返回部分数据即可形成一行。SMRF约每200 ms请求一次，而PLC、ABB、UVC和M3232具有不同阻塞与更新节奏，因此现有行既不保证10 Hz，也不保证通道同一时刻或完整。

当前检查将“任一期望通道有值”视为接口成功，实时接口状态也以任一健康通道判定整体正常。预测层又要求当前内存缓存的全部历史行在所有模型输入上均有限，一个早期缺失可长期阻断推理。M3232实物帧未确认，驱动输出`压力`但接口分配要求`薄膜压力`。

无实物环境复检暴露出另一条独立风险链：模拟模式复用真实硬件检查对象和接口卡渲染；驱动/DLL存在或占位端点可被误认为物理设备；PLC/ABB的TCP探测可被FlClash等TUN接管；公共状态对未登记的新失败码会退化为`unchecked`；运行服务未重启时，磁盘上的新前端资源与内存中的旧后端模块可能形成混合修订。接上传感器只会消除部分“端口不存在”，不会自动解决这些软件、路由、身份和协议问题。

远程helper已有单在途ACK、断线重传和保存边界，本设计不重新定义该传输协议，而是让helper和本机管理员复用同一个确定性采集内核。公网预计算演示继续与真实采集隔离。

约束：

- 保留五类逻辑接口及原有物理协议，不以通用JSON驱动替换实物驱动。
- 保留17个采集通道；当前检查点只使用其中16个传感器通道和4项工艺条件。
- 当前模型序列长度和预测长度均为24，训练/展示基准为10 Hz。
- 保存、网络上传、数据库、预测和浏览器绘图不得反向限制设备采样。
- 现场设备协议和真实缺陷真值不能由模拟或环回数据推断。

## Goals / Non-Goals

**Goals:**

- 建立一个本机与helper共用的、时钟驱动而非驱动返回驱动的采集内核。
- 让每个通道的值、来源时间、年龄、质量和填充策略可追踪。
- 使检查、正式启动、预测准备和发布验收使用同一分层状态语义。
- 让模拟数据源就绪与真实物理Readiness拥有独立状态、缓存和渲染合同。
- 让发现、绑定和状态投影准确区分驱动可用、设备存在、身份确认、路径有效和协议就绪。
- 在不丢失高频原始证据的前提下生成与检查点兼容的10 Hz模型流。
- 让文件、传输和数据库可以按`capture_uuid + frame_sequence`对账。
- 把真实预测限制为可解释的影子模式，直至真实标签完成批准。

**Non-Goals:**

- 本变更不重新训练包含`薄膜压力`的新预测模型。
- 本变更不定义M3232未知字节协议的具体常量；具体值必须来自实物抓帧与供应商证据。
- 本变更不改变公网预计算演示的数据生成或浏览器本地播放合同。
- 本变更不允许以服务器硬件替代访问电脑helper硬件。
- 本变更不把代理、VPN或隧道配置成工业设备网络的替代路径。

## Decisions

### 1. 每个物理接口使用独立 DriverWorker

每个已启用接口由独立工作单元负责打开、读取、重连和关闭。工作单元向有界缓存发布标准化`ChannelSample`：

- `interface_id`、`channel_name`、`value`、`quality`
- `device_timestamp`（设备提供时）
- `received_wall_time`与`received_monotonic`
- `source_sequence`或驱动局部序号
- 协议校验与错误摘要

每个通道保留最新样本和小型诊断环形缓冲；满载时允许丢弃旧诊断副本，但不得覆盖尚未持久化的正式统一帧。

选择该方案是因为设备API的阻塞行为、频率和重连方式不同。备选“继续顺序轮询并缩短超时”仍会让最慢驱动决定所有通道频率；备选“每个通道一个进程”隔离更强，但对当前五类本机驱动的部署和IPC成本过高。可能永久阻塞的供应商调用由现有helper可终止检查边界或可重启子进程包裹。

### 2. FrameAssembler以会话单调时钟产生统一帧

`FrameAssembler`按`deadline(n) = start_monotonic + n / frame_rate`运行。每个期限从各通道缓存选择不晚于期限的最新样本，计算年龄，并根据通道配置标记：

- `measured_new`
- `held_within_freshness`
- `interpolated`（仅批准的离线/模型重采样路径）
- `missing`
- `stale`
- `invalid`

原始宽表继续作为兼容主文件，但新增逐通道质量/时间侧车；必要时增加长表设备事件文件保存高于统一帧频率的原始样本。正式文件不得只保存值而丢失质量来源。

选择统一时钟可让帧数、时间轴和模型窗口可预测。备选“收到任意样本立即合并”无法证明频率和同步；备选“等待所有设备同一轮返回”会被最慢设备阻塞。

### 3. 原始流、统一流和模型流分为三层

数据路径为：

```text
设备事件流 → 统一采集帧 → 检查点兼容模型帧 → 预测/健康/预警
             ↘ CSV/质量侧车/数据库 ↗
```

- 设备事件流：尽可能保留原始频率和协议质量，用于诊断与重算。
- 统一采集帧：按会话配置频率形成17通道宽表，作为实时显示和标准保存边界。
- 模型帧：按检查点元数据生成。本次现有检查点固定10 Hz、24→24和16个传感器输入；重采样器采用版本化配置并坚持因果对齐，禁止未来值泄漏。

50 Hz用于设备/传输能力或高频原始证据时，不直接改变模型时间语义。当前检查点元数据将补充`sampling_hz=10`和重采样策略标识。备选“模型按当前页面频率自动解释”会使24点窗口物理时长变化，予以否决。

### 4. 新鲜度和完整性由配置档而非全局常量决定

每个接口档声明期望更新周期、最大新鲜度、是否允许短时保持、数值范围和正式必需通道。默认阈值由实物测量确定，未确定前保持现场待验证。统一帧完整性与接口更新率分别统计，避免把10 Hz统一帧误称为每个设备都在10 Hz产生新值。

预测输入只接受模型档批准的质量状态。SMRF若以5 Hz运行，可在明确的新鲜度和因果保持策略下形成10 Hz模型流，但质量侧车必须保留保持标记；若现场证据表明保持会改变模型语义，则必须提高设备更新率或重新训练，而不是静默填充。

### 5. ReadinessReport采用分层状态机

每个接口产生结构化状态：

```text
port_present
  → endpoint_compatible
  → driver_open
  → protocol_identified
  → channels_complete
  → values_valid
  → freshness_stable
  → ready
```

每层包含`state`、`evidence`、`started_at`、`finished_at`和`remediation`。整体接口只有全部正式必需通道通过才是`ready`；部分通道有值为`partial`。真实正式启动读取同一报告，不再维护另一套宽松判断。

提供两个采集策略：

- `formal`：默认；所有已启用必需接口失败关闭。
- `degraded_engineering`：操作员显式停用或批准缺失接口；保存证据但关闭正式预测和发布结论。

备选“所有模式均尽量开始”容易产生看似成功但不可用于模型的数据；备选“任何运行中单通道中断立即停止所有采集”会丢失故障证据。因此启动严格，运行中保留其他通道并将模型转为不可判定。

### 6. 工业网络检查绑定物理接口和源地址

PLC/ABB检查不再只做目标TCP连接。检查器读取Windows最佳路由和所选网卡信息，并将协议连接绑定到选定源地址；下列情况直接失败：

- 所选接口为APIPA、代理、VPN、隧道、回环或测试网段；
- 源地址不属于设备配置网段；
- 实际路由接口与操作员选择不一致；
- TCP连接存在但Modbus/RWS身份或内容不符。

这可以阻止FlClash等TUN设备把私有目标地址的端口探测伪装成真实工业设备在线。

### 6A. 模拟源和真实硬件使用独立Readiness命名空间

检查状态按采集模式在入口处分流：

```text
simulation → source_open → schema_compatible → channels_complete → values_valid → replay_ready
real       → port_present → endpoint_compatible → driver_open → protocol_identified
             → channels_complete → values_valid → freshness_stable → ready
```

模拟路径只描述CSV、文件夹或MySQL模拟源及其通道映射，不创建物理接口失败状态，也不更新真实硬件缓存。真实路径不接受模拟数据、JSON夹具或浏览器预计算结果作为物理证据。五类逻辑角色可在模拟页面用于解释通道分组，但界面标签必须是“模拟通道覆盖”，不能复用“物理接口检查”。

模式切换只改变当前可见状态源：从真实切到模拟时隐藏真实错误但保留其审计缓存；返回真实模式时，仅在缓存身份仍匹配时恢复，否则显示过期并要求重检。备选“继续复用一个hardwareCheck对象并根据字段猜模式”容易产生状态泄漏和错误颜色，予以否决。

模拟模式的五类卡片表示逻辑协议与通道分组，不代表物理设备。进入模拟模式后这些卡片统一显示`simulation_normal`（界面文案为“模拟接口正常”），物理端口层标记不适用；模拟源尚未选择、文件不可读或通道缺失仍由独立的`simulation_readiness`失败关闭。页面必须同时显示当前“采集来源”，并明确“仅采集”只是关闭预测而不是切换为模拟采集。

真实Readiness失败结果必须转换为结构化诊断事件。内置规则诊断始终可运行；管理员或授权会话配置模型后，可把同一份只读取证据提交给LangChain增强诊断。诊断调用失败时保留规则结果和原始错误，诊断结论不得修改Readiness、自动重绑接口或解除真实启动门禁。

### 6B. 发现证据按层级建模并限制自动绑定

每个候选端点分别记录：

- `driver_available`：库、DLL或通用系统驱动可加载；
- `endpoint_present`：当前系统确实枚举到物理端点；
- `identity_verified`：VID/PID、序列号、产品字符串、设备档或命令响应匹配；
- `protocol_ready`：检查窗口内得到完整有效协议数据。

只有满足当前设备档自动绑定条件的`endpoint_present`候选才可自动选择。`detected=false`占位项只用于说明所需驱动，不进入真实绑定；通用HID、蓝牙COM和未识别串口不得自动替代SMRF或M3232。M3232保存设备身份而非固定COM号，运行时由身份解析当前端点；身份不明时要求人工确认。

网络发现同时返回`tcp_probe_reachable`、`network_path_valid`和`protocol_ready`。前者即使为真也不得生成“PLC/ABB可达”结论。UVC等供应商API失败时保留调用阶段、原始返回码和最后错误码；没有权威错误码表时只报告已证实的失败层，不猜测原因。

### 6C. Readiness缓存绑定运行身份并完整投影

真实检查缓存键至少包含：

```text
acquisition_mode + execution_host/device_id + runtime_revision + config_fingerprint
```

任一值变化会使旧结果变为`stale`，不能解除启动门禁。服务健康接口、浏览器bootstrap和helper能力必须暴露可比较的运行修订；浏览器发现前后端修订不一致时提示刷新、重启或重新部署，并禁止沿用旧检查。

核心、管理员页面、公共状态和helper状态使用同一规范状态目录。投影层可以隐藏物理标识和敏感细节，但必须保留失败语义；已知的`network_path_invalid`等状态不能退化为`unchecked`。客户端遇到未登记的非成功状态时保留原始码并安全显示为未知失败，而不是猜测成功或未检查。

### 7. M3232采用“先抓帧、后实现、再锁定样例”的闭环

先提供只读/受控原始串口捕获模式，记录波特率、开始/停止命令响应、帧间隔、定界、长度、校验和矩阵变化，同时遮蔽与设备身份无关的敏感信息。获得实物证据后实现解析器，并固化脱敏原始帧夹具。驱动标准输出唯一使用`薄膜压力`；`压力峰值`等辅助指标作为质量元数据或显式扩展通道，不得覆盖PLC`压力`。

在实物协议确认前保留现有JSON矩阵作为模拟/协议夹具，但接口状态必须是`hardware_protocol_unverified`。备选“猜测二进制格式”不可验证且可能向设备发送错误命令，予以否决。

### 8. ModelInputBuilder只看最近连续窗口

预测门禁使用模型帧序列尾部的连续完整段：

1. 检查频率、通道集合、质量、时间间隔和工艺条件。
2. 最近连续段达到`seq_len=24`后允许预测。
3. 任一点无效即从下一完整点重新累计。
4. 健康/预警按预测原点冻结结果，等随后24个实际点完整到达后计算。

早期缺失保留在数据质量摘要中，但不永久污染恢复后的窗口。推理和健康计算在独立执行边界运行，异常只影响预测状态，不停止采集。

### 9. 工艺参数使用带来源的ConditionSnapshot

四项工艺参数统一建模为`value + source + observed_at + confirmed + revision`。优先级为可信控制器实时值、经确认的运行配置、未确认默认值。未确认默认值可用于工程预览，但正式预测失败关闭。参数变化产生新revision并写入每个后续模型帧和会话清单。

### 10. 真实预警先影子运行并增加分布外保护

模型输出保留预测值，但正式状态层增加：

- `pending`
- `available_shadow`
- `indeterminate_data_quality`
- `indeterminate_out_of_distribution`
- `approved_production`

使用检查点缩放统计产生通道级分布外提示；初期阈值只用于保护和证据收集，不宣称缺陷识别。只有G5真实标签盲测批准后才能进入生产模式。薄膜压力在当前模型中始终显示“仅采集保存”。

### 11. 持久化使用单写入队列和会话清单

统一帧由本地文件写入器顺序落盘；数据库和网络各自消费不可变帧批次。所有目标使用`capture_uuid + frame_sequence`幂等标识。内存队列有界并具有高水位：

- 文件写入无法维持时，正式采集安全停止并保留partial，禁止丢弃正式帧；
- 数据库或网络变慢时，本机文件继续，目标进入积压/待重试；
- 浏览器只消费合并视图，永不成为背压源。

会话清单记录版本、接口、模型、网络、工艺条件、文件哈希、各目标首末序号、行数和质量摘要。停止状态机按`sampling_stopped → local_finalizing → transport_flushing → persistence_reconciling → completed/failed_persistent`推进。

### 12. 本机和helper复用采集内核，服务器只接收规范帧

本地管理员直接在服务器电脑运行同一采集内核；远程模式在访问电脑helper内运行。服务器接收规范帧和质量元数据，保持既有ACK与幂等合同，不访问访问电脑设备。浏览器状态投影明确执行端、统一频率、设备更新率、积压和预测可用性。

### 13. Harness按证据等级编排而不伪造现场结论

为五份能力规格建立需求ID和矩阵项：

- quick：解析器、通道映射、时钟、最近窗口、状态机和前端契约。
- full：虚拟时钟6000/30000点、阻塞驱动、缺失/陈旧、断线重传、文件/数据库对账。
- release：交付哈希与G0自动项，并检查G1–G5证据清单。
- field：单设备刺激、五设备600秒、第二台电脑LAN、公网真实helper、真实标签。

已有`remote-acquisition-transport`继续拥有ACK和网络传输细节；已有`usb-dock-interface-discovery`继续拥有物理拓扑；本变更只消费其结果并提高真实就绪与发布门禁。

## Risks / Trade-offs

- [严格门禁使原来可开始的部分采集被阻止] → 提供显式`degraded_engineering`，但永久标记且禁用正式预测。
- [增加并发工作单元带来线程与关闭复杂度] → 统一生命周期接口、总关闭期限、故障注入和线程泄漏测试。
- [质量侧车和设备事件流增加磁盘量] → 使用分块写入、可配置事件保留和启动前空间预算；正式统一帧不可丢。
- [5 Hz热电偶到10 Hz模型的保持策略可能产生分布偏移] → 先用真实健康数据比较策略；不通过则提高设备速率或重训模型。
- [50 Hz原始流与10 Hz模型流对账更复杂] → 保存父子序号、重采样版本和源时间范围，使每个模型点可回溯。
- [Windows代理/TUN环境复杂] → 以实际路由和源地址为证据，不依据网卡名称；提供明确绕过配置指南。
- [接上传感器后占位端点或通用驱动被误认为匹配设备] → 自动绑定要求当前端点存在及设备档兼容，驱动可用性仅作提示。
- [模拟与真实状态复用导致硬件错误污染模拟采集] → 在模式入口分流状态模型、缓存键和渲染器，并增加双向切换回归。
- [运行中热更新形成新静态资源与旧后端模块混合] → 以运行修订握手和检查缓存失效失败关闭，部署后显式重启服务。
- [供应商错误码缺少权威说明] → 原样保留调用阶段与代码，只给出通用排查步骤，待厂商资料确认后再版本化解释。
- [M3232协议需要实物且存在误发命令风险] → 首次只捕获供应商软件/设备已知安全交互，未经确认不发送猜测命令。
- [真实标签数量不足导致预警长期处于影子模式] → 把影子模式作为安全默认，并提前设计标签、盲测和质量结果回填流程。
- [跨change归档时出现能力重叠] → 先同步/归档`release-regression-harness`，协调`usb-dock-interface-discovery`和`fix-remote-acquisition-workflows`的未完成现场项，再归档本变更；冲突时保留更严格且更新的失败关闭语义。

## Migration Plan

1. 为现有会话配置增加版本和`capture_policy`，旧真实配置迁移为`formal`；未确认工艺默认值保持可见但不再产生生产有效预测。
2. 先引入标准样本、质量状态、DriverWorker和FrameAssembler，使用模拟/协议夹具与旧文件并行比对，不立即删除旧读取路径。
3. 先拆分模拟源与真实硬件状态、收紧物理端点自动绑定、补齐运行修订握手和状态投影，再接入五类驱动；实物协议未确认时保持现场未验证。
4. 增加质量侧车、会话清单和行数对账；确认下游仍可读取兼容宽表。
5. 将预测切换到10 Hz ModelInputBuilder和最近连续24点门禁；先仅影子显示新旧结果差异。
6. 将本机与helper切换到新采集内核，完成虚拟时钟、断线、磁盘和数据库故障回归。
7. 按G0至G4逐级现场验收；G2/G3/G4未通过前不发布“真实采集就绪”结论。
8. 收集真实标签并完成G5后，单独审批是否启用生产预警。

回滚时保留新格式原始文件和清单，只切回旧运行入口；不得把新格式数据覆盖为旧结果。若新采集内核影响正式采集，回滚交付版本并把对应G阶段标记失效，重新执行受影响验收。

## Open Questions

- M3232实物的安全开始/停止命令、帧格式、校验和压力换算需由现场原始捕获和供应商资料确认。
- SMRF现场能够稳定达到的设备更新率，以及5→10 Hz保持策略对当前检查点误差的影响需由G1/G2数据确定。
- PLC实际寄存器、字序、倍率和ABB RobotWare/RWS资源路径需按现场控制程序冻结为版本化设备档。
- UVC设备打开返回码`-2`的权威含义、厂商驱动/固件兼容矩阵，以及发射率、量程、ROI和允许温度偏差需在G1前由厂商资料和测量负责人确认；确认前只报告设备打开失败层。
- SMRF实物VID/PID、产品字符串及M3232 USB转串口身份字段需在首次接入时冻结，避免通用HID、蓝牙COM或变化的COM号被误绑定。
- G5生产预警的最低真实样本量、误报/漏报上限和审批人需由质量负责人确定；在此之前影子模式不变。
