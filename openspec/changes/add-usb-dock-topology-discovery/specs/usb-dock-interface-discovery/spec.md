# Spec Delta

## Purpose

本能力用于在 Windows 采集电脑上识别 USB Hub 与拓展坞的物理端口拓扑，向操作员完整展示同类型可用接口及其所属拓展坞，同时保持端口存在、设备兼容和传感器数据验证之间的清晰边界。

## ADDED Requirements

### Requirement: Windows USB 拓扑发现
系统 SHALL 在支持的 Windows 环境中发现 USB Hub、每个下行物理连接器、连接状态、支持的 USB 协议和当前所接设备，并 SHALL 包含没有接入设备的可用端口。电脑本机端口记录 MUST 以 `confirmation` 区分 `observed_current` 与 `observed_history`，不得把未经观察的控制器逻辑端口发布为物理接口。系统 MUST 将拓扑查询与传感器数据读取分开，发现端口时不得要求传感器正在输出数据。

#### Scenario: 显示空闲和占用端口
- **WHEN** 操作员刷新接口，且一个拓展坞包含空闲端口和已接设备的端口
- **THEN** 系统 MUST 返回该拓展坞的全部可查询物理连接器，并分别标记为空闲、已占用或具体异常状态

#### Scenario: 递归发现下级 Hub
- **WHEN** 一个 USB Hub 的下行端口连接另一个 Hub
- **THEN** 系统 MUST 保留父子层级并继续发现下级 Hub 的物理端口，且不得把下级端口错误归到上级 Hub

#### Scenario: 电脑原生 USB 端口与拓展坞端口同时存在
- **WHEN** Windows 能够确认电脑 Root Hub 上的用户可连接端口，且电脑同时连接一个拓展坞
- **THEN** 系统 MUST 同时返回经过当前占用或历史观察确认的电脑原生 USB 物理端口和拓展坞外部 USB 端口，并 MUST 排除不可供用户连接的内部设备端口；连接拓展坞的电脑上游插孔 MUST 作为已占用的电脑原生物理端口保留

#### Scenario: Root Hub 报告未实际布线的可连接端口
- **WHEN** Windows 将某个空 Root Hub 逻辑端口报告为 `user_connectable`，但该端口从未出现设备或下级 Hub，也没有本机历史观察记录
- **THEN** 系统 MUST NOT 将该逻辑端口显示为电脑机身物理插孔，并 MUST NOT 仅凭 `user_connectable` 推断机身端口数量

#### Scenario: 已观察本机端口恢复为空闲
- **WHEN** 一个经过设备或下级 Hub 实际占用确认的电脑原生端口被持久记录，随后设备被拔出
- **THEN** 系统 MUST 继续以相同端口标识显示该端口，将状态更新为空闲，并将 `confirmation` 从 `observed_current` 更新为 `observed_history`

### Requirement: 伴随 Hub 合并为物理连接器
系统 SHALL 使用 Windows 报告的伴随端口关系，将共享同一连接器的 USB 2.x 与 SuperSpeed 端口合并为一个逻辑物理端口。系统 MUST 保留各通道支持的协议和状态，且在缺少可靠伴随关系时不得仅凭端口数量猜测合并。

#### Scenario: 三口拓展坞具有两套 Hub 实现
- **WHEN** Windows 将同一拓展坞报告为相互关联的 USB 2.x Hub 与 SuperSpeed Hub，且每套实现映射到三个共享连接器
- **THEN** 系统 MUST 显示三个逻辑 USB 物理端口，不得显示为六个

#### Scenario: 无法确认伴随关系
- **WHEN** 两个 Hub 的端口数量相同但 Windows 未提供可靠伴随映射，也没有匹配的受信硬件拓扑规则
- **THEN** 系统 MUST 保留独立拓扑并将合并状态标记为未知，不得静默合并端口

### Requirement: 拓展坞内置功能与外部端口分类
系统 SHALL 将能够确认属于拓展坞的内置 USB 网卡等固定功能关联到对应拓展坞，并 MUST 仅在系统属性或受信硬件拓扑规则确认该连接器不可供用户外接时，将其排除在外部 USB 端口数量之外。

#### Scenario: 三个 USB 口和一个内置网口
- **WHEN** 已识别拓展坞具有三个用户可连接的 USB 物理端口，另有一个内部端口连接 ASIX 网卡
- **THEN** 系统 MUST 显示三个外部 USB 端口和一个“拓展坞网口”，不得把内置网卡连接显示为第四个外部 USB 口

#### Scenario: 内置属性不能确认
- **WHEN** 一个已占用连接器无法被系统属性或受信规则确认是内置功能
- **THEN** 系统 MUST 保留该 USB 端口的可见性并显示当前设备，不得为减少端口数量而隐藏它

### Requirement: 稳定端口身份和系统标签
系统 SHALL 为拓展坞和物理端口生成确定性的系统标识与显示标签。在同一电脑、同一上游连接位置和同一拓扑下刷新或重新连接时，端口标识 MUST 保持稳定；系统 MUST 不把系统端口号解释为拓展坞的左、中、右物理方位。

#### Scenario: 拓展坞重新连接到原位置
- **WHEN** 操作员断开拓展坞并重新连接到同一电脑的原上游端口
- **THEN** 系统 MUST 恢复相同逻辑拓展坞和端口标识，并以系统端口号生成一致标签

#### Scenario: 拓展坞连接位置改变
- **WHEN** 无序列号拓展坞被移动到不同上游 USB 端口，导致系统无法证明它与原拓展坞实例相同
- **THEN** 系统 MUST 生成新的位置相关标识或标记身份不确定，不得错误继承原位置的绑定

### Requirement: 按物理传输类型和位置完整显示候选项
接口界面 SHALL 按物理传输类型和所属位置组织候选项。所有通过 USB 连接的标准传感器 MUST 显示同一个完整用户可连接 USB 端口池，包含电脑原生和拓展坞端口；HID、UVC、COM 等通信端点 SHALL 作为端口当前设备属性表达。以太网接口 MUST 显示所有可用网卡，真正不经过 USB 的主机原生串口 SHALL 作为独立候选保留。

#### Scenario: 三类 USB 传感器显示相同完整端口池
- **WHEN** 操作员分别为热电偶、UVC 和 M3232 选择实际接口，且电脑原生 USB 口与拓展坞三个外部 USB 口可用
- **THEN** 三个逻辑接口 MUST 显示相同的完整 USB 物理端口集合，包括空闲端口、已接兼容设备的端口和已接不兼容设备的端口，并显示各自状态

#### Scenario: USB 转串口显示在所属物理端口下
- **WHEN** M3232 使用的 USB 转串口设备连接在拓展坞端口并由 Windows 枚举为 COM8
- **THEN** 页面 MUST 将 COM8 显示为该拓展坞 USB 端口的通信端点，并 MUST 同时保存该物理端口标识和 `serial:COM8` 实时接口标识

#### Scenario: 真正的主机原生串口
- **WHEN** Windows 报告一个无法关联到任何 USB 设备或 USB 位置路径的主机原生 COM 口
- **THEN** M3232 候选列表 MUST 在独立的主机原生串口分组中保留该 COM 口，其他 USB HID 或 UVC 角色不得把它作为正常候选

#### Scenario: 网卡显示拓展坞归属
- **WHEN** ASIX 网卡的父级拓扑属于已识别拓展坞
- **THEN** 以太网候选列表 MUST 将其显示为该拓展坞的网口，同时继续显示其他可用网卡

#### Scenario: 排除无关类型
- **WHEN** 操作员配置某种逻辑接口
- **THEN** 系统 MUST 显示该物理传输类型的完整候选项，并通过兼容状态说明当前端点是否适用于该传感器，不得把真正的主机原生 COM 口作为 USB HID 或 UVC 的正常候选项

### Requirement: 标准接口具有稳定默认选择
系统 SHALL 在真实模式完成接口发现后为已启用的标准逻辑接口生成默认物理选择。默认算法 MUST 优先保留已保存和手动选择，其次选择已连接兼容设备，再按稳定顺序选择未分配的可用物理端口；刷新 MUST NOT 迁移手动选择。

#### Scenario: 三个 USB 角色和三个空闲端口
- **WHEN** 热电偶、UVC 和 M3232 均已启用，且存在三个未分配的用户可连接 USB 端口而没有已保存选择
- **THEN** 页面 MUST 为三个角色分别默认选择一个不同的 USB 物理端口，并 MUST 保持选择值在页面中可见

#### Scenario: 已连接兼容设备优先
- **WHEN** 某个 USB 端口已连接与逻辑接口协议兼容的设备，其他端口为空闲
- **THEN** 系统 MUST 优先将该逻辑接口默认绑定到兼容设备所在端口，再为其余逻辑接口分配未占用端口

#### Scenario: PLC 与 ABB 默认共享可用网卡
- **WHEN** PLC 与 ABB 均已启用且没有已保存选择，同时存在可用网卡
- **THEN** 系统 MUST 为两者默认选择可用网卡，并 MAY 按既有共享规则选择同一网卡

#### Scenario: 手动选择在刷新后保持
- **WHEN** 操作员手动更换某个接口的物理端口后刷新接口发现
- **THEN** 页面 MUST 保持该手动选择；设备拔出时仅清除实时端点和验证状态，不得自动迁移到其他端口

### Requirement: 端口预选与设备验证分离
系统 SHALL 允许操作员预选空闲 USB 物理端口，但 MUST 分别记录端口选择、兼容设备识别和有效传感器数据验证。端口存在或端口被占用均 MUST NOT 单独使逻辑接口进入已验证状态，也不得绕过真实采集门禁。

#### Scenario: 预选空闲 USB 端口
- **WHEN** 操作员为 USB 类传感器选择一个空闲端口
- **THEN** 系统 SHALL 保留该端口选择并显示“端口存在，未检测到兼容设备”，且真实采集 MUST 保持不可开始

#### Scenario: 未验证物理端口仍执行原有接口检查
- **WHEN** 操作员点击“立即检查”，且逻辑接口已有可执行的原驱动和端点，但所选物理端口尚未与实时设备关联
- **THEN** 系统 MUST 继续逐项打开该驱动并读取所选传感器通道，MUST 分别报告数据读取结果和 `physical_unverified` 端口绑定状态，并 MUST NOT 因读取到数据而绕过真实采集门禁

#### Scenario: 兼容设备插入预选端口
- **WHEN** 兼容设备随后插入已选择端口并通过协议及数据检查
- **THEN** 系统 MUST 将实时设备与该端口关联并将接口标记为已验证，之后才能满足真实采集门禁

#### Scenario: 不兼容设备占用预选端口
- **WHEN** 已选择端口被不兼容设备占用
- **THEN** 系统 MUST 保留端口选择、显示所接设备不兼容，并 MUST 阻止该逻辑接口通过真实采集检查

### Requirement: 热插拔刷新保持拓扑一致性
系统 SHALL 在手动刷新和现有自动重新发现流程中重新计算 USB 拓扑，并 SHALL 按稳定端口标识更新选择状态。设备移除、设备插入或拓展坞断开 MUST 更新状态，且不得把旧设备继续报告为当前连接。

#### Scenario: 从已选端口拔出设备
- **WHEN** 已验证设备从当前选择的 USB 端口拔出后执行刷新
- **THEN** 系统 MUST 将端口更新为空闲、清除实时设备验证并阻止真实采集，同时保留对该物理端口的预选

#### Scenario: 拓展坞整体断开
- **WHEN** 已选择的拓展坞被断开
- **THEN** 页面 MUST 将相关端口显示为断开或不可用，且不得自动把逻辑接口重新绑定到另一个未选择的拓展坞端口

### Requirement: 本地 helper 拓扑来源隔离
远程真实采集模式 SHALL 由访问电脑上的本地 helper 执行 USB 拓扑发现，并仅向已授权会话返回规范化结果。服务器本机硬件 MUST NOT 混入 helper 结果；访客模拟模式 MUST NOT 通过该能力探测或暴露服务器及访问电脑硬件。

#### Scenario: 授权远程真实采集
- **WHEN** 已授权页面通过配对的本地 helper 请求接口发现
- **THEN** 页面 MUST 使用 helper 所在电脑的拓展坞、端口和设备结果，并 MUST 不追加服务器本机接口

#### Scenario: helper 未连接
- **WHEN** 远程真实采集页面没有已配对且在线的 helper
- **THEN** 系统 MUST 报告本机拓扑不可用，不得以服务器接口替代访问电脑接口

#### Scenario: 访客模拟访问
- **WHEN** 访客进入预计算模拟模式
- **THEN** 系统 MUST 不发起 USB 拓扑探测，并 MUST 不返回拓展坞实例、设备标识或底层位置路径

### Requirement: 可诊断降级和向后兼容
Windows 拓扑查询不可用、权限不足或局部失败时，系统 SHALL 返回明确的拓扑降级状态，并 SHALL 尽可能保留现有串口、网卡、已枚举 HID/UVC 设备和协议占位项。拓扑增强 MUST NOT 改变五类逻辑接口协议、通道映射、PLC/ABB 共用网卡规则或模拟采集行为。

#### Scenario: USB Hub API 查询失败
- **WHEN** 系统无法打开某个 Hub 或查询其端口信息
- **THEN** 接口发现 MUST 继续返回其他成功发现的接口和错误摘要，不得因单个 Hub 失败而使整个发现请求失败

#### Scenario: 非 Windows 或不支持的 Windows 版本
- **WHEN** 运行环境不支持所需拓扑查询
- **THEN** 系统 MUST 使用现有兼容发现路径并标明未提供物理 USB 端口拓扑，不得伪造空闲端口或拓展坞归属

#### Scenario: 原有五类采集配置
- **WHEN** 旧配置未包含 USB 物理端口字段
- **THEN** 系统 MUST 继续接受原有物理设备绑定，并在能够解析拓扑时补充端口关系，不得改写其驱动、协议和通道映射
