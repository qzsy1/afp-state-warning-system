# Tasks

## 1. 确认原生 USB 协议前置条件

- [ ] 1.1 先通过只拔下热电偶并保持断开、再插回时的完整 PnP 差异确定物理设备；无枚举变化时排查可传数据的线缆、仪表数据通信 USB 口、电脑直连端口和 USB 模式，有未知设备时再核对驱动。结合铭牌和实际通信设置更新 `hardware_facts`；必须以设备新增/消失及现场接线建立对应，COM5 应变片不作为热电偶，未知项保持未确认。
- [ ] 1.2 使用商家上位机单独连接当前原生 USB 候选，核实型号、64 路目录及至少一个真实变化的温度；验证退出后串口可供 AFP 打开，区分商家软件也不通和仅 AFP 不通。
- [ ] 1.3 针对公开 PDF 仅明确内部通讯 1/RS232 的边界，向厂商确认 USB 在 PC/Modbus 模式下的协议适用范围、握手、帧格式及 SDK 可用性；在已确认设置下只读验证，以合法响应和仪表温度对照选择 Modbus 路径，或以厂商依据选择 PC 路径。无法确定时明确协议阻塞，不推定驱动解析错误。
- [ ] 1.4 在 `docs/慧谱TCP64热电偶集成说明.md` 更新已确认的 USB 通信方式、配置要求和模式核对方法；逐项核对资料与实物，文档不把未确认 USB 协议写成有效规则。

## 3. 接通已确认协议并完善诊断

- [ ] 3.1 为 TCP64 连接检查提供端口打开结果、实际通信参数、请求范围、收发字节数、扫描耗时和分类错误；在既有协议及接口测试中覆盖占用、零字节超时、错误功能码、地址不符、CRC、分片与中途失败，确认只读且超时有界。
- [ ] 3.2 按 1.3 的协议结论接通实际 USB 路径：Modbus 通路复用现有 FC03 驱动并修正经证据确认的差异；PC 通路在取得厂商协议/SDK 后实现独立适配器并核实依赖位数和打包。用厂商样例和实机报文验证温度及完整通道映射；缺少 PC 依据时此任务保持阻塞，不以猜测协议完成。
- [ ] 3.3 统一页面、接口检查结果与 Helper 的物理发现、协议验证和温度质量展示；添加行为测试，验证停用不等于已采集、零响应提示核对模式/地址、修改配置撤销验证、现有采集会话拒绝冲突探针。
- [ ] 3.4 验证完整扫描发布、保持/过期质量及重连后的重新验证，必要时按实际扫描耗时调整新鲜度；用分块失败及重连夹具验证不混合半轮新值，不缩短六十四路目录，不将未知有限温度当作故障哨兵。
- [ ] 3.5 更新既有设备说明中的协议选择、只读检查、故障分类及厂商软件占用处理；按实际 AFP 界面复核步骤可以执行，不保存实施流水账。
