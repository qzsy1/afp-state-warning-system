两边均不将 `zMovespeed` 直接当成实际线速度。AFP 工艺参数读取 `T_ROB1/MainModule/zMovespeed` 的速度分量；参考程序可写工艺设定，实时线速度仍来自位置差分。

`zCorr` 与 XYZ 的 Z 不是同一量：参考导出中的 `zCorr` 来自其控制器内部展示命令，不能代替位置 Z；层偏置和路径状态也不能直接映射为 AFP 运动测量。参考程序还有 Mastership、压力命令/确认序号、RAPID 写入和报警控制，均非本次只读测量范围。

AFP 源码与固定运行目录的有效修订由发布清单、文件摘要和实际进程核验；仅磁盘代码一致不证明进程已加载同一修订。

离线核对使用 AFP 实际速度方法：位置 `(0,0,0)` 到 `(3,4,0)`，主机时间差 0.1 s，输出 50 mm/s，与参考源码公式一致；首点和非正时间差时 AFP 不输出有效速度，参考初始化为 0。该核对不等于执行完整 C# 程序或实物验收。

## Goals / Non-Goals

**Goals:**

- 在相同有效位置和时间依据下得到可复算的 XYZ 与速度，对齐 100 ms 目标轮询而非虚报实际采样率。
- 让采集行与位置来源分开，避免缓存或异步保存把旧坐标解释成新响应。
- 保持本机、helper、存储及模型对同一源样本的值和质量一致。

**Non-Goals:**

- 不构建第二套 C# 采集宿主，不复制控制优先级队列，不申请 Mastership，不执行运动或 RAPID 写入。
- 不新增层数、路径、角度、zCorr、层偏置等通道，不改变既有模型输入维度。
- 不保证两个独立进程逐点同步，不把位置差分速度等同于 `zMovespeed` 或控制器内部瞬时速度，不将轮询优化当作测量精度标定。

## Decisions

### 1. 保留读取资源与数值语义

沿用配置端点和现有 ROB_1/Base 资源，位置仍直接读取 x/y/z 并检验有限值。默认不增加 tool、wobj 或坐标变换参数，不通过偏置修正追求与未知参考值一致。已保存凭据、源网卡、超时、新鲜度及启停选择继续有效，超时不被错误地规范为 100 ms。

由明确的 ABB 测量档与算法版本标记来源，配置指纹纳入影响测量语义的字段。旧配置缺少新增档字段时采用本计划默认值；回放和模拟保持原合同。

不选择更换资源或读取 RAPID 的速度设定代替测量：这些会改变信号含义，不能解释已经确认使用相同位置资源的事实。

### 2. 复用独立工作线程与固定周期机制

ABB 使用 100 ms 固定周期目标，以单调时钟计算下一轮截止时间。驱动收发、调度、缓存年龄、统一帧截止、启动边界和本机显示传输共用高精度 `host_perf_counter` 时间域，不混减 `GetTickCount64` 读数。其他传感器统一主机时间戳，其协议、周期、换算和质量规则保持原合同。ABB 长等待使用停止事件，末段使用高精度短等待并复核截止；帧等待也复核截止，防止提前返回。请求耗时计入本轮，慢轮次跳过已经过去的时段，不重入、不发突发补读、不按遗漏 Tick 排队。记录实际请求间隔、响应耗时、轮次耗时、跳过周期数和成功率。

不复制参考程序后台请求队列：AFP 仅做测量，没有压力控制与报警写入优先级需求，复用现有适配器可避免引入无界排队。PLC 的固定周期实现可供复用，但改动以设备可选能力区分，不改变 PLC 参数和其他驱动默认循环。

### 3. 用实际时间与两个源位置计算速度

在响应体完整接收时记录主机单调时间和墙钟时间，同时保留请求开始时间。成功有限位置获得独立源序号及连接代次；没有设备时间戳时明确标记为主机接收依据，不将墙钟填充为已知设备采样时间。

速度使用同一连接代次中两个有效成功位置的欧氏距离除以单调时间差，再保留两位小数。保存前后位置关联、距离、实际时间差及时间依据，不能以固定 0.1 s 替代实际时间差。墙钟跳变不改变速度间隔；非正单调间隔不输出速度，重建计算基础。构造器增加可注入时钟时保持现有调用方式相容，并调整相关测试的时钟注入。

首点坐标有效而速度未验证；静止的第二个有效位置才能得到真实 0 mm/s。任何读取故障、重连或超过配置新鲜度的成功样本间隔都重建速度基础，不计算跨故障区间的平均速度。连接代次变化时旧速度不进入新代次的首点。

该选择与参考程序的墙钟差分、首点置零及跨故障保留历史不同，原因是已有两点速度合同及真实测量质量要求；不是逐行复制参考实现。

### 4. 来源记录绑定源样本而不是当前缓存

每个合法位置源记录保存响应中 x/y/z 的原始字段或白名单数值、解析 XYZ、资源路径、机械单元、坐标系、时间依据、主机收发时间、序号、连接代次、处理档及速度前后关联。原始响应没有设备序号/时间时使用空值而不合成设备事实。

复用已有通道元数据、记录接口、统一帧及时间戳侧车。统一帧仍只选截止时刻前的有效来源；沿用值保留旧来源序号、时间和质量，不能复制为新测量。保存层必须携带采样时固定的不可变来源快照，不能在异步写盘时再读驱动的最新状态。

错误记录使用严格 JSON 安全的分类和必要白名单信息，不保存含凭据、Cookie、Authorization 或完整任意响应的日志。不使用新增来源字段放宽公网访客权限。

### 5. 保持故障、传输与持久化合同

认证、HTTP、JSON 结构、非有限数值、资源缺失、会话上限和退出失败保留明确分类。新鲜度内旧值可按现有规则沿用，超时留空，不无限保持缓存，不伪造首点或故障速度 0。不得将沿用位置重新做速度差分产生新速度。

保留显式 Digest 质询、Cookie/连接复用、禁代理、源网卡绑定及连接源地址复核；退出只影响本客户端会话。对真实断开后的会话重新建立与首点状态增加生产路径测试，不通过禁用错误传播掩盖恢复失败。

helper 在自己的高精度单调时间域完成帧截止与年龄计算，服务器保留来源时间与帧年龄，不与服务器单调时间直接相减；墙钟对齐只用于离线对照。helper 声明 `abb_clock_domain=host_perf_counter`，能力不足时拒绝 ABB 检查与启动。本机、helper、连接检查和只读复现入口共享测量及来源合同；helper 能力必须表达新证据与时间依据，能力不足明确阻止该采集，不能回退到服务器设备或丢弃字段后声称等价。

曲线、WebSocket、主 CSV、MySQL 和符合既有准入的模型使用同一 XYZ/速度及质量。列名、单位和维度保持不变；来源保存在已有 JSON、侧车和会话清单，旧文件无需迁移或重写。页面只添加用户需要的速度依据、数据年龄和质量说明，完整来源放入诊断查看。

### 6. 验证实际生产路径与现场边界

复用 `test_abb_digest_contract.py` 的本机 HTTP/Digest 服务器夹具，覆盖实际请求路径、相同 XYZ、认证和会话；扩展相邻测试并用可控时钟覆盖 100 ms 调度、慢读、墙钟跳变、首点、静止、故障、重连与异步跨帧保存。期望速度来自已知轨迹及时间，不以源码字符串存在替代行为测试。

相同两点和时间的离线等价不能证明现场一致。现场先在机器人静止工况下比对双方同一控制器的原始 x/y/z、RWS 资源、机械单元、坐标系和接收时间。若需动态比较，只观察操作员已批准的既有运动，记录完整采样间隔、响应时间、路径与 `zMovespeed` 设定，不能为验收擅自启动运动或闭环。

动态速度为两个位置之间的平均，弯曲路径、加减速、网络延迟与排队可影响波形；采样更慢并不必然导致固定倍率偏低。容差需来自批准参考和测量依据，不用无依据倍率或偏置消除差异。

## Risks / Trade-offs

- [100 ms 目标提高 RWS 读取频率] → 单设备有界请求、跳过慢轮次、测量实际响应与会话数，不虚报 10 Hz，不引入控制队列。
- [单调时钟切换改变异常时间下的速度] → 来源声明时间依据，墙钟仅对账，覆盖跳变和舍入测试，不改写历史记录。
- [首点或恢复后缺速度被视为采集失败] → 通道质量明确说明两点验证，保持已有就绪规则，不用假零解除门禁。
- [helper 或保存层遗漏源记录] → 同一源序列贯穿本机/helper、统一帧、侧车和 MySQL JSON 对账，能力不足明确拒绝。
- [PLC 兼容更新或其他任务修改相同文件] → 在唯一 checkout 中串行工作，逐段保护既有修改，复用成熟接口并运行 PLC 合同回归，不把新计划当成覆盖他人修改的授权。
- [静止坐标偏移仍然存在] → 比对实际控制器、坐标资源、工具/工件配置与原始响应，保持根因未确认，不自动添加校正。
