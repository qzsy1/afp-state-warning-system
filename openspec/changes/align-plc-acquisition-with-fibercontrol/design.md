### 与其他接口的关系

- AFP 的 `压力/N` 来自 PLC；`薄膜压力原始响应/raw` 来自 M3232 串口 32×32 矩阵合计，没有有效标定时不能称为 N/kPa。最新版参考压力模块不使用旧串口矩阵；这不构成删除 AFP 独立 M3232 接口的依据。
- 实时 `线速度` 来自 ABB 相邻 XYZ 距离除以时间差；工艺参数 `zMovespeed` 是速度设定值。二者不属于此次 PLC 测量改动。
- 既有 `fix-plc-abb-uvc-real-acquisition` 约定了严格响应校验、网卡与实际源地址验证、接口隔离及缺测语义。本变更保持这些约束，不将参考程序的故障置零移植到有效测量链路。

## Goals / Non-Goals

**Goals:**

- 在相同合法寄存器输入下对齐三通道测量数值，并可追溯负压力规范化。
- 将 PLC 周期与来源时间描述清楚，使参考曲线与 AFP 的动态差异可以解释、定位。
- 为本机、helper、界面及持久化提供一致的值、质量和处理依据。

**Non-Goals:**

- 不复制完整 C# 项目或修改参考目录，不将其设备控制器接入 AFP。
- 不新增八路跳辊、平均通道、控制联锁、压力校准系数或模型维度。
- 不将连续采样系统宣称为与另一独立进程逐点同步；不以软件兼容结论替代载荷精度或 PLC 下位机版本验收。

## Decisions

### 1. 将兼容行为限定在真实 PLC 设备档

在现有 PLC 配置规范化和驱动构造处接入明确的测量兼容档标识；缺少该字段的真实 PLC 配置采用本计划的默认规则。保存档标识与算法版本到会话来源信息，保留显式地址映射、端点、Unit ID、网卡绑定和启停选择。模拟与文件回放不通过字符串匹配通道名触发截零。

不替换整个 C# 模块：它包含 UI、写入、闭环及 .NET 依赖；本方案复用 AFP 现有驱动、网络门禁和存储结构，避免出现第二套采集宿主。

### 2. 分开保存原始值与规范测量值

解码时先保留 low/high 两个 UInt16、原始有限 float32 值，再按参考规则保留两位小数；仅 PLC 压力进一步执行 `max(0, rounded_value)`。温度、张力不截零。三个通道都不做三点平均。

规范测量值供现有实时通道、主 CSV、MySQL 及符合既有质量准入的模型使用；负压力主通道语义变化在会话清单和界面说明中明确。原始寄存器、未裁剪值、规范值、地址、处理档、处理标识、源序号与时间通过已有来源记录及时间戳侧车保存，不能仅放在短暂状态面板。MySQL 已有 JSON 来源结构优先使用，不为此强制数据库结构迁移。旧文件不改写、不回填，旧侧车无新增字段时仍可读。

来源记录必须按源帧绑定，而不是读取写盘时的“最新驱动状态”。无效浮点只保存原始 words/位模式、分类与错误，严格 JSON 中不写 NaN/Infinity。原始层与规范层使用明确键和单位，避免把规范值再叫作串口原始字节。

不选择只在前端截零：这会让曲线、CSV、MySQL 和模型对应不同测量值，继续制造对照歧义。

### 3. 采用 PLC 独立的 100 ms 周期

生产默认三通道按温度、张力、压力顺序分别发送 FC03，每通道两个寄存器；显式自定义映射保持其配置地址，不恢复成默认地址。读取未启用通道遵循现有配置合同，不因兼容档自动启用设备。

调度使用单调时钟的固定周期截止时间，100 ms 是一轮目标周期，不是读完再额外睡 100 ms。慢轮次跳过已过截止时间，不并发重入或突发补读。记录实际周期、轮次耗时、跳过周期数和请求完成时间，避免把标称 10 Hz 当成实测 10 Hz。保存配置若请求不同 PLC 周期，规范化为本档 100 ms 并回显实际值，不静默沿用旧 50 ms 默认。

每个通道使用实际读取完成时间和源序号，统一帧继续选用截止时刻之前的新鲜样本。不能把更晚收到的压力倒填到较早帧，也不能将沿用值计为新测量。不重写所有设备的统一调度器；需要适配逐通道证据时，将接口限制为可选能力并为其他驱动保留默认路径。

参考程序还读跳辊、共享锁中的离散输入并访问 ABB，因此本方案只对齐本次三通道的顺序与周期，不声称两进程的压力采样瞬间完全相同。保留批量读取作为生产默认会继续扩大时序差异，因此本档选择分通道读取，并用夹具评估读取负载和超时。

### 4. 保留故障质量合同

严格保留 MBAP、事务、Unit ID、功能码、字节数、寄存器数量与异常响应验证。通信故障、非有限值和过期数据不输出有效 0，不弱化就绪门禁。已有新鲜度内沿用与超时留空规则继续适用；故障和恢复必须可区分，沿用样本不获得新的源时间。

分通道读取中成功通道保留其来源证据，失败通道保留错误、质量及缺失。不得将失败轮次伪装为全部成功；按现有生命周期进行有界重连。其他接口不因 PLC 慢读或失败停顿。来源中明确声明与参考故障置零的差异，而非隐式兼容开关。

### 5. 本机与 helper 共享规范化及证据合同

新行为由权威生产驱动及共享样本处理实现，本机直连、helper、连接检查和只读复现入口复用同一合同。检查 helper 能力与实际传输字段；必要时增加测量兼容能力标识，缺少能力的 helper 以明确不兼容结果阻止启动，不回退服务器设备或无证据旧算法。

接口检查、采集状态、统一帧、WebSocket、CSV 侧车和 MySQL 来源 JSON 都保留同一来源关联。涉及公共访客的数据仍按既有脱敏规则，不因诊断新增寄存器值泄漏。

### 6. 用寄存器证据定位偏差，测试与现场验收分开

扩展现有 `test_plc_modbus_contract.py` 的真实字节夹具及相邻采集、保存、helper 和前端测试。至少验证正常数值、负压力、合法全零、NaN/Infinity、半包及协议错误；通过可控时钟验证顺序、100 ms 周期、超时跳过、源时间和新鲜度。既有“生产路径只发一条批量请求”的断言需要按新合同调整，不通过删掉协议验证降低测试强度。

参考期望值来自明确的寄存器位模式与已核对的 C# 规则。Python 重写参考公式不是已经执行 C# 程序的证据。若使用独立 C# 数值夹具验证舍入边界，所有源码及构建临时产物仅写入已忽略的 D 盘受控临时目录，不能构建或复制完整参考项目。

现场先在稳定载荷核对双方原始 DT37/38、实际时间、处理值和设备/下位机身份；不同时间读取的变化载荷只做带时间关联的趋势对比。容差依据参考载荷与设备资料确认后记录，不能为了通过而推定量值精度。参考上位机启动可能连接控制逻辑，不能为获取对照数值擅自启动气缸、激光、伺服、运动或闭环。

## Risks / Trade-offs

- [负压力截零掩盖零漂] → 保存原始 words、未裁剪值及裁剪标识，界面可以查看来源，禁止将 0 自动等同于已校准无载荷。
- [多条 FC03 增加负载且独立进程采样不同步] → 独立 100 ms 调度、忙时跳过、有限超时、实际周期统计及受控稳定载荷核对，不承诺逐点一致。
- [来源扩展被 helper 或保存层丢弃] → 两种模式相同夹具贯穿到侧车/MySQL 来源 JSON 对账，能力不符明确阻止启动。
- [变更影响既有模型和消费者] → 通道及维度不变，只对合法负压力规范化；质量准入不放宽，清单标记算法，历史数据保持原样。
- [并行任务改动相同采集文件] → 复用本机现有任务分支时逐段核对归属，只修改本任务所需部分，不覆盖、暂存或提交来源不明改动；单一 checkout 不允许多个聊天同时编辑。
- [既有在途设计保留批量路径或旧发布许可描述] → 当前任务的明确测量合同及根目录当前规则优先；不改动其他任务文件，不降低其网络门禁、其他设备范围或实物验收。
