# Design

## Context

动机和范围见 `proposal.md`，外部行为与验收见 `specs/esr1001-native-usb-acquisition/spec.md`。

`visualization_app/acquisition.py` 的 ESR1001-A 角色区分 USB/TTL 与 Modbus 协议，归一化按显式驱动保留串口参数。多接口工厂、helper 能力和前端使用同一驱动及数据用途合同；未声明原生 USB 的旧配置继续使用 Modbus。

原生协议依据是厂商《ESR1001-A 用户手册V2.6》第 3 章及补码说明。当前设备通过 CH340 原生 USB 在 115200-8-N-1 下返回合法参数与启停应答，原始样本可复算，说明该连接具备原始通信能力。设备身份线索包括 VID/PID、当前实例和物理位置；厂商参数帧没有可靠唯一序列号，不得虚构唯一身份。

厂商资料位于 `D:\keti\自动铺丝\数据采集相关\应变片\应变片`。原始样本位于 `D:\AFP_Capture\ESR1001_USB_raw_20261019_195849.csv`，仅作协议夹具核对来源，不作为已修复的软件验收结果，也不把短时观测帧率固化成设备保证。

项目主规格目录尚无已归档能力。现有 `add-esr1001-strain-acquisition` 负责 RS485 路径，其寄存器、CRC 和固件要求仅适用于 RS485；本变更增加原生 USB 能力。整合时应变接口的有效合同是双协议，原生 USB 不受 `0x0030` 固件门禁限制。`new_collection_v13_0` 仍是当前完整采集模式，已有 21/17 通道数据模式继续按各自身份兼容，不恢复旧模式为默认。

## Goals / Non-Goals

**Goals:**

- 让选择的物理端口、序列化配置、实际驱动、执行主机和采集数据来源一致。
- 分开表达协议已识别、原始数据可用和标定微应变可用，缺少 K/B 仍可完成原始诊断采集。
- 在 AFP 原有独立工作线程、统一时间轴和质量模型内接入持续上传流，保持有界读取、重连和停止。
- 把验收落在正式软件及保存文件，明确自动化与量值精度的边界。

**Non-Goals:**

- 不通过猜测系数、自动清零或默认单位换算制造微应变，不训练模型或增加应力通道。
- 不把所有 CH340 自动识别为应变设备，不探测鼠标或任意串口，不改装现有硬件来绕开原生 USB 问题。
- 厂商软件只读分析仅用于核对通信互操作行为，不复用其实现代码；不自动更改桥路、增益、采样率、滤波、通信模式或 Windows 驱动。
- 单设备原始采集验收不要求其他五类设备全部到齐，也不替代完整 77 通道或其他实物联采验收。

## Decisions

### 1. 一个逻辑接口使用两个显式协议档案

保留逻辑角色 `esr1001_strain` 和已有 `modbus_rtu_esr1001`，新增驱动标识 `esr1001_usb_ttl`、协议标识 `esr1001_usb_ttl` 和 `data_mode`（`raw_adc` / `microstrain`）。两条驱动共享原生数据来源的通道身份，但不共享串口格式、请求帧或解码器。单个启用接口只能选择一条路径，同一物理串口仍是独占资源。

旧配置缺少新字段且指定 Modbus 驱动时保留 RS485。原生 USB 选项使用 115200-8-N-1；RS485 地址/波特率信息即使出现在 USB 参数应答中，也不能覆盖 USB 主机串口格式。

配置归一化必须按角色允许的协议档案解析，不能把整个应变角色设置为任意可编辑驱动。接口刷新仅更新物理资源，不改写已选择协议。前后端、本机/helper 的配置指纹纳入协议、数据模式及标定摘要。

### 2. 枚举与受控探针分开

复用 Windows PnP、USB 拓扑和串口目录；CH340 是候选条件，设备位置可确认当前物理关联。发现只枚举，显式“接口检查”仅查询所选候选。已有会话占用的端口直接返回占用状态，多候选保留人工选择；不得为识别设备遍历打开全部 COM 口。

被选择的候选以 USB 参数帧建立协议兼容证据，不把该证据描述为厂商唯一序列号或密码学身份。无序列号设备在 COM 号变化或物理位置变化后重新查询，无法唯一关联时等待人工选择，不依赖友好名或“第一个可用串口”。

### 3. 使用独立 USB 协议模块和持续接收状态机

新增 `visualization_app/esr1001_usb.py` 封装协议常量、参数解析、流式接收与驱动，复用 `pyserial`；`acquisition.py` 负责档案、工厂、路由和状态整合。

| 消息 | 协议合同 |
|---|---|
| 参数查询 | `23 A8 00 00 00 FF` |
| 参数响应 | 固定 14 字节，首字节 `26`、尾字节 `FF`；模式、速率、PGA、通道数、滤波、地址、485 波特率字段分别验证；未定义字段保留原字节 |
| 控制响应 | 固定 14 字节，`25` + 功能码；必须匹配正在等待的命令及参数 |
| 开始 / 停止 | `23 A1 01 00 00 FF` / `23 A1 00 00 00 FF` |
| 四通道数据 | 14 字节，`24` + CH4/CH1/CH2/CH3 各 3 字节 + `FF` |
| 可识别通道数 | 1/2/4，对应数据帧长 5/8/14；本次四路验收只接受四通道配置 |

打开串口后等待 1 秒再查询，参数校验完成后等待 1 秒再受控启动；检查、采集启动和重连复用相同稳定间隔。默认命令期限为 2 秒且可配置；接口检查的数据验证窗口至少 3 秒，计时从参数与启动事务完成后开始，避免把串口初始化及板卡准备时间计入无数据期限。整体探针设定明确总期限并向调用方返回超时阶段。

读取线程连续处理上传数据；数据帧不能按 UI 更新频率读取一帧后长时间休眠，也不能每次读数清空串口缓冲。缓冲上限为 64 KiB；溢出、丢弃字节、截断帧和重同步分别计数。已同步时按确认帧长消费，ADC 字节中的帧头/帧尾取值都是合法数据；失步后要求至少三个连续结构合法、类型可解释的完整帧恢复数据发布。控制和参数帧单独分派，不混入数据观测数。

USB 协议没有 CRC，因此结构校验和连续帧确认只构成帧结构证据，不能声明能检测所有位错误。原始字节保留用于独立复算，统计不虚构设备侧丢包率。

### 4. ADC、微应变和标定分别建模

USB 层每帧生成四个有符号 24 位 ADC：先合并大端整数，值达到 `0x800000` 时减去 `0x1000000`，再重排 CH1～CH4。原始记录使用 `CH1_ADC_signed`～`CH4_ADC_signed`、`adc_counts`、主机墙钟时间、单调观测时间、应用接收序号和原始帧。主机时间用于对账，单调时间用于新鲜度和间隔，不宣称硬件同步时间。

`raw_adc` 支持独立诊断和正常方案联合采集。正常方案启用 USB 原始接口时，有效通道表将四路规范应变替换为 `CH1_ADC_signed`～`CH4_ADC_signed`，单位为 `adc_counts`；统一 CSV、质量侧车和启用的存储目标保留独立名称、单位和来源，同时独立保存源帧。历史方案的静态定义保持兼容。原始会话只允许 `capture_only`，不得进入微应变模型；微应变模式必须验证合法 K/B。未启用的设备明确禁用，不参与会话就绪判定。

正常与诊断方案分别保存接口配置和存储/处理选择，切换前保存当前配置，切换后恢复目标配置。页面刷新恢复用户配置，重新发现只更新实时资源证据，不以默认协议或启用状态覆盖用户选择；持久化配置不保存凭据和就绪授权，恢复后重新检查。

`microstrain` 使用显式选择的逐通道 K/B 档案，输出已有 `应变1～4`。档案保存来源引用、设备物理绑定、桥路、增益、单位、版本、内容摘要及四路系数；非有限值、零 K、不匹配的绑定/增益/桥路直接阻断换算。来源是可核验的厂商配置导出或批准的独立标定结果，不从 ADC 样本幅值推测。更改档案必须重检，采集中禁止无边界热替换。

### 5. 沿用统一就绪合同并增加数据语义证据

复用 `real_acquisition.py` 中已有 `ReadinessReport`、`ReadinessSnapshot` 和阶段顺序：`port_present`、`endpoint_compatible`、`driver_open`、`protocol_identified`、`channels_complete`、`values_valid`、`freshness_stable`、`ready`。不再建立第二套互相矛盾的就绪字段。

`values_valid` 证据明确 `raw_adc` 或 `microstrain` 及标定适用性；原始模式通过只对该模式生效。状态同时给出原始通信可用和标定未确认提示。失败码覆盖端口不存在/占用、参数错误、无响应、协议不匹配、通道不足、标定缺失/不匹配、过期、失步和溢出；前端及公共状态保留未知失败码。

检查与启动共用驱动和校验；启动复核仍可用的设备绑定和参数。就绪指纹增补 USB 协议、数据模式、通道数、标定内容摘要及运行修订；设备重连后重新识别，之前快照不能直接授权新连接。

### 6. 检查、采集与停止共用明确生命周期

只读发现不打开端口。参数查询不发送启动/停止；需要验证数据的检查会明确执行临时启动、观察和收尾。检查记录本次是否发送启动，仅对本次启动执行停止；检查期间本软件已有采集会话时返回忙，不能创建第二个驱动抢占端口。

专用串口被本驱动持有至会话结束，跨接口冲突在打开前拒绝。采集接收与统一帧装配独立：持续接收并保存原始帧，统一时钟按需要读取最新原子四路快照，统计新观测、期限内保持和过期，不将一帧重复计为多个源观测。

停止采用有界事务；停止响应正确与端口关闭是独立事实。丢失停止应答时记录错误并释放资源，文件队列继续收尾。拔插测试单独进行；重连识别到不同配置或设备证据时先阻断微应变输出并提示重新检查。

### 7. 在既有采集、helper 和存储路径中实现一致行为

后端工厂、单接口入口及 `LocalDirectAdapter` 注册 USB 驱动。USB 的最小调用间隔不能强制退化为现有 Modbus 的轮询节奏。规范微应变继续使用现有统一帧、质量侧车、CSV/MySQL 事务和重试；诊断原始文件使用独立写入队列，过载必须可见，不能无限积累。

Web 和原生桌面同时增加协议和数据模式选择、原始曲线/计数及标定状态；后端校验不能只依赖页面。前端配置往返、状态归一化和就绪指纹要覆盖新增字段。

helper 增加版本化能力 `esr1001_usb_ttl`、`esr1001_raw_adc_capture` 和 `esr1001_calibration_v1`，携带与本机相同的配置和状态；原始模式需要前两项，微应变模式需要三项。只由设备所在主机打开串口，旧 helper 明确失败，不降级为 Modbus。

### 8. 验收矩阵使用可量化的正式程序结果

| 验收层 | 必须核验的结果 |
|---|---|
| 协议自动化 | 参数/控制/数据混流、分片、粘连、噪声、错长度、24 位边界、四路重排、无 CRC 事实、启停超时、缓冲有界 |
| 软件链路 | 配置档案不覆盖 USB；接口检查与启动一致；本机/helper 等价；原始数据不混入微应变；保存可复算；其他设备不被探测 |
| 正式程序基础验收 | 界面关联实际 USB，四路曲线/计数，600 秒至少 6000 个源帧、最大间隔 ≤0.25 秒、无未说明解析丢弃/溢出，文件逐帧对账，正常停止和再次检查 |
| 故障恢复 | 单独拔插测试，旧就绪失效、缺口可追溯、恢复后新帧可见，其他接口及鼠标不受影响 |
| 标定微应变采集 | 合法 K/B；定长 600 秒 10 Hz 共 6000 个统一序号，各路有效比例 ≥99%，保持与新观测分开，启用存储目标对账 |
| 量值精度 | 事先记录参考源不确定度和允许误差，逐通道已知输入核验通道、符号、量级与误差，不使用猜测的容差 |
| 正式交付 | 固定目录启动，发布身份、磁盘摘要、实际进程路径、运行修订与页面资源一致 |

600 秒基础测试针对当前应变设备，不要求其他设备参与；设备源帧计数与 10 Hz 统一帧计数各自核算，不能用 CSV 的 6000 行代替源数据证据。当前短时 117 帧只证明可实现协议原始采集，不证明长时稳定性、标定准确或正式软件已通过。

## Risks / Trade-offs

- [USB 无 CRC 且帧标志可出现在 ADC 数据中] → 固定长度、同步参数约束、连续结构确认、原始证据与异常计数；承认无法证明所有位错误均被发现。
- [设备没有可靠序列号] → 当前实例、物理位置、端点及协议组合绑定；歧义或重插后重检，不能持久化一个虚构唯一编号。
- [K/B 资料尚未取得] → 原始诊断模式可独立交付验证；量值采集和精度保持未验收，档案导入与校验用夹具先覆盖。
- [设备速率不足 10 帧/秒] → 提示实际速率并明确验收不满足；采样率调整必须显式确认，不能为通过验收自动改写。
- [工作区有并行修改] → 只在本机任务分支编辑任务自有范围；实现前核对涉及配置与就绪合同的已有改动，不覆盖、暂存或提交来源不明内容。

## Migration Plan

1. 固化 USB 协议、误识别、数据语义和配置往返失败测试，再实现独立协议模块及工厂注册。
2. 完成双协议档案、原始诊断模式、K/B 档案、就绪指纹及生命周期；保持旧 RS485 和既有数据模式兼容。
3. 贯通 Web、桌面、本机/helper、原始写入及规范持久化；更新能力清单、发布合同和现有现场文档，使说明按两种链路分别描述有效行为，不保留排斥原生 USB 的全局规则。
4. 运行定向回归与 Harness quick/full；构建与候选验证只使用 `D:\AFP_Runtime\.afp-staging`，结束后清理本次产物，不生成第二套长期完整运行目录。
5. 在获得用户明确发布授权后，通过现有受控机制更新 `D:\AFP_Runtime\AFP_Integrated_System_Modular`，从该目录启动并核对摘要、运行身份与页面资源；发布失败按现有机制恢复，不长期保留额外完整副本。
6. 用正式程序完成单设备基础、故障恢复及保存验收；按实际具备的 K/B 和参考输入分别执行微应变与精度验收，分别报告，缺失项目保持未完成。

## Open Questions

- 实物逐通道 K/B、桥路及适用增益的厂商导出或批准标定文件尚需取得；档案合同和原始采集策略不依赖具体系数取值。
- 精度验收采用的参考输入、不确定度与允许误差需在量值试验前由设备资料和实际工况确定；它们不改变接口及原始数据基础验收要求。
