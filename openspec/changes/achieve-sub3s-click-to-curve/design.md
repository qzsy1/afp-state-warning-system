# Design

## Context

动机与范围见 `proposal.md`，验收合同以 `specs/acquisition-curve-readiness/spec.md` 为准。

`static/app.js` 的 `startAcquisition()` 冻结当前配置并校验会话检测证据，在开始请求之前准备实时订阅。`app.py` 的真实 `capture_only` 启动使用轻量上下文，不执行完整模型清单或模型文件检查。`acquisition_start.py` 保留后台启动分段，客户端从可信输入事件到全部原画布显示帧计算端到端时间。

`MultiInterfaceDriver` 为设备创建独立适配器线程并使用共享截止时间。PLC/ABB 的请求预检复用同会话匹配路径，实际连接仍校验源接口。ESR1001 默认保留两段固定等待；只有当前会话的有效检测、匹配参数和命令应答及稳定源帧证据齐全时才使用对应有界策略，重连回退到固定等待。USB 启动取消使对应接口证据失效，恢复检测使用固定等待。TC64 显式 `full_record_block` 与通用默认 `channel_temperature` 保持各自合同。页面在同一绘制帧中更新原画布，并在后续帧确认显示。

各段等待归属由同次启动的关联事件确定；后台就绪、设备实验与实际桌面绘制分别提供证据，均不能替代全通道端到端验收。

## Goals / Non-Goals

**Goals:**

- 以同一启用配置的全部有效路由通道为基准，分别测量连接准备和正式开始到真实曲线的时延。3000 ms 为工程目标，完整性能验收须满足既有60轮合同；少量功能或性能轮次不授予达标结论。
- 每个通道需要两次本轮真实新观测；保持值不增加源观测数，数值相同不影响有效性。
- 使用相同计时身份定位等待，优化从请求前准备到显示帧的完整路径；保留停止、保存、取消、就绪校验与端口释放合同。
- 生成可在正式桌面窗口重复执行的测量工具，避免手工数秒与后台计时无法对应。

**Non-Goals:**

- 不改变设备采样率、ADC/微应变语义、标定、生产文件结构、模型量值合同或厂商参数。
- 不通过少选通道、模拟曲线、重复缓存点或提前采样达标。
- 三秒目标及五秒上限本次针对本机桌面 `local_direct`、健康设备、有效配置及检测已完成的场景；Helper、远程网络和预测预警保留兼容回归，不据此宣布也已达到三秒。
- 软件打开到完成初次检测另行测量。初检中不接受悄悄排队的正式启动；一旦点击被受理，所有后续等待必须计入端到端时延，不得重置起点。

## Decisions

### 连接接收与正式采集生命周期

本机 `local_direct` 使用独立的“连接数据／断开数据”和“开始采集／停止并保存”操作。连接打开当前启用设备、完成既有握手并取得持续新鲜有效源帧后进入“已连接，等待采集”。连接不创建采集身份或文件，不更新曲线、数值卡片或矩阵，也不运行预测预警。连接缓存上限为 `max(128, 已选通道数×64)` 个通道事件，每个接收线程仅保留128条观测、64条启动事件；设备解析器、命令证据及待消费队列仍受各自固定容量约束。

正式开始必须使用当前进程、当前配置指纹且健康的连接。服务入口在接收请求时明确拒绝未就绪连接，不隐式重新打开端口或执行完整初检。每轮重新创建采集代次、文件和单调时间边界；在全部接收锁内等待正在执行的读取完成，清除旧事件与串口积压。M3232清除解析半帧并丢弃下一个LF边界前的数据；ESR清除解析和待消费队列、重新确认连续三帧结构并保守丢弃第一个完整数据帧；TC64清除跨界完成的扫描，随后才读取本轮完整新扫描。边界建立后才挂接本轮原始记录器。设备连接、接收线程、采样参数和标定保持不变。

正常停止结束统一采样并排空、刷新和校验本轮全部写入，关闭并分离本轮原始记录器，再按原规则生成最终文件；健康连接继续有界接收。待机数据不进入本轮或下一轮保存，不用于开始成功证明。取消启动保留释放设备的路径；空取消矩阵只有满足原严格归档判据才能解除恢复阻塞。断开操作先完成已有采集保存，再停止设备输出并释放端口。保存与释放各自报告结果，任一失败不得被另一结果掩盖。程序窗口退出前执行同样的保存和断开检查，未完成时阻止退出；受控版本切换前也必须确认已释放。

接收线程失败、重连、身份或参数变化使连接就绪失效，需要显式断开并重新连接，沿用设备原有策略。连接和接收线程仍有效而仅有新鲜度或稳定性波动时，连接进入“已连接，接收尚未就绪”；继续原有质量标记、缺口记录和保存行为，不将就绪波动附加为整段采集停止。就绪恢复须满足既有稳定判据，且全部启用通道均取得波动后的两个不同新源观测；历史快照不授予当前在线资格。质量中断事件窗口上限32条，真实源缺口仍保留于采集质量证据。连接、正式开始、有效新样本实际写入并fsync、全部通道新源、保存终结和绘制分别计时，浏览器与服务器不跨时钟域相减。

当前实测配置启用TC64全部64路、ESR1001全部4路与M3232当前路由及32×32完整矩阵；PLC、ABB暂时停用，UVC禁用。与正式基线比较必须使用相同配置，不能将停用接口的收益计入代码收益。本轮不调整ESR端口保护、QUERY匹配后的等待、START应答与稳定性判据，不调整预测预警、MySQL或设备质量标准。

### 1. 统一计时与数据归属

每次有效点击产生 `start_request_id`，与后台 `operation_id`、试样 `capture_uuid`、本次 `capture_generation` 和配置摘要关联。试样可以跨层复用 `capture_uuid`，但每次启动的代次必须不同。

客户端在当前窗口的性能时间域计算点击到全部曲线的总耗时。起点取可信按钮激活输入的 `event.timeStamp`，验证并规范到 `performance.now()` 的时间域；另外记录处理器实际进入时间，两者之差保留输入排队延迟。不得仅在处理器入口调用 `performance.now()` 重新计零。桌面测量还需关联实际鼠标/键盘输入以检查事件时间戳的可靠性。服务器和设备使用各自的单调时钟记录阶段持续时间；时间线以关联标识连接，不将浏览器与服务器时间戳直接相减。墙钟只用于人工关联日志。

| 标记 | 记录位置及含义 |
|---|---|
| C0 | 激活开始按钮的可信输入事件时间戳；包括事件排队和之后所有请求前工作 |
| C_handler | 输入事件处理器实际进入；与 C0 的间隔用于定位主线程阻塞 |
| C1 | 当前启动请求实际交给网络层 |
| S0 | 服务器接收并辨认本次请求 |
| S1 | 完成启动必需校验，创建或复用幂等任务 |
| D0 / D1 / D2 | 每个接口开始打开、协议和身份有效、得到两次有效新观测 |
| S2 | 当前代次全部所选通道满足源观测要求 |
| S3 | 对应绘图数据集进入发送，保留源序号和质量 |
| C2 | 页面收到属于当前代次的数据集 |
| C3 | 每个通道绘制本轮两点后的实际显示帧确认 |

`T_all_curves = max(C3[channel]) - C0` 为唯一硬验收指标；另报 `T_first_curve`、设备首帧、完整源数据集及所有分段。C3 不采用修改文本、更新计数或仅调用图表 API 的时刻。优先使用图表完成回调及渲染帧证据；Canvas 完成绘制后需跨越显示帧确认，并以实际可见窗口录屏或帧截图抽查。单独的 `requestAnimationFrame` 回调处于绘制前，不能直接充当实际像素已显示的证明。

每条通道至少两次点击后源观测。以当前代次的驱动读取时间、源帧序号和质量证明归属；清除前代缓存的就绪资格。保持值仍可用于合法统一时间轴，但不能增加就绪计数。UI 收到前代消息时不得清空当前就绪证据或改变本轮按钮状态。

### 2. 采用带余量的启动预算

以下为设计分配，不是已测性能承诺；实验需要验证设备段能否达到预算。

| 关键路径 | 预算 |
|---|---:|
| 点击处理、配置冻结和请求前必需检查 | 50 ms |
| 本机请求、服务校验与任务受理 | 150 ms |
| 独立设备并行打开至最慢通道取得两次新观测 | 2200 ms |
| 完整数据集组装与本机实时传输 | 150 ms |
| 浏览器排队、曲线绘制与显示帧确认 | 200 ms |
| 抖动余量 | 250 ms |
| 合计 | 工程目标 3000 ms；单轮硬上限 5000 ms |

所有通道并行后的最大完成时间决定设备段预算，不能相加或只取快接口。P95 以 2500 ms 为工程优化参考；60 轮验收要求至少 54 轮不超过 3000 ms，最多 6 轮可超过目标，但最大值不得超过 5000 ms。任意轮次超过预算必须保留并定位。

### 3. 缩短真实启动请求的关键路径

- 对 `real + local_direct` 请求直接使用当前采集配置和启动所需上下文，不为取得模拟数据默认路径调用完整 `bootstrap()`。
- `capture_only` 不遍历、计算摘要或加载预测模型；需要预测预警时仍按其模式校验兼容性。
- 在启动受理前仅执行鉴权、配置结构与资源冲突校验、持久化阻塞检查、幂等和原子任务登记。后台任务继续执行真实启动必要的设备与写入校验。
- 启动 UI 使用冻结配置，避免一次点击多次重建全量 DOM 映射和指纹。手动启用的工艺参数或 MySQL 校验如果是本轮前置条件，其耗时必须明确进入完整计时，不能隐藏失败或忽略用户配置；本次三秒配置二者均关闭。
- 正常停止保存必须先完成；不得把上一层的保存工作偷偷转移到下一次点击。先统计既有目录、试样清单、层文件合并和摘要耗时，再只移除确认不必要的全量遍历。

模型概况可在启动初始化或相应设置变化时生成缓存；模型文件与配置变化使对应缓存失效。设备、保存门禁不可用模型缓存代替。

### 4. 首次检测与每次启动验证分工

软件打开时对独立资源并行检测，聚合后签发仅当前后端进程有效的检测身份。前端把该身份绑定到后端会话、运行修订及有效设备配置，不将层号、当前采集次数、正常停止或普通 UI 显示变化当作设备配置变化。

正常再次启动仅进行当前身份/连接的轻量有效性检查及本轮实际新样本验证。设备故障、拔插、路由或绑定变化、参数与标定变化使相应接口失效；未受影响接口保留证据。应用重启不从磁盘恢复检测授权。

对 `markHardwareCheckStale()`、`hardwareCheckIsCurrent()`、状态渲染和实时流中的失效路径添加可追踪原因，并验证停止后的旧消息不误清当前授权。避免前端和后端同时发起同配置物理检测；相同指纹检查共享在途结果。禁止以扩大过期时间掩盖持续完整检测。

### 5. 设备启动优化与可行性门槛

先为每个驱动测量打开、枚举、网络路径、身份查询、固定等待、命令应答、首帧、第二新源帧及稳定判定耗时，保留每轮原始事件。所有独立资源并行调度，共用单调截止时间，消除在循环中给每个接口重新分配完整等待窗口的累加效应。

**ESR1001：** 连接使用既有保守等待、匹配QUERY参数应答、START应答和稳定源帧判据。正式开始复用健康连接，不再发送START，不缩短固定等待，不修改仪表配置；取消贯穿连接等待与正式启动。0.25秒新鲜度及既有稳定恢复条件保持有效。

**TC64：** 当前经验证仪表显式使用 `full_record_block`；测量两轮真正扫描的时间，复用仍有效的通道类型配置，禁止逐次重新查询全部设置。类型、量程或绑定改变后必须失效重检。不得静默修改其他仪表的通用默认协议。

**PLC/ABB：** 独立并行连接并获取新数据；缓存本进程内稳定网卡枚举和已验证路径，使用可观察的拓扑/路由变化与实际连接结果失效。每次开始不应重复启动整套 Windows 枚举，但仍校验真实连接的源地址和所选接口一致。ABB 会话按既有方式关闭，不泄漏认证会话。

**可行性门槛：** 若可靠获得两次新观测所需的物理时间不能落入预算，保留原安全策略，精确报告下限和证据。连接待机耗时单独统计；不能以待机观测、减少启用通道或跳过保存与断开合同宣称达标。需要硬件/厂商协议变更时明确提出具体依赖，不编造三秒达标结果。

### 6. 数据推送和 UI 绘制

- 页面实时订阅在开始请求前准备；设备“连接数据”持续有界接收，但不生成正式采集样本、文件或展示。
- 为本轮数据保留逐通道源序号、代次和质量，允许分批进入页面。只有全体通道均有两次真实新观测并实际绘制，才能结束总计时。
- 对状态推送和 UI 更新采用有界合并：落后的实时显示包可合并为当前代次最新快照，但必须保留每通道最近至少两次新源观测；持久化和源数据通道不可丢弃。
- 曲线骨架、通道顺序和画布在初次 UI 准备时建立。首次出数只追加或替换数据，不逐帧重建 75 路 DOM、图例及全部设置卡片。将硬件详情文本和非必要面板降频更新。
- 保持现有界面布局，不新增采集总览。TC64 的 64 路使用现有 8 张原始组画布，PLC、ABB 和 ESR1001 的 11 路使用现有通道卡片画布；每个原画布都必须实际绘出本轮新源观测并跨越显示帧确认。内部滚动区中的所有卡片仍须创建并绘制，正式验收逐区滚动截图核对；折叠、未创建、空图或只更新计数均不能算完成。
- 统一在合适的显示帧批量绘制；控制积压队列和长任务，慢设备状态继续可见。记录浏览器队列、绘制耗时和窗口可见性，避免只测数据收到时间。

### 7. 真实桌面验收与证据结构

测量工具驱动正式程序的实际可见桌面窗口，捕获真实按钮事件。诊断使用的 DevTools/浏览器控制只能绑定本机回环地址与任务实例；正常交付不开放常驻调试端口。无头页面和函数单测仅作为辅助测试。

每轮记录配置、接口启用表、设备身份、实际运行路径、版本/修订、停止完成状态、打开到初检就绪耗时、所有计时标记、逐通道两次新观测证明、曲线显示帧及数据保存校验。测量工具自身的等待不改变 C0；不能额外手动预检后再把冷启动归入成功样本。

| 验收组 | 最少轮次 | 执行条件 |
|---|---:|---|
| 冷启动后的首次有效点击 | 10 | 每轮关闭本任务的桌面及后端，确认已退出后重开正式 EXE；初检自动完成后立即首次点击，不预热采集 |
| 正常停止保存后重复点击 | 40 | 同一后端会话；20 轮在保存确认后立即开始，20 轮间隔 5～15 秒；确认完整检查只发生于初次准备 |
| 空闲后点击 | 10 | 保存后空闲 2～5 分钟再开始，保留设备状态和检测复用证据 |

各组需要覆盖用户实际选定的采集视图、启用的 75 通道，以及干净诊断目录和含代表性已有层/清单的目录。始终使用唯一测试试样标识，不覆盖或移动生产文件。代表性数据规模写入证据，不只在空目录取最好成绩。主验收窗口保持前台；另做最小化/恢复兼容测试，隐藏状态不能提供性能通过证据。

另执行多窗口共享后端、重复点击、慢/缺失设备、取消、USB 拔插、配置变化、延迟旧推送、慢文件写入和保存失败测试。这些错误场景要求正确失败、可取消、无迟到启动、无数据丢失，不能被计为健康设备性能成功轮次。对预定的健康验收轮次发生的失败不能事后删除，必须报告并修复后重新完成整组。

每组报 P50/P95/最大值、总轮次与失败数；保留全部原始事件。发布验证另完成至少 10 分钟联合采集，检查掉线、源帧新鲜度、队列增长、行数与摘要。曲线快速出现不得以采集或保存不稳定为代价。

## Risks / Trade-offs

- [ESR1001 可靠新帧存在物理下限] → 先以实机事件实验判断预算可行性；不放宽全通道、稳定性或停止释放要求。
- [重复检测的真正触发点尚未确认] → 使用统一身份与原因码建立完整时间线，按证据修复，不将猜测写成业务规则。
- [设备时钟无法跨域比较] → 总耗时只在当前客户端计量，源代次与主机观测时间证明数据归属，分段时长各自计算。
- [高频推送挤占浏览器主线程] → 合并显示更新、保留必要新源点、预建画布并记录长任务；保存链路保持完整。
- [低频设备只有一个新点时曲线看似已完成] → 每通道独立记录两次新源观测，前值保持不增加计数。
- [更快受理使请求失败与后台状态脱节] → 保留幂等任务、状态查询、启动取消和恢复保护状态，未知结果不得误报成功。
- [诊断实例干扰正常设备或用户目录] → 仅在无正在采集任务时实机实验，明确本任务进程和唯一试样目录，禁止删除来源不明的数据。

## Migration Plan

只在固定源码目录、本机拥有的任务分支继续工作，保护既有修改。先完成链路证据和设备预算实验，再实施请求、检测、驱动、推送与绘制改动；各步骤保持软件可运行，不把任务步骤写成产品业务规则。

相关检查通过后按既有单运行目录流程自动发布，无需再次请求常规发布授权：构建仅写入 `D:\AFP_Runtime\.afp-staging`；按实际源码重建受影响的辅助程序，核对新增模块确实被组装；安全停止采集，保留运行配置及数据，更新 `D:\AFP_Runtime\AFP_Integrated_System_Modular` 并从该目录启动验收。任务自己的构建缓存和临时候选按规则清理，不操作来源不明的目录。

发布前后核对源文件与交付文件摘要、实际进程路径、运行修订和页面资源。无法构建或启动复验时不得称为交付；软件更新与实物性能验收分别报告。回退按现有受控同卷交换/重建流程执行，不长期保留额外完整可运行副本，不用来源不明或不匹配的修订重建已验证版本。
