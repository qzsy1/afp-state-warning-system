# Design

## Context

动机见 `proposal.md`，外部行为和验收以 `specs/uvc-temperature-acquisition/spec.md` 为准。

当前权威实现包括 `visualization_app/acquisition.py` 的 `UvcThermalDriver`、共享设备档和检查/启动门禁，以及 `uvc_windows.py`、`uvc_windows_probe.cs` 的Windows目标描述符、隔离XU查询和原始样本诊断。原生适配打开和启动返回0为成功，负值失败；不自动设置量程。矩阵复制前后核对源计数，重复、复位和全零占位不作为新观测，非法ROI拒绝，计算保留精度。接口检查仍要求至少三个不同有效温度源帧且跨度不少于一秒。

目标已知身份为 `2BDF:0102`，当前容器身份为 `{F597BF78-50D1-5892-8FD2-B862328B48D9}`，Windows 使用 Microsoft `usbvideo.inf`。设备能枚举为UVC相机，但同摘要原生DLL打开返回 `-2`，共享设备档仍因Windows绑定、接口/端点、温度范围、帧格式、换算和新鲜度依据不足而阻断温度采集。现有资料未包含与该型号匹配的INF、签名驱动包或安装/回滚说明，因此不得把 `-2` 解释为已确定的驱动故障，也不得自行替换系统驱动。

原生 DLL 导出含 `BsvGetFrameCounter`、尺寸查询和取帧 API；当前适配按32位无符号计数读取，并以复制前后计数相同证明矩阵一致。帧计数复位、回绕和实机连续性仍须通过批准后端复验。参考软件目录名、已有录像或DLL存在均不证明实物温度可用。

当前完整模式为 `new_collection_v13_0`，定义六接口、77路传感器。热电偶64路与ESR1001原生USB已存在独立变更及未提交工作，保护对象必须取实施时现状，不能套用旧17/21路方案或把ADC自动换成微应变。计划沿用本机已有任务分支上的相关工作；后续执行按 `AGENTS.md` 和 `local-branch-workflow` 核对本机身份、最新远程及工作区归属，禁止为切换分支暂存、隐藏或覆盖未知修改。

## Goals / Non-Goals

Windows后端使用当前目标的USB配置描述符取得接口号、XU GUID和端点，使用实际PnP实例精确绑定DirectShow设备，不选择第一台相机。目标 `HM-TM32-3RG`、`APP 20012 BUILD 20250207` 当前读回协议2.0和流类型8；描述符为VC接口0、Unit 10、XU GUID `a29e7641-de04-47e3-8b2b-f4341aff003b`、VS接口1与IN端点0x81。`256×392` 的200704字节原始样本未符合现有指南B.1.3帧头；`256×400` 未取得样本。此差异只作为未确认的适用性阻塞，不定义新换算规则。`uvc_temperature.py` 按显式格式验证结构与换算，不能将其他布局按固定偏移猜成温度。Windows诊断不批准设备档，不发布ROI，不生成温度就绪授权。

集成验收为“UVC 相机正确识别接口并正常采集到数据”，真实矩阵及ROI、600秒、保存和恢复按各自证据判定；参考温度量值精度独立保留，未取得参考与公差时标记“精度未验收”。ABB/PLC停用时不访问，也不算通过。

Windows原始传输诊断分别记录请求格式、`IAMStreamConfig.GetFormat`读回和SampleGrabber实际连接格式，以及协商后、运行后和停止后的XU流参数。当前256×392的三种格式均为YUY2、200704字节、400000个100ns帧间隔，三次流参数均为`0108`；256×400连接格式为204800字节，但有界观察内没有回调。上述证据只证明主机连接和配置读回，不证明USB线上的厂商载荷完整性或温度编码。200704字节样本在偏移98816和198656分别观察到`ddccbbaa`和`ffffeeee`字节标记；它们的字段、温度换算、来源序号和冻结语义未确认，不作为解析设备档。诊断回调的DirectShow样本时间、主机经过时间和transport ordinal只统计传输，不作为新温度来源证据。

探针stdout采用`uint32_le_length_then_payload_v1`记录封装，离线读取逐记录校验非零长度、16MiB上限和完整载荷，拒绝截断记录。调用方提供的根实例、父Hub实例、端口和位置路径必须与当前拓扑同时一致；移动设备后须重新发现和选择，不能仅凭同序列号继续沿用旧端口约束。

当前设备USB配置描述符中，未压缩格式1、帧条目4的256×400声明`dwMaxVideoFrameBufferSize=201248`，Windows对应媒体类型却读回204800；帧条目1的256×392声明200704，与实际回调长度一致。原始配置描述符及SHA256须与传输证据共同保存。400模式的尺寸差异不能单独证明主机截断、设备未输出温度或指南完整适用；当前未获得400模式厂商载荷，温度格式和来源语义保持未确认。探针JSON诊断使用UTF-8，以保留本机化HRESULT消息；stdout二进制记录不经文本转换。

**Goals:**

- 在现有驱动边界内修复实际ABI、首帧、新鲜度与关闭行为，并以真实温度帧完成UVC就绪。
- 以逐通道基线和保存对账证明加入UVC后既有采集能力完整；共享层改动必须有其他设备回归。
- 保留统一帧、现有质量状态、检查指纹、单设备隔离和单运行目录流程。

**Non-Goals:**

- 不改写PLC寄存器、ABB运动、热电偶协议或应变标定；不新增模型训练或以像素亮度估温。
- 不因当前DLL依赖libusb就断言必须替换系统驱动；不将设备档批准设为前端可任意覆盖。
- 不增加独立长期运行副本，不复制项目或参考工程，不改动外部参考包，不把规划任务勾选为已实施。

## Decisions

### 1. 首先固定正常采集基线，不凭界面绿色推定正常

用当前正式程序、现有已启用配置和只读设备检查确定正常集合 B。基线证据包含应用/源码/候选身份、设备与端点、接口启用和逐通道映射、名称/单位/顺序、数据模式/标定摘要、目标输出速率、设备扫描/源速率、新鲜度、源观测数、有效比例、最大间隔、错误/溢出/队列高水位、CSV及启用数据库目标。证据写入已忽略的D盘机器可读诊断位置，不新增过程报告。

在相同设备、布线、输入和存储目标条件下完成不含UVC的600秒基线。若已有同运行身份且条件一致的完整600秒证据可复核并复用；短时证据仅用于初始识别，不能替代耐久对照。固定 B 后不可为通过验收删除某个正常通道或关闭其保存。M3232等是否属于 B 取决于实读证据，不凭“六接口”自动宣称全部正常。基线本身失败时定位原有问题，不能把失败吞入UVC修复结论。

分别冻结每类设备已生效的阈值。PLC/ABB/UVC要求有效比例≥99%、最长无有效数据间隔≤2秒；热电偶64路按完整扫描与其既有新鲜度核验，ESR原生USB保留源帧/最大间隔/原始文件指标及实际ADC语义。不能把慢扫描强制说成10个新源帧/秒，也不能放宽已有更严格的设备指标。

### 2. 以可核验ABI修复当前后端，温度与驱动批准独立完成

先用参考适配器和同摘要DLL锁定打开/启动的0成功、负值失败合同；量程设置不在只读采集初始化中执行。是否有帧和取帧按各自合同判断，不能把所有函数统一改成非负成功。保留原始阶段、返回码与最后错误；`-2` 不等同于libusb枚举中的任意同数值错误。

具体后端选择采用以下有依据的分支，外部合同和任务集合不变：

- 型号匹配厂商资料确认当前原生DLL及WinUSB/libusb路径：核对指定接口、端点、签名/位数、依赖和回滚，按现有授权流程由操作员配置；应用不静默安装。
- 厂商资料确认保留 `usbvideo` 并提供UVC测温/扩展接口：只在UVC适配边界实现该批准后端，使用实际温度载荷，保持同一状态、ROI与保存合同。

资料不足时可独立完成ABI、等待、错误与隔离回归；厂商事实填写、驱动切换和实物验收保持未完成。参考代码证明的是互操作实现，不自动填充批准事实。配置归一化目前用共享设备档覆盖输入，批准事实须进入后端权威档案和指纹，而非只在页面payload加入 `approved`。

### 3. 用阶段期限与新帧证据取代快速重复查询

分开配置加载、打开、启动、首帧、帧间和停止期限，并使HTTP/Helper总请求预算覆盖合法初始化与观察窗口；具体数值由批准资料和当前硬件实测确定，测试使用可控时钟。等待用单调时间与可取消间隔，普通暂无新帧不立即重开设备，超过期限才报告阶段化失败并进入既有退避。

核验并使用 `BsvGetFrameCounter` 或批准后端等价来源标识；如API不提供原子帧/计数对，需验证复制前后计数一致或采用有界重试/原子快照接口，保证序号与矩阵属于同一帧。计数复位与重连使用连接代次区分，不能把旧缓存标为新帧。无法取得可信来源标识时，不得仅凭 `BsvHasFrame>0`、内容变化或再次读取时间断言“新帧”；需补齐可证明的新帧接口后才能通过连续性验收。

仅有新源帧才能更新来源时间与新观测计数；统一10 Hz可在设备批准新鲜度内保持同一值，质量标为 `held_within_freshness`。超期标记 `stale/missing`，不补零、不前向填充成新观测。来源若只有主机接收时刻需明确标识，不能伪装设备硬件时间。

### 4. 温度矩阵与ROI验证不依赖普通视频

尺寸、实际载荷布局、字节序、量程、换算和新鲜度必须来自适用设备档；256×192、代码4及 `raw/64-50` 是当前实现待确认参数，不是所有 `2BDF:0102` 的通用业务规则。将格式/长度/未初始化和无效值判断下沉到UVC后端，检查至少三个不同源帧、覆盖至少一秒并满足批准新鲜度后再给出 `data_ready`。

显式非法ROI返回配置错误；默认ROI按现有有效语义记录实际区域。保留可复算原始矩阵样本、ROI与转换元数据，核对至少两个不同稳定参考温度，事先确定参考不确定度和公差，记录发射率等适用测温参数。有限ROI均值本身不能证明量程/换算正确；无效或零占位矩阵不得进入有效样本。

### 5. 故障隔离沿用现有采集边界

UVC独立工作线程只发布本接口快照，不能持有阻塞其他设备的全局锁。原生调用超时后未退出的线程继续拥有其上下文，不允许并发Stop/Close/重开；若DLL无法提供可取消且可回收生命周期，以UVC专用受控子进程隔离实现有界结束，不终止AFP主进程或其他设备。选择哪种隔离由阻塞回归证明，不能只因上层timeout已返回就宣称资源已释放。

在联采中注入UVC延迟、暂无帧、拔出、恢复、原生阻塞及保存背压，逐通道观察 B 的序号、有效比例、最大间隔和队列。UVC故障只影响自己的质量与重连状态；其他接口持续保存。正常无故障耐久、拔插故障和阻塞故障分别执行，故障缺口不能从无故障统计中隐藏或补造。

### 6. 配置与就绪只使用现有合同

沿用实际代码中的统一Readiness、阶段状态和快照，不另造第二套审批字段。识别事实、后端/设备档摘要、驱动状态、ROI/量程、执行主机及运行修订进入指纹。检查/启动配置一致，且旧快照不能跨设备重连或后端变更生效。

桌面/Web与Helper都使用同一后端配置；刷新、重启、接口重新发现和模式往返保留 B 的协议、绑定、启用与保存选项。继续遵守已有检查single-flight及桌面复用固定服务行为，禁止临时探针和正式采集争用设备。只对启用接口执行检查，明确停用不等于通过。旧Helper能力缺失需明确失败，不以服务器相机代替。

### 7. “不丢失”逐层对账，不要求不同硬件源速率相同

定义两层统计：设备层是新源观测、帧序号与实际接收频率；统一层是10 Hz输出、质量和持久化。设备到统一层的有意下采样/保持必须有解释；现有ESR源帧独立保存等强合同仍逐帧对账。UVC为复算保留带来源标识的原始矩阵样本及ROI参数，不默认新增全速视频录像或无限原始矩阵归档。

定长600秒窗口排除预检与预热，统一时基窗口为 `[t0,t0+600s)`，期望序号0～5999共6000行。每个输出通道含质量与来源证据，逐通道检查 B 完整且指标不退化；源计数不要求等于6000。对没有设备侧序号的硬件只能证明主机已接收后的完整性，不能声称证明设备从未丢包。

CSV、时间戳、质量侧车与所有启用MySQL目标按同会话/序号/通道对账，正常结束后未完成重试为0，禁止静默缺列/缺行/重复行。基线用过的存储目标不得为了联采通过而关闭；保存失败必须显式失败并保留恢复证据。首次与停止后的再次采集各验证端口释放和新会话隔离。

### 8. 验收矩阵

## Risks / Trade-offs

- [设备档资料不足] → 先实现可独立验证的软件修复，明确资料清单；不以参考代码注释作为驱动或测温批准依据。
- [只改成功码后仍打不开] → 保留真实打开失败，在相同布线下分时对照批准工具；不叠加未经证实的驱动切换。
- [暂无帧或重复缓存造成假稳定] → 期限与源标识分离，恒温新帧和停更缓存分别测试。
- [原生阻塞占用共享资源] → 通过并发/超时/关闭测试证明隔离，必要时采用UVC专用可终结执行边界。
- [新功能覆盖热电偶、应变或配置持久化改动] → 以当前正常集合和现有变更的有效合同为基线；共享层变更必须跑相关定向测试及Harness。
- [设备或保存目标缺席] → 保留未覆盖范围与待验收状态，不缩小原本正常集合来宣称全通过。

## Migration Plan

1. 新窗口读取本变更四份工件和现有相关变更，核对工作区/远程/当前运行版本及 B；只读资料包，冻结原配置和机器可读基线，不复制项目或运行目录。
2. 先以零成功ABI、首帧延迟、缓存停更与UVC阻塞建立失败用例，再修UVC适配、设备档/后端及新帧质量；共享层仅做必要兼容整合。
3. 完成桌面/Web、本机/Helper、统一帧与保存回归；运行定向测试、Harness quick/full、`git diff --check`及OpenSpec校验。
4. 构建与候选测试仅写 `D:\AFP_Runtime\.afp-staging`；若需要系统驱动改变，先取得型号匹配资料和现有授权，再由操作员在停止AFP的维护窗口实施并复验/回滚。
