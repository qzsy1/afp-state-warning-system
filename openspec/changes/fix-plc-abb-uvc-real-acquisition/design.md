# Design

## Context

参见 `proposal.md` 的问题说明和 `specs/plc-abb-uvc-real-acquisition/spec.md` 的行为合同。权威源与正式运行目录是独立交付对象，必须分别核验文件摘要、运行修订和实物检查结果。

- 权威源分别保存设备端点和物理绑定，依据目标路由推荐工业网卡，并在检查、启动和重连前复核实际 TCP 连接源地址；UDP 路由查询不能证明 TCP 未被 TUN 接管。
- PLC 使用严格 Modbus 响应校验读取温度、压力、张力；读到有限值不代表已经完成工艺参考语义核对。
- ABB RWS 使用 Digest 质询认证和明确错误分类，工业 HTTP 会话不继承系统 HTTP 代理；控制器身份、坐标和线速度仍须独立进行现场核对。
- BSV UVC 依据 Windows VID/PID、设备实例和位置路径关联 USB 端口。原生 DLL 依赖 libusb，设备当前绑定 `usbvideo`；批准驱动、温度帧及换算事实不完整时，正式测温检查保持阻断，不据 DLL 依赖推定必须更换系统驱动。
- 正式源码固定在 `D:\AFP_Integrated_Modular_v2`，构建临时目录固定在 `D:\AFP_Runtime\.afp-staging`，唯一完整运行目录固定在 `D:\AFP_Runtime\AFP_Integrated_System_Modular`。

## Goals / Non-Goals

**Goals:**

- 建立设备协议端点、物理接口、实时身份和数据就绪证据相互独立的数据模型。
- 让发现、立即检查、启动门禁、运行状态、本地 helper 和保存证据使用同一设备合同。
- 使用可执行夹具锁定三个已定位缺陷，并用实机逐项及并行采集完成最终验收。
- 保持单设备故障隔离、有界停止、D 盘保存和唯一运行目录约束。

**Non-Goals:**

- 不向 PLC 写寄存器，不控制 ABB 运动，也不由应用自动安装或替换 Windows 驱动。
- 不改变现有规范通道名称、单位、统一帧、CSV/MySQL 格式或模拟采集语义。
- 不把普通视频预览视为 BSV 温度矩阵，不用模拟或协议夹具替代实物验收。
- 不在本变更中改造 SMRF、M3232、ESR1001 或热电偶 64 路协议。

## Decisions

### 1. 保留 `endpoint` 的设备协议语义

逻辑接口的 `endpoint` 继续表示 PLC 主机和端口、ABB RWS 主机、串口名称或设备档端点；`physical_interface_id`、`physical_port_id`、`physical_interface_kind`、`physical_transport_family` 和设备身份字段只表示物理绑定。前端物理选择不得通用地改写 `endpoint`。

串口角色是唯一需要从实时接口派生协议端点的类型；该行为通过角色/设备档显式声明，而不是复用所有候选项的 `endpoint`。网络角色仅更新网卡绑定，UVC 角色仅更新设备实例与 USB 端口绑定。

该字段模型兼容现有配置和 API，并消除网卡名称覆盖 IP 的根因。

### 2. 后端计算路由事实，前端只呈现和选择

发现结果为每个 PLC/ABB 目标计算候选网卡的同网段、源地址、最佳路由、物理/虚拟类型和推荐等级。前端优先保留手动或已保存选择；无选择时使用后端推荐，不再按数组顺序取第一块网卡。

检查和启动时后端重新验证当前 Windows 路由，不信任前端缓存。使用不发送应用数据的有限超时 TCP 连接检查实际源地址，防止 UDP 路由与 TCP TUN 路径不同而误通过。连接源地址与所选网卡一致、目标为直连物理路径时才进入协议阶段。PLC 与 ABB 可以共享同一工业网卡，但分别保留设备端点和协议结果。

该决策避免在浏览器复制 Windows 路由判定，也防止 WLAN、APIPA 或代理虚拟网卡因枚举顺序变化被自动选中。

PLC 与 ABB 的生产协议连接绑定路径检查通过的源 IPv4，并在实际连接上再次核对源地址；连接重建沿用该绑定，重新打开设备前复核路径。只读复现入口使用同一生产驱动执行多轮独立连接，保留每次读取和缺失通道，不将短时复现结果标记为现场验收通过。

### 3. PLC 保留现有严格解析并补齐阶段证据

PLC 不重写已经能从实机读数的 Modbus 主路径。改动集中在：传入正确设备端点、验证选定路由、为每次读取消除错误吞没、输出三个通道的来源时间与质量，以及在检查中要求全部启用通道完成。

协议夹具继续覆盖 MBAP、事务、Unit ID、功能码、异常响应和寄存器数量；新增绑定回归证明任何网卡选择都不会改变 `192.168.125.5:502` 等设备端点。

### 4. ABB 使用质询驱动的 Digest 会话

ABB 传输建立可复用的认证会话：首次请求接收 RWS 质询，使用配置凭据完成 Digest，再复用会话读取 robtarget 或 RAPID 资源。工业 RWS 会话显式禁用系统 HTTP 代理，不得预先发送 Basic；认证、HTTP、资源路径、JSON 结构和数值解析使用不同错误类别。

连续采集路径不再把所有异常转换为 `None`。驱动将异常交给现有接口工作线程，由统一状态层记录失败阶段、重连和新鲜度；状态和日志对用户名进行必要最小化，对密码、Digest 响应和授权头始终脱敏。

会话使用独立的内存 CookieJar 保存并复用 `ABBCX` 与 HTTP 会话 Cookie，避免每次读取重新占用控制器会话。关闭只通过同一会话请求 `/logout`，没有本客户端 Cookie 时不发退出请求；退出失败保留具体错误，禁止清除其他客户端会话。Cookie 不进入配置、状态或证据。

使用运行程序已包含的 `requests.Session` 和 `HTTPDigestAuth` 复用实际 HTTP 连接、Digest 质询与会话 Cookie；独立连接池绑定并核对工业源地址，`trust_env=false` 禁止继承系统代理，HTTPS 保留默认证书校验。收到质询前不发送认证头，后续请求复用协商结果，nonce 更新后重新协商；不能回退到 Basic。

### 5. UVC 身份从 Windows PnP 事实映射到 USB 拓扑

Windows 发现层新增规范化相机端点，保留设备实例、容器、VID/PID、服务、驱动提供者和 Location Path。拓扑层使用同一实例/容器/位置证据把相机端点关联到已有 `usbdev` 与 `usbport`，而不是用友好名称猜测。

设备档负责声明批准的 BSV 身份、温度帧尺寸、量程代码、换算规则和所需后端。其他相机仍显示在诊断中，但不会成为兼容候选。`driver_available`、`device_detected`、`topology_bound` 和 `data_ready` 分开保存，删除“DLL 存在但固定 detected=false”的合成结论。

### 6. UVC 后端与驱动绑定必须依据型号匹配的厂商事实

当前原生 DLL 依赖 libusb 并按目标 VID/PID 打开设备，这些实现事实不能证明该型号的批准 Windows 绑定是 WinUSB/libusb。实施前必须取得型号匹配的厂商驱动包、INF 或书面接口说明，并确认 Windows 绑定、接口号、端点、温度量程、帧格式、换算和回滚方法；事实不足时设备档保持未批准状态，不得使用未经批准的通用驱动替换工具形成正式配置。

若厂商资料确认该型号必须继续使用 `usbvideo` 并通过 UVC 扩展单元读取温度，则只替换 UVC 后端实现，设备档、状态合同、前端绑定和验收指标保持不变。该兼容分支不改变 Spec，也不允许以普通视频帧通过温度采集门禁。

应用只检测和报告驱动状态。驱动安装、替换与回滚由操作员在停止 AFP 后执行；完成后必须重新枚举并重新检查，旧快照全部失效。

### 7. 统一结构化就绪结果

每个接口返回阶段数组和一个规范最终状态，阶段至少包含：`physical_binding`、`device_identity`、`driver`、`network_path` 或 `usb_binding`、`authentication`、`protocol`、`channels`、`freshness` 和 `stability`。不适用阶段显式标记，不用空值推断成功。

最终状态采用稳定代码，如 `data_ready`、`network_path_invalid`、`authentication_failed`、`resource_mismatch`、`driver_incompatible`、`device_open_failed`、`no_valid_frame` 和 `partial_channels`。公共状态与前端保留未知失败码并按失败显示，不能映射为 `unchecked`。

配置指纹纳入协议端点、物理绑定、非明文凭据标识、设备身份、驱动状态、设备档版本和运行修订。任一变化使检查快照过期。

前端在生成真实采集配置时即固定 `execution_host`：本机直连为 `server`，Helper 为 `helper_local`。检查和启动复用该规范配置，不允许只在启动请求中补充默认执行位置而使已通过的检查快照失效。

### 8. 驱动生命周期继续使用单接口隔离工作线程

正常方案可与 `fix-esr1001-native-usb-acquisition` 规定的 ESR 原始 ADC 模式联合采集；未启用 UVC 等接口不参与会话就绪判定，也不被标记为检查通过。该联合会话保留 PLC/ABB 路径、认证及业务数据门禁，ESR 标定状态独立呈现；PLC/ABB/ESR 验收不能替代本变更的 UVC 三设备及测温验收。

PLC、ABB、UVC 分别由现有本机直接适配线程管理打开、读取、退避重连和关闭。变更不引入一个共享阻塞循环；统一采样器只消费各接口缓存及质量元数据。UVC 原生调用必须受有限超时或隔离执行边界保护，停止超时要报告具体设备。

本地 helper 使用同一权威驱动和结果结构，通过能力版本声明新合同。旧 helper 缺少该能力时，正式真实采集失败关闭，不以服务器设备代替。

### 9. 自动化测试与现场证据分层

自动化包含四层：

1. 前端纯逻辑测试验证端点保持、网卡排序、人工选择和刷新。
2. Python 协议夹具验证 PLC 报文、ABB Digest 会话和错误分类、UVC DLL API 成功/失败及状态映射。
3. Windows PnP/USB 拓扑夹具验证相机实例到物理端口的关联，并验证其他相机不会误绑定。
4. 装配和 helper 集成验证权威源、候选程序和两种执行模式合同一致。

现场证据使用候选运行程序逐台检查，再执行 600 秒三设备并行采集。证据保存到批准的 D 盘位置，包含构建与设备身份、配置、统计和对账，不创建新的过程报告或重复总结文档。

## Risks / Trade-offs

- [BSV 厂商驱动资料缺失或与当前 DLL 不一致] → 在任何驱动变更前设置硬件事实门禁；只接受厂商批准的驱动/协议资料，不能取得时允许完成软件诊断修复但现场验收保持失败。
- [切换 UVC 驱动后标准相机预览不可用] → 先导出当前驱动身份和回滚步骤，在维护窗口人工切换；正式需求只依赖温度矩阵，普通预览能力单独记录。
- [ABB Digest 会话增加请求状态] → 使用每驱动实例独立会话、有限超时和重新质询，加入 nonce 过期与错误凭据夹具。
- [路由在检查后被系统或代理改变] → 启动时复核，运行中记录实际源地址并在网络错误重连前再次验证。
- [600 秒验收受工艺停机影响] → 软件自动化可先完成，但正式结论保持现场待验证；验收必须使用批准的安全工况和参考源。
- [当前工作区含其他未提交修改] → 实施时只修改任务清单列出的权威文件和测试，提交前逐文件核对归属，不暂存或覆盖来源不明内容。

## Migration Plan

1. 在权威源中先增加失败的端点保持、路由排序、Digest、UVC 身份/驱动状态和分层结果测试。
2. 调整共享配置与发现模型，保持旧 `endpoint` 的协议语义并兼容没有新增身份字段的旧配置。
3. 修复 PLC/ABB 网卡建议和后端路由复核，确认 PLC 实机三通道读数不回退。
4. 替换 ABB 认证会话及错误传播，先用夹具再用实机只读 RWS 验证。
5. 完成 UVC PnP 到 USB 端口关联及驱动兼容诊断；确认厂商资料后，在维护窗口由操作员执行批准的驱动绑定并验证温度帧。
6. 统一前端、公共状态、本地直连和 helper 的结果投影，补齐单设备断线与停止回归。
7. 运行相关窄测试、Harness quick/full、候选装配一致性和候选程序冒烟测试；所有构建只使用 `D:\AFP_Runtime\.afp-staging` 并在结束后清理。
8. 最终实物验收在当前版本上执行单设备现场核对和 600 秒三设备并行采集，完成保存与统计对账；参考语义、UVC 或联合验证未完成时，最终验收保持未完成。
9. 按用户明确授权的发布范围，通过现有受控机制更新唯一运行目录，从该目录重新启动并复验健康、接口实读、短时采集、停止和保存。源码与候选通过不能代替正式交付；实际进程路径、运行修订、发布清单、文件与页面资源摘要均须一致。若启动、协议或采集复验失败，则停止新运行程序并恢复切换前版本；不长期保留第二套完整运行目录。
