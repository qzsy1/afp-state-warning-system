# Design

## Context

参见 [proposal.md](proposal.md) 及四个 delta spec。产品事实来源位于 `visualization_app/`，候选装配由 `modular_runtime/` 完成，Harness 负责门禁与证据。正式 `delivery/` 在准备和演练过程中保持只读。

`local_direct` 与 `remote_helper` 共用统一帧、质量、持久化和停止核心。公网访问同时涉及服务器源站、隧道控制面、公共边缘、浏览器和远端 Helper；任何单层成功都不能代表端到端就绪。公网 URL 可能在恢复时变化，因此入口身份必须独立于进程 PID 和临时连接，并跨服务器重启、Helper 重连及计划任务持久存在。

公网访问丢失由以下失效组合造成：以进程存在代替监听检查、以隧道命令成功或本机 HTTP 成功代替公共边缘证明、多个 watchdog 竞争恢复所有权，以及服务器在 Helper 尚未匹配候选和入口代次时提交在线状态。有效合同使用持久化代次、唯一所有者、公共边缘探测和服务器签发的跨进程切换预约，禁止这些独立推断形成就绪结论。

配置、状态和证据不得包含密码、Token、Cookie、数据库凭据、配对码或响应正文。生产网络、防火墙、电源、时间和系统服务只允许只读检测或执行经过明确授权的动作。

## Goals / Non-Goals

**Goals:**

- 让主程序、Helper、配置、协议、静态资源和受管模型使用可比较的同一发行身份。
- 让环境预检、候选验证、双机演练和恢复结果具有稳定状态、明确终态和脱敏证据。
- 通过唯一、持久化的公网入口代次约束 URL、恢复所有者、配对、Helper 会话和采集命令。
- 让公网入口切换具备独立公共边缘证明、原子发布、唯一所有者和异常安全回滚。
- 让第二台电脑或目标 MySQL 不可用时明确报告 `blocked`，且不把本机模拟升级为真实环境证据。

**Non-Goals:**

- 不增加第三种真实采集模式，不改变统一帧或采集数据语义。
- 不替代真实传感器的设备身份、信号、校准、USB/电磁环境和实物耐久验收。
- 不自动修改防火墙、Tailscale 配置、Windows 服务、电源、时间或生产网络。
- 不用自动重试代替一次性采集步骤，也不因等待超时重复发送启动请求。
- 不在没有独立发布授权时替换正式 `delivery/` 或固定运行目录。

## Decisions

### 1. 发行合同与候选 manifest 是组件身份的唯一来源

发行合同声明应用版本、Helper 版本、协议、统一帧合同、配置 schema 和最低能力。候选根目录的 `RELEASE-MANIFEST.json` 加入候选 ID、源修订、受管文件和静态资源摘要，`SHA256SUMS.txt` 承担逐文件完整性。主程序与 Helper 从同一合同加载身份，并在设备打开、正式会话创建或远程启动命令之前比较。

候选写入新的唯一目录，不覆盖、合并或就地修补既有候选。旧候选只有在新候选验证通过、无运行时引用且审计证据已保存时才能清理。

### 2. 受管模型使用规范化真实路径包含关系

内置模型由发行 manifest 声明的模型根目录定义。后端使用规范化后的真实路径包含关系判断文件是否位于受管根目录，并向前端返回明确的模型来源字段；前端只消费该字段，不再从文件路径文本推断来源。路径字符串中偶然出现 `models/new`、`models/legacy` 等片段不构成内置模型身份。外部自定义模型不在受管根目录内时保持外部选择，不因目录名相似被删除或替换。

选择真实路径包含关系而不是字符串搜索，可以正确处理相对段、大小写和相似目录名；候选 manifest 则限定哪些根目录属于当前发行。

### 3. 配置模板和预检使用单一结构化结果

`local_direct` 与 `remote_helper` 使用完整、互斥、无密的版本化模板。预检探针返回统一结构，包括检查 ID、状态、证据、影响、修复建议、证据等级和外部环境标记。JSON 与人类报告由同一结果对象渲染。

状态只允许 `passed`、`failed`、`blocked` 和 `physical_sensor_pending`。只有实际设备读取、物理端口和真实信号检查可以使用 `physical_sensor_pending`；第二台电脑、MySQL、权限和网络缺失均为 `blocked`。

### 4. 耐久和恢复复用生产边界

两种模式的演练直接调用生产采集、Helper 调度、远程镜像、journal 和 MySQL retry spool 边界。故障只注入外部适配器和受控临时服务，不复制 ACK、重传、停止或持久化逻辑。默认每种模式运行至少 1800 秒、10 Hz；短时自动测试保留独立证据等级。

所有介质按同一 `capture_uuid`、绝对序号、时间戳和质量字段对账。上一采集存在未完成 journal、数据库重试或未终结停止状态时，新正式采集失败关闭。

### 5. 公网入口状态是持久化、单调递增的权威记录

服务器维护一个不含秘密的 `public-ingress-state.json`，至少包含：

- `schema_version`
- `generation`：单调递增的非负整数
- `public_url`
- `provider`
- `recovery_owner`
- `candidate_id`
- `status`
- `published_at`
- 本地源站、隧道控制面、DNS 和公共边缘探测的分层结果及时间戳

URL、提供方或恢复所有者发生变化时发布新代次。写入使用同目录临时文件、刷新并原子替换；读取方只接受完整 schema 和递增代次。损坏、缺字段、回退代次或候选身份不一致时状态为失败，不根据现有进程或普通 HTTP 成功自行推断。

状态文件只保存请求元数据和摘要，不保存响应正文、WebSocket 帧、敏感请求头或凭据。

### 6. 公共边缘探测必须证明真实公网数据面

公共边缘探测由生产脚本和 Harness 共用同一判定规则：

- 通过独立公共 DNS 查询 A 与 AAAA 记录；
- 使用标准 IP 地址分类判定地址为全局可路由，拒绝回环、私有、链路本地、运营商级 NAT、文档、基准测试、组播、保留及其他特殊用途地址；
- 绕过系统代理，并将原公网域名的 TLS SNI/Host 强制绑定到所选边缘地址；
- 禁止重定向，只有声明健康端点返回精确 HTTP 200 且静态身份匹配时通过；
- 不记录响应正文、Cookie 或敏感请求头。

本地 `127.0.0.1:8770` 成功只属于源站层；隧道命令成功只属于控制面层；服务器对公网域名的普通请求不属于公共边缘证据。

### 7. 入口代次约束配对、readiness、会话和命令

配对记录、Helper readiness、WebSocket 会话和采集命令都携带当前 `generation`。服务器只向当前代次、当前候选且协议兼容的 Helper 接受或交付命令。

发布新代次时，服务器按同一状态转换执行：

1. 废止旧代次配对和 readiness；
2. 分离旧 Helper 会话；
3. 将尚未交付或确认的旧代次采集命令写入明确失败终态 `ingress_generation_changed`；
4. 保留命令和状态的脱敏审计信息；
5. 等待 Helper 使用新入口重新连接、配对并报告匹配代次。

每个命令在入队时固定代次。Helper 收到与当前会话代次不一致的命令时拒绝执行并返回明确失败；服务器不会把旧命令重新标记为新代次，也不会因超时自动重发启动请求。

入口切换只允许在没有已确认执行中的采集命令或活动采集时开始。已交付但未确认的命令视为未完成命令并在代次变化时失败终结；已经确认执行的采集必须先通过现有停止和对账流程达到明确终态，切换不能把运行中采集静默遗留在旧入口。服务器启动时按持久化代次重新核对命令状态，确保状态发布后进程崩溃也不会恢复旧代次命令。

Helper 保存的 URL 仅可用于同一代次内的自动重连。操作员提供或候选交接声明了不同代次时，当前权威入口优先，旧保存 URL 不得覆盖新入口，也不得作为静默回退。没有匹配代次和新配对时，Helper 可以保持进程运行，但 `ready` 必须为 false。

### 8. 公网入口恢复只有一个所有者

`recovery_owner` 明确指定当前允许执行自动恢复的提供方 watchdog。非所有者只能读取和报告状态，不得启动替代隧道、改写 URL、切换计划任务或关闭当前入口。

提供方切换是显式操作员动作。入口状态写入使用跨 Windows 会话的共享互斥锁。切换方必须从仅绑定本机管理端口 8771 的控制端点取得有界预约；预约以哈希形式持久化并随固定运行目录切换迁移，服务器重启后继续拒绝新的本机和 Helper 采集启动，释放时校验同一事务标识。预约建立时再次核对活动采集、待确认命令和持久化 journal，任何并发、陈旧或无法核对的调用均失败关闭。计划任务安装、修复或单个 watchdog 自检不得隐式夺取所有权。

选择单一所有者而不是多个 watchdog 竞争恢复，可以避免两个临时 URL 反复覆盖、旧 Helper 追随错误入口以及证据把不同提供方状态拼接为伪成功。

### 9. 切换事务先证明新入口，再发布，再退出旧入口

切换顺序固定为：

1. 读取并备份当前入口状态、运行时引用、可变运行状态和回退入口；
2. 从本机管理端口取得切换预约，并验证不存在进行中的启动、未确认命令、活动采集或未完成对账；
3. 启动候选入口但不改变权威 URL 或所有者；
4. 验证候选入口的源站、控制面、公共 DNS、强制公共边缘 HTTP 200 和静态身份；
5. 在共享锁内原子发布新代次和 `degraded` 待提交状态，并触发旧代次会话和未完成命令失效；
6. 复读状态并验证候选入口仍符合已发布身份；
7. 验证当前候选、Helper 可执行文件 SHA-256、协议、命令生命周期、配对和当前代次 readiness；
8. 原子提交全部通过的分层状态；只有此时状态才能成为 `online`；
9. 只有明确切换动作才能退出旧入口；普通安装、健康检查或恢复不得退出旧入口；
10. 部署提升只有在上述门禁通过并释放切换预约后才能完成。

运行时提升保留安全存储、Helper 注册表、目标采集 journal 及公网入口状态等可变文件。事务在删除回退材料或报告完成前确认释放切换预约。任一步骤抛出异常、超时或返回失败时，事务先验证旧入口仍可作为回退数据面，再恢复原入口身份和恢复所有者并停止候选入口；存在旧入口状态时，回滚发布使用高于失败代次的新代次，Helper 层保持 `degraded` 直至新代次显式对账，禁止恢复旧字节或旧 Helper 就绪结论。旧入口状态不存在、旧入口无法验证、预约无法释放或其他补偿失败时保留可用候选和两端现场、标记 `failed` 并要求人工处理，不伪报原入口已恢复。

尚未实现预约接口的旧运行时只允许走操作员显式选择的兼容切换。工具先使用生产公共边缘探测验证旧入口并确认本机采集、持久命令、活动采集和目标 journal 均无未完成项，再停止 watchdog、Helper 和服务器；只有停服后才能创建与新运行时相同格式的持久预约。新运行时通过本机、局域网和公共边缘门禁后可以保持 `degraded` 等待 Helper，但不得删除旧运行回滚材料或报告部署完成。匹配候选及入口代次的 Helper 就绪、预约已释放且分层状态提交为 `online` 后，显式收尾入口才清理回滚材料。

### 10. 状态报告按层级聚合且失败关闭

未配置公网域名、隧道及入口状态的本机运行目录使用显式 `LocalOnly` 发布模式；缺少 `PublicUrl` 不能隐式进入此模式。本机发布保留采集预约、持久命令和 journal 核对、固定监听进程、候选身份、本机页面摘要、预约释放和回滚验证，不创建公网入口状态。配置了 LAN 地址时继续验证 LAN；公网及远程 Helper 就绪保持不适用。已有公网配置或入口状态时拒绝本机模式，继续使用完整公网事务。

公网状态报告分别记录：

- 源站监听及所属 PID；
- 隧道控制面和提供方；
- 公共 DNS 地址类别；
- 强制公共边缘 TLS/HTTP 结果；
- 权威 URL、代次和恢复所有者；
- Helper 计划任务、进程、路径、候选、哈希、会话代次、配对和 readiness；
- 旧代次命令取消数量及终态；
- 回滚或恢复结果。

只有所有必需层都通过且 Helper 更新动作成功时才能写入 `online`。Helper 重启失败、代次不匹配、原子发布失败、公共边缘非 200 或状态复读不一致都产生明确的 `failed` 或 `blocked`，不得被源站成功覆盖。

### 11. Harness 验证生产行为而不是测试回调

Harness 的 quick、full 和 release profile 都包含公网入口合同。测试使用受控 DNS、HTTP、状态文件、命令队列和进程替身，但调用生产探测、发布、切换、会话失效和回滚入口。覆盖特殊用途 IPv4/IPv6、重定向、代理绕过、原子写入失败、所有权冲突、异常回滚、旧 readiness 失效、旧命令终结和 Helper 旧 URL 拒绝。

测试替身只提供外部边界，不重新实现判定逻辑。源码关键字搜索和测试专用回调不能单独满足行为要求。

## Risks / Trade-offs

- [临时 URL 变化会中断已连接 Helper] → 代次变化立即失败关闭旧会话和命令，要求显式重新配对，避免旧命令在未知入口恢复后执行。
- [严格公共地址分类可能拒绝仅 IPv6 或特殊网络] → 同时支持 A 与 AAAA；无法形成全局可路由证据时报告 `blocked`，不降低判定标准。
- [待提交状态发布后进程可能崩溃] → 状态保持 `degraded`，持久预约和非在线状态继续阻止采集启动；服务器重启后从权威代次恢复并拒绝旧代次命令。
- [退出旧入口失败] → 事务停止候选入口并以更高代次恢复原入口身份；补偿无法完成时报告明确人工故障态，不保留伪 `online`。
- [Helper 更新失败导致公网网页可用但双机未就绪] → 分层状态保持公网边缘与 Helper readiness 分离，总体不写入 `online` 或验收通过。
- [路径规范化可能遇到符号链接、junction 或不存在文件] → 逐级解析所有已存在祖先的真实路径，再以 manifest 根目录做包含判断；无法解析或祖先逃逸时失败关闭。
- [真实 MySQL 或第二台电脑不可用] → 保留本机自动化证据并将目标环境结果标为 `blocked`，不推导为通过。

## Operational Invariants

- 现有入口状态首次加载时，在不改变当前 URL 和所有者的前提下建立代次记录；无法唯一确定当前入口时停止并要求操作员选择。
- watchdog 只有在入口状态、配对和命令代次可核对时才拥有恢复权限。
- 已保存但没有代次的 Helper 配置视为未就绪，必须使用当前交接信息重新建立连接和配对。
- 部署保存旧入口状态、运行时引用和可变运行状态；失败时以新代次恢复旧身份，且不删除旧候选或旧入口。
- 自动恢复不执行采集步骤，也不修改生产网络配置。
