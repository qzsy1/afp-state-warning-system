# 真实传感器接入前准备状态

## 当前结论

仓库实现具备候选发行身份、公网入口代次、唯一恢复所有者、公共边缘验证、切换预约、Helper 代次绑定和失败终态。固定运行目录仍是已部署候选，仓库中的后续修复尚未获得新的部署授权，因此本报告不把源码状态描述为在线运行状态。

`windows_readiness` 保持 `failed`。双机步骤 3 尚未执行，且在当前候选、Helper SHA-256、进程路径、服务器可达、配对、协议和入口代次 readiness 全部匹配前不得执行。物理传感器项目保持 `physical_sensor_pending`。数据库重试、历史未完成文件和目标 MySQL 对账只能由对应持久证据确认，不能根据当前会话状态推断为已解决。

## 公网入口安全边界

- 公网就绪分别验证源站、隧道控制面、公共 DNS、强制公共边缘 HTTPS、当前候选静态身份、权威入口状态和 Helper readiness。
- 入口状态包含单调代次、URL、提供方、唯一恢复所有者和候选身份，并通过跨 Windows 会话互斥进行原子发布。
- 切换和候选提升从仅本机管理端口取得有界预约；预约跨服务器重启持久存在，预约期间拒绝新的本机及 Helper 采集启动。事务取得预约后复读权威代次和恢复所有者，并在删除回退材料或报告完成前确认释放预约。
- 候选提升保留安全存储、Helper 注册状态、目标采集 journal、入口状态和切换预约。Helper 门通过前入口保持非在线；只有旧入口数据面、静态身份和运行服务重新通过才可报告回滚完成。无法证明旧入口或不存在旧入口时保留可用候选并进入明确失败终态。
- Helper readiness 要求当前候选、Helper 可执行文件 SHA-256、协议、命令生命周期、配对、入口代次和配对公网 URL 一致；仅有 Helper 进程不构成就绪。Helper 注册持久化损坏或写入失败时，切换和新采集均失败关闭，直至显式对账。
- 同代次服务器重启后无法证明状态的命令终结为 `command_state_lost`；迟到结果不能替换该终态，只有新的显式状态对账可以解除未确认启动阻断。
- 管理就绪和预约端点只允许通过回环地址访问 8771，公网反向代理入口不能调用。

## 验收边界

自动化测试用于证明仓库合同和无传感器协议行为，不替代第二台电脑、真实目标 MySQL 或物理传感器证据。任何响应正文、WebSocket 帧、Cookie、Token、配对码、密码、代理凭据和数据库密钥都不得进入证据。
