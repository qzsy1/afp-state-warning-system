# Proposal

## Why

AFP 在接入真实传感器前必须具备一致的发行身份、失败关闭的环境门禁和可审计的双机恢复能力。公网入口还必须把真实公共边缘可达、入口切换、Helper 会话代次和恢复所有权纳入同一合同，避免本机私网成功被误判为公网可用，或 URL 变化后旧会话与旧命令继续执行。

## What Changes

- 建立统一发行身份，绑定主程序、Helper、协议、统一帧、配置模板、静态资源和受管文件摘要，并在任何采集副作用前拒绝不一致组件。
- 提供隔离、不可就地覆盖的候选装配、验证和安全清理能力；未经独立授权不修改正式 `delivery/`。
- 提供互斥无密的 `local_direct` 与 `remote_helper` 配置模板，以及覆盖 Windows、存储、MySQL、Helper、网络、容量和未完成恢复状态的统一预检。
- 严格区分 `passed`、`failed`、`blocked` 与 `physical_sensor_pending`；只有真实设备物理读取项目可以保持 `physical_sensor_pending`。
- 提供两种模式默认至少 30 分钟、10 Hz 的无传感器耐久和故障恢复验证，并对 CSV、质量侧车、journal、retry spool 与 MySQL 做统一身份对账。
- 提供第二台 Windows 电脑可直接执行的 Helper 部署、检查和脱敏证据入口；本机协议模拟不得替代真实跨机证据。
- 把公网入口建模为持久化代次：本地源站、隧道控制面和公共边缘分别验证，公共边缘必须使用公共 DNS 返回的全局可路由地址、原域名 TLS SNI/Host、禁用代理且得到精确 HTTP 200。
- 公网入口 URL、提供方或恢复所有者变化时原子发布新代次，废止旧配对、readiness 和 Helper 会话，终结旧代次排队采集命令，并要求 Helper 在新代次重新完成连接与配对。
- 公网入口切换必须保留已验证回退路径、使用唯一恢复所有者并具备异常安全回滚；部署只有在强制公共边缘探测和状态发布均成功后才能完成。
- 公网状态证据分别记录 DNS、边缘 HTTPS、源站、隧道控制面、恢复所有者和 Helper 更新结果；任一必要层失败时不得写入 `online`。
- 内置模型身份只按规范化真实路径位于发行 manifest 声明的受管模型根目录内判定，不按路径字符串片段判定，避免误删外部自定义模型选择。
- 交付现场运行手册、Harness 强制合同、脱敏证据包和只包含真实设备事项的最终验收清单。

## Capabilities

### New Capabilities

- `pre-sensor-release-contract`: 定义统一发行身份、组件一致性、受管模型边界、隔离候选装配和正式 delivery 只读边界。
- `pre-sensor-environment-readiness`: 定义双模式模板、启动前门禁、统一环境预检、Helper 入口代次和状态分类。
- `pre-sensor-endurance-recovery`: 定义两种模式的 10 Hz 耐久、故障注入、持久化恢复、容量门禁和端到端对账。
- `pre-sensor-field-operations`: 定义双机无传感器部署、公网入口切换、操作员顺序、脱敏证据和真实设备剩余清单边界。

### Modified Capabilities

无。当前仓库尚无已归档的对应主规格。

## Impact

- Harness：增加统一预检、候选发行、环境分类、耐久恢复、公网入口代次与切换、模型来源边界和证据导出的强制检查及矩阵映射。
- 权威应用源：增加发行合同读取、启动前版本与配置门禁、入口代次持久化、会话失效、命令终结、容量状态和恢复状态投影。
- Helper：增加与主程序可比较的发行、协议和入口代次身份、独立诊断入口及第二台电脑部署检查。
- 公网入口：Tailscale 与其他隧道恢复路径共享同一探测、状态发布和恢复所有权合同，不再各自推断公网在线状态。
- 部署：切换事务在强制公共边缘验证、原子状态发布和回滚能力就绪后才完成，并保留旧入口直到明确退出。
- 配置与文档：提供两套无密模板、现场操作手册和严格限定的真实设备验证清单。
- 外部环境：目标 MySQL、第二台 Windows 电脑、管理员权限、防火墙、电源和生产网络保持只读检测或生成可审查脚本，缺失时明确阻塞。
