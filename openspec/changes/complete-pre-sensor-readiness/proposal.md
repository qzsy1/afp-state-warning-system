# Proposal

## Why

上一轮已经完成双模式真实采集核心与无硬件合同加固，但主程序、Helper、配置、静态资源和协议仍缺少统一发行身份，环境预检、候选部署、长期故障演练和操作员流程也未形成一个失败关闭的交付门禁。必须在接入真实传感器前消除这些与物理设备无关的风险，使现场剩余工作严格限于设备身份、真实信号、物理连接和实物耐久。

## What Changes

- 建立统一、可比较的发行与协议合同，绑定主程序、Helper、配置模板、静态资源、运行模块和摘要；启动前发现版本、合同或配置不一致。
- 生成隔离、带版本和摘要的现场候选包，验证导入、自检、静态资源、依赖和 manifest，且不覆盖正式 `delivery/`。
- 提供并自动验证互斥的 `local_direct` 与 `remote_helper` 无密配置模板；配置门禁在打开设备或发送远程启动命令前执行。
- 建立一个统一的传感器前预检入口，同时输出人可读报告和机器可读 JSON，覆盖 Windows 运行环境、DLL/SDK/驱动、存储、MySQL、Helper、HTTP/WebSocket、网络与电源设置、时间同步、容量和未完成对账。
- 统一预检结果语义：只有物理设备读取可为 `physical_sensor_pending`；缺失第二台 Windows 电脑、目标 MySQL、管理员权限或网络访问必须报告为 `blocked`，其他检查必须明确为 `passed` 或 `failed`。
- 为两种模式增加可配置、默认至少 30 分钟的 10 Hz 无传感器耐久和故障演练，覆盖慢磁盘、数据库和网络中断恢复、乱序/重复/缺口/重传、Helper 与主程序重启、停止超时、容量阈值和最终对账。
- 提供第二台 Windows 电脑可直接执行的一键部署/检查脚本；没有第二台电脑时，本机协议模拟不得标记为双机通过。
- 交付现场运行手册、一键入口、脱敏证据导出及“仅剩真实设备验证清单”，并阻止版本、配置、网络、存储、MySQL、Helper 部署或 Windows 设置问题进入该清单。
- 保留现有 `local_direct`、`remote_helper`、共享采集核心、API、前端字段、模拟采集、10 Hz、CSV/MySQL 和旧调用方兼容；不扩展模型预测、历史预警、Dashboard 因果指标、真实标签或生产预测审批。

## Capabilities

### New Capabilities

- `pre-sensor-release-contract`: 定义统一发行身份、主程序/Helper/配置/静态资源/协议一致性、隔离候选装配和正式 delivery 只读边界。
- `pre-sensor-environment-readiness`: 定义双模式模板、启动前配置门禁、统一环境预检项目、状态分类和修复建议。
- `pre-sensor-endurance-recovery`: 定义两种模式的 10 Hz 耐久、故障注入、持久化恢复、容量门禁和端到端对账。
- `pre-sensor-field-operations`: 定义双机无传感器部署检查、操作员顺序、脱敏证据包和真实设备剩余清单边界。

### Modified Capabilities

无。当前仓库没有已归档主规格；本变更复用并补充进行中的 `prepare-real-acquisition` 软件合同，不重复实现其双模式采集核心。

## Impact

- Harness：新增统一预检、候选发行、环境分类、耐久/故障演练和证据导出的检查及矩阵映射。
- 权威应用源：增加发行合同读取、启动前版本/配置门禁、容量与恢复状态投影；复用现有采集、Helper、journal、retry spool 和 MySQL 实现。
- Helper：增加与主程序可比较的发行/协议身份、独立诊断入口和第二台电脑部署检查。
- 配置与文档：新增两套无密模板、现场操作手册和严格限定的真实设备验证清单。
- 装配：候选包写入独立版本目录并生成可验证 manifest；正式 `delivery/` 保持不变，正式发布仍需单独授权。
- 外部环境：目标 MySQL、第二台 Windows 电脑、管理员权限、生产防火墙和实际网络变更仅执行只读检测或生成可审查脚本；缺失时明确阻塞，不伪报通过。
