## Context

参见 `proposal.md` 的动机和三个能力规格。当前 `new_collection_v12_0` 有 21 个采集通道，其中 `温度1`～`温度8` 来自 `thermocouple_8ch`；通道目录、别名、接口档案和数组归一化均固定到 8。后续正式采集不再使用该 8 路实物接口，而由 64 路设备产生 `温度1`～`温度64`。模型仍适合接收较少温度特征，因此需要从 64 路生成 8 个语义明确的连续分组均值，而不是把原始前 8 路继续当作模型温度输入。

当前采集管理器在同一试样的后续层启动前比较 CSV 列，列集合不同就拒绝继续；完整试样和训练导入也默认各层列宽一致。新合同允许各层传感器集合不同，但要求分层原始数据不可改写，补齐只发生在带来源记录的派生视图。实时推理还必须满足因果性，不能使用未来层数据计算中位数。

真实采集已经使用逐通道质量的统一帧，本机与远程 helper 共用采集配置，CSV 采用模式定义的宽表，MySQL 把传感器值写入 `sensor_json`。实时页面每 50 ms 检查新版本并向浏览器发送包含所有通道历史的载荷，前端为每个通道创建一张独立画布；这一方式扩到 64 路会显著增加重复数据、DOM 和绘制工作。

64 路设备的厂商型号与协议尚未出现在仓库中。因此设计固化软件可验证的规范边界，但不把现有 8 路 SMRF HID 细节当作新设备事实。正式驱动、发布配置和现场门禁必须在设备资料或协议抓包确认后补齐。

## Goals / Non-Goals

**Goals:**

- 用新模式表达 64 路热电偶和总计 77 路原始传感器，以 64 路接口替换旧 8 路实物采集，同时保留旧文件可读、可回放。
- 从 64 路原始温度生成 8 个固定组均值，为兼容维度的新模型和简化界面提供稳定投影。
- 允许同一试样各层通道集合不同，用试样内同通道中位数只填充整层缺失的派生数据，并保留因果/完整试样两种范围。
- 让本机、远程 helper、CSV、MySQL、恢复和实时展示使用同一份通道目录与质量语义。
- 让操作者通过互斥按钮在 8 张原始组图与 8 张均值组图之间切换，并共用一个组/单通道放大区域。
- 限制网络、内存和绘制成本，使展示降频不影响原始采集与保存。
- 把可自动验证的软件合同和必须人工验证的硬件事实同时接入现有 harness。

**Non-Goals:**

- 不训练 64 路输入模型；8 组均值模型仍需单独训练或提供明确兼容元数据，不能复用旧 8 路实物模型语义。
- 不在设备资料缺失时指定厂商命令、线序、电气拓扑、换算公式或默认量程。
- 不把缺失热电偶数据插值、补零或合成为“正常”数据。
- 不继续提供旧 8 路设备的正式采集能力；只保留旧数据模式的读取、回放和导出能力。
- 不在原始逐层 CSV、原始 MySQL 或原始恢复日志中写入中位数补值或组均值。
- 不改变其他传感器卡片、三级预警和健康指标的业务语义。

## Decisions

### 1. 新增 `new_collection_v13_0`，并从当前采集目录移除旧 8 路接口

新模式按当前 21 路方案保留 13 路非热电偶通道，并用 `温度1`～`温度64` 替换原 8 路热电偶，形成 77 路原始传感器。默认接口目录、配置模板、发现和发布合同只暴露 64 路接口；`thermocouple_8ch` 不再是可启动角色。旧模式解析保留在导入/回放边界，不要求旧驱动继续注册。

### 2. 逻辑 8×8 分组同时定义原始展示和 8 个派生均值

目录增加稳定逻辑分组 `TC-G01`～`TC-G08`，每组连续 8 路，并分别派生 `热电偶均值1`～`热电偶均值8`。组均值使用补层后的 8 个有限值做算术平均；缺少任一值时该均值不可用于模型，不计算“7 路平均”。聚合元数据记录输入范围、有效计数、补值掩码和规则版本。

这些逻辑分组也用于 8×8 原始展示、诊断汇总和测试定位，但不表示实际设备必然由 8 块 8 路模块组成。物理绑定另存设备/节点标识及厂商通道映射，因此一台 64 路设备、八台 8 路设备或其他经确认的拓扑都能投影到相同规范目录。

### 3. 模型输入使用独立的 8 组均值语义

64 路设备始终采集并保存原始温度。模型侧增加一个版本化输入投影，把 8 个组均值按固定顺序放入模型温度特征。模型元数据必须声明派生名称、输入范围、聚合版本、补值范围和缩放参数；旧检查点只声明 `温度1`～`温度8` 时，系统拒绝把组均值静默塞入这些槽位。

这样可以维持 8 个温度特征的张量维度，但不谎称新均值与旧 8 个物理测点语义相同。兼容模型需要重训，或由模型所有者提供明确验证过的聚合元数据。

### 4. 建立厂商无关的 64 路适配器合同

采集核心只接受适配器输出的通道索引、值、质量、源时间、源顺序、设备身份和错误信息。厂商驱动负责帧校验、冷端补偿和单位换算；只有有限的摄氏度值才能标为有效。设备协议确认后增加对应驱动与黄金夹具，在确认前不启用真实发布配置。

### 5. 统一帧允许逐通道缺失，不等待“64 路全好”

固定采集时钟仍为数据行边界，每帧包含所有选中通道及逐通道质量。适配器可以按整机或分组更新缓存；帧装配器在截止时间取各通道最新且足够新鲜的观测。缺失或过期写空值与质量原因，其余通道继续采集。

### 6. 同一试样按通道并集生成原始视图和派生视图

后续层启动不再比较列清单是否完全相同。每个分层原始文件保存当层真实选择、值和质量；试样原始完整视图以全部已保存层的传感器并集对齐，缺列保持空值。另生成模型/分析派生视图，对每个通道独立判断“整层缺失”：该层没有任何有限值时，才用允许范围内该试样该通道所有有限原始值的中位数填满该层；层内已有至少一个有限值时，不用此规则修复零散缺口。

实时派生范围为 `causal_so_far`，只读取当前和先前完成层；若没有可用中位数，模型等待该特征。试样完成后可生成 `completed_specimen` 视图，用全部完成层重算并保留独立版本。中位数补齐发生在组均值之前，且清单记录通道、层、标量、来源样本数、范围和原始摘要。

### 7. 远程链路增加原始/派生目录握手和紧凑帧

旧文件回放继续接受现有 `unified_frame_v1`。`new_collection_v13_0` 优先使用 `unified_frame_v2`：会话开始发送一次有序原始通道目录及其 SHA-256 标识，后续帧携带目录标识、会话标识、帧顺序、时间、等长值数组和质量数组。派生目录与聚合版本单独标识，避免接收端把组均值误认为原始通道。需要追踪来源的接口序号或时间以稀疏元数据附加，接收端先验证目录和数组长度再恢复为内部逐通道对象。

与每帧重复 77 个通道名和完整元数据相比，目录加位置数组能显著降低 helper 到服务器的持续流量；目录哈希与严格长度检查消除位置协议的错位风险。断线批次沿用现有 journal、摘要和幂等确认边界。

### 8. 原始保存与派生保存严格分离

逐层原始 CSV 在新模式中固定支持 64 个温度列并保留真实空值。MySQL 不新增 64 个固定数值列，继续把真实有效键写入两个样本表的 `sensor_json`，原始查询/导出按模式目录展开。完整试样输出区分原始并集视图与模型派生视图；派生视图包含补值后的通道和 8 个组均值，并与来源清单、原始摘要绑定。质量、缺失原因和传输统计进入证据/摘要侧车，而不是把错误码混入温度列。

### 9. 浏览器使用“原始/派生快照 + 增量”，而不是重复发送全历史

实时 API 增加热电偶展示载荷：原始目录和派生目录只在建立连接或改变时发送；首次发送共享时间轴、64 路原始历史矩阵、8 路组均值历史及补值/质量摘要，之后只发送连续序号、时间、当前值与质量。浏览器本地环形缓冲维护展示历史，检测序号缺口或目录变化后请求新快照。HTTP 降级路径可返回同一快照合同。

服务端为当前选中的原始温度生成实测主图，为选中的组均值生成采集/预测主图；不会为 64 路在每次刷新重复携带预测历史。模型未显式支持原始 64 路时，原始通道不显示组均值模型预测。

### 10. 专用面板提供两种组曲线投影

热电偶面板在桌面一行并排呈现 TC-G01～TC-G08 共 8 张紧凑组图。完整模式下，每图同一坐标系叠加对应连续 8 路原始温度曲线，从温度1～8到温度57～64，共 64 条曲线。图例使用稳定颜色，支持各通道显隐与单通道放大；组图显示单位、质量、有效计数及成员明细入口。平均模式仍使用 8 张组图，每图仅绘制数据链路提供的一条严格均值曲线，共 8 个均值，不在前端重新定义平均规则。缺口断线，当前值和补值来源保留在成员明细中。

互斥模式控件位于热电偶面板，并与传感器接口配置附近的选项保持同步。模式、显隐、分隔条和详情选择仅修改展示状态，保持采集会话、保存通道、helper 传输和模型输入合同不变。组与单通道放大使用同一个可收起的共享详情区域，不为 8 个组同时展开大图。

未建立采集会话、重启恢复阻挡或热电偶尚无历史时，仅采集页面按已解析的展示方案生成目录。选择 `new_collection_v13_0` 时仍保留 64 路原始目录、8 组均值目录及两个监测面板，显示等待快照、有效0/8和空曲线，不把64路移入普通卡片，也不生成零值或恢复就绪授权。展示配置仅传入响应生成函数，返回的采集状态、恢复文件和保存收尾状态保持原样；已有会话与页面方案不一致仍拒绝请求。旧数据模式不补入64路目录。

中心监测区使用上方热电偶面板、横向分隔条和下方其他传感器面板，默认比例为 42:58。常规最小高度为 180px/200px；空间不足时提供非零可访问高度。分隔条支持指针拖动、方向键、双击恢复默认比例、持久化比例及窗口缩放约束。两个面板各自纵向滚动，组图和卡片不得覆盖彼此。

其他传感器保留正常大小的卡片和 150px 曲线，桌面一行 4 个，多行在面板内部滚动，保持全部 13 路可访问。1366×768 和 1920×1080 均以一行 8 张热电偶组图、一行 4 张其他传感器卡片为目标；更窄中心区按可读宽度减少列数，禁止不可控横向溢出。

ESR四路沿用其他传感器中的原应变通道卡片与共享放大区，不增加独立大字面板。显示口径、候选标定、显式零点、原始诊断和会话来源以 `fix-esr1001-native-usb-acquisition` 当前合同为准，热电偶视图不修改应变换算、设备参数、保存或回放。

软件验证证据位于 `harness/logs/thermocouple-layout/browser-verification.json` 及对应截图，覆盖空会话恢复状态、64条原始曲线、8条均值曲线、TC-G08成员、共享放大、原应变卡片、独立滚动和1366×768/1920×1080布局。`visualization_app/test_thermocouple64_frontend.py` 覆盖空会话方案、无热电偶选择、旧模式和会话方案冲突；`harness/logs/thermocouple-layout/quick.log` 对应17/17软件检查通过。确定性热电偶曲线和应变历史证据不构成实物验收或正式更新。

### 11. 绘制与采集分离并使用有界降采样

前端在 `requestAnimationFrame` 中合并绘制当前模式的 8 张组预览和当前共享放大画布，同一时刻多次增量合并为一次显示更新；页面隐藏时暂停画布刷新但更新最新状态。每通道展示环形缓冲有明确上限，超过像素密度时用保留首尾与局部极值的降采样绘制。降采样结果仅用于画布，不回写采集、保存或模型输入。

服务端/浏览器显示刷新可以低于采集率；队列积压时覆盖“待显示的最新状态”，不能覆盖待保存数据。这一隔离是 64 路扩展不影响数据完整性的关键。

### 12. Harness 同时验证原始、派生和现场事实

自动合同检查覆盖旧 8 路入口移除、64 路目录/适配器、8 组均值、跨层列并集、中位数补层、因果范围、v2 编解码与恢复、原始/派生对账和双视图行为；容量检查用 6000 帧确定性数据记录字节、队列、丢帧和渲染统计；现场项确认真实设备身份、逐组/逐通道对应、冷端补偿、目标速率、持续运行和断线恢复。

矩阵增加独立检查 ID 与命令入口，并把相关源码模式纳入变更选择。quick 运行目录、编解码和核心前端合同；full 加保存、恢复和容量；release 再要求交付包与现场状态。模拟证据与现场证据保持不同等级。

### 13. 完整运行程序和大体积数据统一存放在 D 盘

唯一受支持的完整运行目录为 `D:\AFP_Runtime\AFP_Integrated_System_Modular`，源码目录为 `D:\AFP_Integrated_Modular_v2`，构建中间产物仅允许进入 `D:\AFP_Runtime\.afp-staging`，采集数据默认进入 `D:\AFP_Capture`。C 盘不保存源码、完整交付包、候选运行目录、构建缓存或采集数据。

发布过程可以在 staging 中短暂形成候选目录，但候选完成验证并提升到固定运行目录后必须清理；失败候选也必须清理。未经用户明确许可，不保留第二个完整可运行副本或大体积归档。源码、虚拟环境和小型验证证据不视为完整运行程序，但不得包含复制出的完整交付目录。

正式目录更新使用既有受控切换流程；采集、保存收尾或恢复门禁未允许切换时保留现有进程和文件，不强制结束、不丢弃恢复文件、不绕过门禁。源码和独立浏览器验证不能替代正式目录启动后的发布身份、磁盘摘要、运行修订与页面资源一致性复验。软件验证、正式更新与实物验收分别报告。

当前正式身份为 `2.0.5-rc.3-efff5d861df6-wt25385eac-20261021T081400Z`，运行修订为 `c951c7911ce01abb4c91182bae3c20abd1da1cda15898d579e580584ff375060`；进程、清单与9项服务页面资源证据见 `harness/logs/thermocouple-layout/runtime-verification.json`。该正式资源尚不包含此处的无会话热电偶显示修复。采集停止，但三份薄膜压力未完成文件保留，保存收尾未完成且切换就绪返回 `allowed=false`，正式更新验收保持未完成。保存方案中的ABB与PLC启用开关均为关闭，其他接口字段保持原值。

## Risks / Trade-offs

- [64 路设备协议未知] → 先实现和验证厂商无关合同；设备资料、黄金帧和实物探针齐全后才启用真实驱动与 release 门禁。
- [8 组均值改变旧模型特征语义] → 使用独立派生名称和聚合元数据，旧检查点默认拒绝，新模型需重训或经模型所有者验证。
- [中位数补层掩盖真实缺测] → 原始存储永不补值；派生输出携带逐点补值掩码、范围、样本数和原始摘要。
- [完整试样中位数使用未来层造成实时泄漏] → 实时只使用 `causal_so_far`，试样完成后才生成独立的 `completed_specimen` 视图。
- [试样内某通道完全无数据] → 不跨试样或全局补值，依赖特征的模型保持不可用。
- [位置数组比命名对象更易错位] → 使用不可变有序目录、SHA-256 目录 ID、模式 ID和严格等长校验；不匹配时整帧拒绝。
- [宽 CSV 列数增加人工查看成本] → 保持稳定顺序和 8 路分组列布局；程序化分析优先按模式目录读取。
- [64 路历史仍可能占用较多浏览器内存] → 共享时间轴、有界历史、降采样、8 张紧凑组预览和单一共享放大区域。
- [当前组自动量程会削弱跨组绝对比较] → 提供统一量程切换，并始终显示当前数值和单位。
- [单路异常造成整组颜色过载] → 状态同时落到通道标签与组汇总，曲线缺口和文本原因并存。
- [新增模式误进入旧模型] → 采集目录和模型目录分离，启动前校验名称、顺序、维度和缩放元数据。
- [远程网络不足] → 紧凑帧、批次压缩空间、显示降频和落盘恢复；不得通过降低保存完整性来缓解。

## Migration Plan

1. 固化新模式、64 路原始目录、8 路派生目录、均值/补层版本和确定性夹具，并把旧 8 路实物入口从当前配置合同移除。
2. 解除后续层列一致性启动限制，实现原始通道并集、`causal_so_far`/`completed_specimen` 中位数派生视图和来源清单。
3. 在设备资料确认后实现 64 路厂商驱动与物理绑定，将其输出接入现有逐通道缓存和统一帧；未确认前保持真实设备门禁关闭。
4. 加入版本化原始/派生目录握手、紧凑帧、journal 恢复和本机/远程等价检查，服务器保留旧文件帧读取能力。
