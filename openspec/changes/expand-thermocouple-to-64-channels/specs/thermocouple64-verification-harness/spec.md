## Purpose

定义 64 路热电偶替换旧 8 路接口、8 组均值投影、跨层中位数补齐和双视图进入 quick、full、release 验收所需的自动化检查、性能证据与真实设备边界。

## ADDED Requirements

### Requirement: 64 路目录与适配器合同检查
Harness SHALL 提供可重复的 64 路夹具和检查，覆盖目录数量、顺序、8×8 分组、厂商映射、边界值、非有限值、缺失、重复、乱序和分组故障，并确认当前正式配置中不存在可启动的旧 8 路热电偶接口。

#### Scenario: 运行 quick 协议合同
- **WHEN** 开发者运行 quick 配置
- **THEN** Harness 在不连接真实设备的情况下验证 64 路规范目录和通用适配器边界，并对通道 1、8、9、16、57、64 的映射进行明确断言

#### Scenario: 厂商协议夹具尚未就绪
- **WHEN** 设备型号或协议资料尚未确认
- **THEN** 通用软件合同可以执行，但 release 结果 MUST 明确报告厂商协议与实物验证未完成，不得把通用模拟标为真实设备通过

#### Scenario: 检查旧 8 路入口移除
- **WHEN** Harness 检查默认接口目录、配置模板、前端传感器选项和发布合同
- **THEN** 这些当前入口只包含 64 路热电偶，旧 8 路仅可作为历史数据夹具被读取

### Requirement: 8 组均值合同检查
Harness SHALL 对 `热电偶均值1`～`热电偶均值8` 的固定分组、算术平均、有效计数、名称、顺序、聚合版本和模型元数据执行值级断言。

#### Scenario: 验证确定性均值
- **WHEN** 64 路夹具使用可计算的递增数列
- **THEN** Harness 对 8 个组逐值验证其等于对应连续 8 路的算术平均，并确认原始 `温度1`～`温度8` 未被改名或覆盖

#### Scenario: 组内一路无效
- **WHEN** 夹具使任一组中的一个原始值缺失、过期或非有限
- **THEN** Harness 确认该组均值不可用于模型且没有使用 7 路平均或零值补齐

#### Scenario: 旧模型缺少聚合元数据
- **WHEN** 64 路模式加载只声明旧 8 路实物温度的检查点
- **THEN** Harness 确认系统拒绝静默映射组均值，并保留仅采集路径

### Requirement: 传输与恢复合同检查
Harness SHALL 验证目录协商、紧凑帧编码解码、顺序、幂等、批次确认、断线重传、目录不匹配拒绝和有界背压。

#### Scenario: 模拟远程 helper 断线恢复
- **WHEN** 测试在连续帧中断开连接、重复发送已确认批次并恢复
- **THEN** 服务器最终接收每个预期帧恰好一次，通道和值保持一致，并报告可验证的重连与去重计数

#### Scenario: 注入错误目录
- **WHEN** 帧携带未知目录 ID 或错误数组长度
- **THEN** 检查确认接收端拒绝该帧且没有写入采集行或错误映射通道

### Requirement: CSV 与 MySQL 对账检查
Harness SHALL 使用确定性 64 路数据验证逐层原始 CSV、原始完整试样视图、恢复载荷、两个 MySQL 兼容样本表和平面原始导出的行数、键集合、空值和抽样值一致，并单独验证补齐/均值派生视图及其来源清单。

#### Scenario: 完整数据对账
- **WHEN** 测试保存一组包含 64 路已知序列的数据
- **THEN** 所有保存目标具有相同样本数，并对首、中、末通道及首、末样本逐值一致

#### Scenario: 部分缺失数据对账
- **WHEN** 夹具使指定通道在指定帧缺失或无效
- **THEN** CSV 为空、MySQL JSON 不含有效数值键或按现行空值合同表示，质量证据保留原因，且任何目标都不出现合成零

#### Scenario: 派生视图不污染原始目标
- **WHEN** 系统为试样生成中位数补齐和 8 组均值
- **THEN** Harness 确认原始层 CSV、原始完整视图和 MySQL `sensor_json` 的摘要及值保持不变，补值仅存在于带来源清单的派生输出

### Requirement: 跨层通道与中位数补齐检查
Harness SHALL 覆盖同一试样各层通道集合不同、传感器列并集、整层缺失中位数补齐、层内间歇缺失、无可用中位数以及实时/完成试样两种范围。

#### Scenario: 不同层使用不同通道集合
- **WHEN** 后续层增加或减少传感器通道
- **THEN** Harness 确认采集不再因列集合不同被拒绝，原始层各自保持真实列和值，试样派生视图使用通道并集

#### Scenario: 整层缺失使用试样内中位数
- **WHEN** 一个通道在试样部分层有有限值、另一层完全无有限值
- **THEN** Harness 按该通道允许范围内全部有限原始值独立计算中位数，验证缺失层每行使用同一标量，并核对补值掩码和来源样本数

#### Scenario: 层内间歇缺失不补齐
- **WHEN** 某层同一通道同时具有有限值和缺失点
- **THEN** Harness 确认整层补值规则不修改这些行内缺口

#### Scenario: 整个试样从未出现通道
- **WHEN** 所有层都没有某通道的有限值
- **THEN** Harness 确认派生视图保持不可用且依赖该通道的模型被阻止，不产生全局中位数、零或其他替代值

#### Scenario: 实时补值不使用未来层
- **WHEN** 夹具把所需通道只放在未来层
- **THEN** 当前实时推理保持不可用；试样完成后才允许以 `completed_specimen` 范围重新生成早期层派生值

### Requirement: 8×8 前端行为检查
Harness SHALL 通过可执行前端行为测试验证上下独立传感器面板、位于传感器接口配置附近且显示当前模式的互斥 `完整模式`/`平均模式（8组均值）` 选项、桌面一行 8 张组曲线图、每图 8 条原始曲线、`已显示 64/64 通道` 状态、`TC-G01`～`TC-G08` 快速选择、组与单通道共用的单一放大区域、8 张各含一条严格均值曲线的组图、正常尺寸且桌面一行 4 个的其他传感器网格、面板分隔条、通道筛选、补值标识和增量重连。检查 SHALL 证明 8 个组分别只使用其连续 8 个通道，并且切换不修改其他传感器布局、采集配置或保存请求。

#### Scenario: 渲染 64 路页面
- **WHEN** 前端加载 64 路确定性载荷
- **THEN** 测试观察到 8 张组图、每图 8 条唯一原始通道曲线、`已显示 64/64 通道` 和 1 个组/单通道共享放大区域，且其他传感器网格中没有热电偶卡片

#### Scenario: 窄窗口选择最后一组
- **WHEN** 页面在 1366×768、1920×1080 及更窄窗口中加载完整模式并选择 `TC-G08`
- **THEN** `温度64` 在 TC-G08 组图中可访问，共享详情区绘制 `温度57`～`温度64`，其他传感器面板仍可访问且页面没有覆盖或不可控横向溢出

#### Scenario: 增量序号中断
- **WHEN** 测试跳过一个显示增量序号
- **THEN** 前端停止在旧快照上追加并发起快照恢复，恢复后每个通道当前值与服务端一致

#### Scenario: 切换为平均 8 通道
- **WHEN** 前端从完整视图切换到 `平均8通道`
- **THEN** 测试观察到 8 张各含一条严格均值曲线的组图及对应原始范围、成员明细入口、有效计数和模型支持状态，所选组使用同一共享详情画布，64 路采集配置、保存请求和其他传感器面板没有变化

#### Scenario: 调整传感器面板比例
- **WHEN** 测试拖动分隔条、使用方向键、双击恢复默认比例并改变窗口尺寸
- **THEN** 热电偶面板默认小于其他传感器面板，用户比例被记忆并受两面板最小高度约束，完整模式和平均模式均不会使任一面板消失或相互覆盖

### Requirement: 页面入口、缓存资源与 API 失败诊断
Harness SHALL 验证桌面启动入口只复用健康版本身份与页面引用资源均匹配当前构建的服务；任何资源不匹配时 SHALL 阻止打开旧页面并指出端口冲突。页面需要的初始化和当前数据请求失败时 SHALL 显示失败路由及错误状态。访客页面 SHALL 使用访客可访问的 bootstrap、静态预计算演示资源和浏览器模拟数据路径；仅受保护功能依赖的 403（例如 helper 状态、MySQL 默认值或访客直接访问真实 `/api/realtime`）是预期权限响应，不能单独判定访客数据区加载失败。Harness SHALL 检查页面实际依赖的路由和可选/受保护路由分支，不得把所有 403 统一当成页面故障，也不得把失败请求原因臆定为未保存的历史浏览器记录。

#### Scenario: 启动服务与页面版本不匹配
- **WHEN** 本地端口已有服务，但其健康版本身份、页面 HTML 或任一页面引用的脚本/样式与当前交付不一致
- **THEN** 启动器不复用该服务，并报告被占用的本地服务端口

#### Scenario: 访客加载页面数据
- **WHEN** 访客打开页面并运行预计算模拟
- **THEN** Harness 验证 bootstrap、当前 cache-busted 静态资源和浏览器模拟数据可加载；页面实际依赖的请求失败时显示该请求路径与错误，单独的受保护 403 不触发通用数据加载失败

#### Scenario: 展示补值来源
- **WHEN** 组均值包含中位数补层数据
- **THEN** 前端行为测试确认用户能识别补值状态并查看涉及的通道及 `causal_so_far` 或 `completed_specimen` 范围

### Requirement: 性能与容量检查
Harness SHALL 提供确定性的 64 路容量场景，分别测量采集/保存、helper 传输和浏览器绘制，记录配置、样本数、字节数、耗时、峰值队列、丢帧/去重和渲染统计。

#### Scenario: 自动容量回归
- **WHEN** full 或 release 配置运行 6000 帧的 64 路合成场景
- **THEN** 保存链路无静默丢行，队列和浏览器历史保持在配置上限内，最终报告包含可比较的性能统计和任何超限原因

#### Scenario: 显示端降频
- **WHEN** 测试把显示消费速度限制到低于采集速度
- **THEN** 采集和保存仍完成全部预期帧，显示只减少绘制次数或合并增量，不增加保存缺口

### Requirement: F 盘单一主运行交付
系统 SHALL 只把 `F:\new_AFP_exam\AFP_Integrated_System_Modular` 作为受支持的完整主运行目录。源码 SHALL 位于 `F:\new_AFP_exam\AFP-Readiness-Repo`，构建中间产物 SHALL 仅位于 `F:\new_AFP_exam\.afp-staging`，默认采集目录 SHALL 为 `F:\AFP_Capture`。C 盘 MUST NOT 保存完整交付包、候选运行目录、构建缓存或采集数据。未经用户明确许可，系统 MUST NOT 保留第二个完整可运行副本或大体积运行归档。

#### Scenario: 提升已验证候选
- **WHEN** 已验证候选被提升为当前运行版本
- **THEN** 候选内容进入固定主运行目录，旧完整运行副本和 staging 候选被清理，最终只存在一个受支持的完整运行目录

#### Scenario: 构建或验证失败
- **WHEN** 候选构建、完整性检查或启动验证失败
- **THEN** 失败内容只在 F 盘 staging 中处理并完成清理，不得回退到 C 盘保留大体积副本

#### Scenario: 检查保存位置
- **WHEN** Harness 检查交付目录、staging 根和默认采集目录
- **THEN** 所有路径均位于 F 盘，且没有未经许可的第二个完整运行程序

### Requirement: 旧模式和模型隔离回归
Harness SHALL 在同一矩阵中验证旧 8 路数据文件仍可回放和导出，但旧 8 路实物采集入口已移除；现有模型不得被错误地解释为 8 组均值模型。

#### Scenario: 回归旧采集模式
- **WHEN** quick 或 full 配置运行旧模式夹具
- **THEN** 旧文件的目录、CSV 列、MySQL 导出和只读界面保持原合同，且新的真实采集配置无法选择旧 8 路接口

#### Scenario: 回归现有模型
- **WHEN** 64 路采集模式加载现有检查点
- **THEN** 测试确认没有组均值聚合元数据的旧检查点不会接收 `热电偶均值1`～`热电偶均值8`，64 路原始采集仍可在仅采集模式运行

### Requirement: 真实设备 release 门禁
Harness SHALL 将真实 64 路设备身份、接线、通道对应、量程、冷端补偿、目标采样率、持续采集、断线恢复和保存对账列为独立现场项，自动化模拟不得代替该证据。

#### Scenario: 执行现场验收
- **WHEN** 操作者按现场清单连接正式设备并完成逐组/逐通道激励、持续采集和故障恢复
- **THEN** 证据记录设备与协议版本、配置摘要、64 路对应关系、有效率、错误计数、CSV/MySQL 对账和签字结论，且不包含密码或令牌

#### Scenario: 现场证据缺失
- **WHEN** release 检查没有当前设备和当前构建对应的现场证据
- **THEN** Harness 将真实 64 路采集标为待验证或阻断正式发布，不得显示为自动化通过
