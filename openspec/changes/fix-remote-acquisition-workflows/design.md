## Context

见 `proposal.md - Why`。当前实现同时跨越主程序外置 Python/HTML/JavaScript、服务器 WebSocket、访问电脑 local helper 及其独立打包 EXE。主程序启动器可加载交付目录中的外置业务文件，但 local helper 的发送循环和本机配置代码位于 `AFP_Local_Capture_Helper.exe` 打包边界内，因此两类交付物必须采用不同的更新策略。

远程访问中的资源归属如下：浏览器文件和本机 MySQL 属于访问电脑；采集会话、预测和 Web API 属于服务器；传感器连接可属于访问电脑 helper 或服务器本机。设计必须在 API 和状态中显式保留该归属，不能依赖 `127.0.0.1` 或 Windows 绝对路径的表面字符串推断。

## Goals / Non-Goals

**Goals:**

- 只改变远程边界、传输调度、数据源传递、MySQL 配置作用域和诊断调度，不改动采集协议解析、模型计算和业务阈值。
- 使四条问题链路具备可自动验证的行为合同、可观测指标和可回滚交付物。
- 保持主程序稳定启动器二进制不变，同时为必须变化的 local helper 生成可追踪的新二进制。
- 使局域网或客户端实验室中的实际模拟继续在访问电脑 helper 中以 10 Hz 执行；同时把公网“模拟采集”改为浏览器本地播放预计算合成结果，避免高 RTT 进入逐点采集、保存和推理链路。

**Non-Goals:**

- 不改变 MySQL 表结构、CSV 字段和目录结构。
- 不重新训练或替换预测模型，不调整健康指标、预警阈值或缺陷结论规则。
- 不宣称自动化或本机公网测试等同于第二台电脑现场验收。
- 不把远程服务器文件浏览扩展成通用文件管理器。

## Decisions

### 1. helper 使用单在途、ACK 驱动的自适应数据泵

每个 helper 会话最多保留一个未确认批次。空闲时低频等待；队列有数据时立即取有界批次发送；服务器确认后立即安排下一批，不再等待固定一秒。批次上限按采样率和目标排空窗口计算，并设置绝对上限，避免单帧无限增大。断线时保留当前批次并在重连后以相同会话和序号重发，继续使用服务器幂等确认。

公网批量不能使用与 RTT 无关的固定 5 点上限。最低可持续批量按 `ceil(sample_rate × (ack_rtt + 0.2s安全余量))` 计算；队列年龄超过 2 秒时逐级扩大恢复批量，绝对上限 50 行，并继续受单帧序列化字节上限约束。该策略只提高每个已持久化批次承载的连续样本数，不改变单在途、服务器持久接受后 ACK、序号幂等和固定配对地址。ACK RTT 使用 helper 单调时钟；服务器接收墙钟差和样本端到端墙钟差可能包含两台电脑的时钟偏差，不能作为单向网络耗时。

选择该方案是因为它复用现有 pending batch/ACK 语义且修改面最小。未选择“并行多个在途批次”，因为需要新增滑动窗口、乱序确认和更复杂的内存上限；未选择单纯缩短固定定时器，因为网络抖动时仍会产生重复发送或增长性积压。

### 2. 实时载荷采用会话版本失效，远程 Bootstrap 按角色跳过本机探测

远程镜像在接受新批次或状态变化时推进单调版本。WebSocket 缓存最近一次业务载荷及版本，只有版本变化才重新聚合和预测；无变化期间发送轻量心跳。Bootstrap 的硬件发现仅对回环 `local_admin` 保留，其他角色返回 helper/会话状态而不顺序探测服务器 PLC、ABB 和 RTSP。

选择版本失效而不是纯时间节流，是为了在没有新数据时消除重复计算，同时在新数据到达时立即推送。版本仅控制调度，不改变预测输入、窗口或计算函数。

### 3. 远程模拟数据采用浏览器上传加会话不透明标识

`local_admin` 继续使用服务器本机选择器。局域网或客户端实验室中的实际模拟由浏览器选择单个 CSV 或文件夹，上传到服务器会话隔离暂存区。服务器返回随机、不包含路径的数据源标识；兼容 helper 使用该标识接收受限文件清单和有界分块，并在完成大小、相对路径及 SHA-256 校验后启动。公网模拟不上传任意文件，只允许选择服务器发布清单中的审核合成演示包。

上传入口执行扩展名、数量、大小、相对路径和总量校验，并在会话结束、替换或超时后清理。原始客户端绝对路径仅用于浏览器显示文件名，不发送或不作为服务端定位依据。

选择上传后由服务器一次性中继给 helper，而不是让服务器访问 SMB 共享或让 HTTPS 页面直接连本机不受信 HTTP 端口，是为了避免额外网络凭据、防火墙、混合内容和本机服务冒充风险。相同内容哈希可复用已校验 helper 缓存，但会话运行状态、保存身份和停止结果必须独立。

### 4. MySQL 配置分为 helper-local 与 server-target 两条执行链

“访问电脑本机 MySQL”的连接测试和写入在 local helper 执行。其密码复用 helper 已有的 Windows 当前用户 DPAPI 机制加密保存；服务器只转发一次性设置命令并接收安全元数据和预检结果，不落盘密码。“服务器或指定目标 MySQL”继续由服务器现有存储和写入链执行。

2026-09-22 公网复测揭示此决策在真实 helper 采集路径尚未落地：网页目标库密码框默认空且 `/api/mysql/defaults` 故意不返回密码，预检却把空密码交给 MySQL，复现 1045；真实采集则把目标库开关及密码随 `start_capture` 发送给 helper，由 helper 停止时连接目标库。服务器已有凭据的只读预检成功不等于 helper 在另一台电脑写入成功。后续实现 MUST 消除这两条执行路径不一致，而非仅放宽预检或回填密码。

目标库采用服务器侧会话绑定的非秘密配置标识：默认目标与服务器已有配置的主机、端口、用户和数据库完全一致时，由服务器解析已有密码；用户显式填写自定义目标密码时，只在授权会话内短暂使用，并使预检与最终保存引用同一个目标配置。空密码不得表示“尝试空口令”，也不得自动借用其它目标的密码；如确需空口令目标，须有独立、明确的配置语义。目标密码不回传浏览器、不写入样本暂存文件、不传给 helper，也不出现在状态和日志。访客无目标库写入权限。

真实模式中，helper 保留五类硬件采集、本机 CSV 和可选 helper-local MySQL，但目标库开关从发送给 helper 的采集配置中剥离。服务器在启动时记录授权会话、目标配置和待绑定的采集意图，收到 helper 的 `capture_uuid` 后绑定。现有 `RemoteAcquisitionMirror` 的 50,000 点环形缓存只用于实时显示与预测，不能作为数据库完整铺层来源；服务器须在现有单在途批次/ACK 链上，为目标库单独追加会话隔离、磁盘配额受控的持久样本记录。只有批次按 `(session_id, capture_uuid, sequence)` 持久接受后才确认；重复批次返回原确认而不重复追加。磁盘写入或配额失败必须反映为明确积压/失败，不得假确认或丢弃早期样本。

helper 停止后仍发送最终状态批次；服务器等待最终状态及此前全部序号确认，再从完整记录构造与 helper 同一 `capture_uuid`、工况、试样、层号和连续样本序号，复用现有 `MySQLCaptureStore.save_layer` 的完整铺层事务和表结构。现有写库函数一次接收整层列表，实现时须对持久记录设明确磁盘配额，并采用受限大小读取或分批入库，不能因铺层超过实时镜像容量就无限制地装入内存。重复停止或数据库重试复用同一身份与完整数据，不新增表结构或截断其它会话数据。成功后才报告 `server_target` 已保存；失败时本机 CSV 和可选本机库照常完成，服务器保留不含凭据的有界待补传记录与可重试状态，并在安全保留期后清理。目标库写入和重试不得阻塞 helper 实时上传及浏览器预测。

局域网或客户端实验室中的实际模拟在兼容 helper 在线时优先由 helper 本地回放，因此可复用真实采集的本机 CSV 和 helper-local MySQL 保存；服务器仍通过完整批次日志和同一目标配置解析保存 server-target MySQL。helper 不可用时只能在启动前明示回退到服务器模拟，该回退不支持访问电脑本机 MySQL。服务器本机 `local_admin` 原路径保持不变。公网预计算演示不创建采集会话、不连接 MySQL、不产生待补写记录，并隐藏或禁用两个 MySQL 保存入口。目标库和本机库在实际采集页面显示独立的执行端、预检结果和停止写入结果，不能以一个“已连接”覆盖另一端的失败。

helper hello/status 增加不含密码的能力和配置元数据；设置凭据、预检和写入使用明确命令类型。新电脑若没有可解密配置，前端显示未配置并要求重新输入。MySQL 1045 诊断同时涵盖密码错误和 `用户@来源主机` 授权错误；连接拒绝、超时和未知数据库使用独立分类。

隔离客户端复测进一步表明“数据库已创建”和“AFP 表已初始化”不能混为一项。访问电脑用户显式点击本机“保存并检查”时，helper 可在当前已选择数据库内调用既有 `initialize_schema(create_database=False)` 创建缺失表，随后重新执行包含回滚写入的预检；只允许从 `stage=schema` 且明确存在缺失对象的结果进入该分支，网络、认证、未知数据库和驱动错误不得触发 DDL。初始化失败时以实际错误和分类覆盖笼统的“表结构不完整”，其中 1142 归为授权不足。真实空库和中断重试验证要求所选数据库级 `SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES, CREATE VIEW, SHOW VIEW, DROP`；`REFERENCES` 用于外键，数据库级 `DROP` 只用于 `CREATE OR REPLACE VIEW` 重试，不授予全局权限。服务器目标库继续只做既有结构预检，避免网页操作越权修改受管数据库。

本机复测补充：若首次检查在连接阶段收到明确的未知数据库 1049/`Unknown database`，该动作本身已经是用户对 helper-local 目标的显式初始化授权。helper SHALL 仅对通过数据库名校验的当前本机配置调用 `initialize_schema(create_database=True)`，成功后重新执行预检；认证失败、网络不可达、服务未启动、驱动缺失和权限错误不得触发建库。服务器目标链路继续使用只读结构预检。

服务器目标 MySQL 进程不属于 helper 生命周期。服务器重启后若独立 MySQL 未自动启动，应用保持网络/服务不可达诊断；运维恢复现有 MySQL 监听后，服务器复用同一内存/本地目标配置完成预检和保存，不改成向访问电脑下发密码，也不自动启动任意远端数据库进程。

真实数据库烟雾测试还暴露了两条保存链共享的事务顺序错误：`save_layer` 在父 `afp_layer` 记录之前插入带外键的两张采样表，真实 MySQL 因此返回 1452，而伪游标测试未体现约束。修复保持表结构、事务边界和有界流式批次不变：先在同一事务中以 0 行建立/刷新父铺层，排空采样迭代器后再更新最终 `sample_count`，失败仍整体回滚。不得删除外键或把整层重新装入内存。

选择 DPAPI 而不是跨电脑复制配置，是因为本机凭据不应在服务器和多台电脑间共享，且 helper 已有同类保护实现。选择由 helper 写本机 MySQL 而不是服务器反向连接访问电脑，是为了避免暴露 3306、NAT 和来源授权不一致。

未选择“每台访问电脑直接连目标库”，因为这要求逐机分发目标密码、MySQL `用户@来源主机` 授权和网络可达性，不能满足现有目标库的服务器作用域合同；也未选择把服务器密码经 WSS 下发 helper。持久样本记录的成本是服务器磁盘、ACK 延迟和补传清理，需要以 50 Hz、超过镜像容量、断线重传和磁盘配额测试约束。

### 5. 诊断拆为即时本地快照和异步模型增强

提交诊断时先冻结本地证据快照并立即返回本地规则结果与任务标识。默认快速路径使用确定性的现有工具收集器生成证据包，只执行一次模型综合调用。现有模型规划加综合流程保留为显式深度模式。任务记录 queued/running/succeeded/degraded/failed 状态、阶段和耗时。

外部调用使用连接和读取超时，快速任务总时限 90 秒；浏览器最多等待 120 秒并可继续查看本地结果。对相同会话、证据指纹、模型和安全配置摘要的成功结果设置短 TTL 缓存。超时不在同一阶段立即重复调用，避免最坏等待翻倍。

选择“本地先行”而不是只缩短模型超时，是因为外部服务延迟无法完全控制。保留深度模式可避免删除原有 Agent 规划能力，同时让常用路径只承担一次外部往返。

### 6. 源码、交付目录和二进制采用分层发布

`visualization_app/` 为业务源码事实来源；通过测试后将明确清单中的外置文件同步到 `delivery/AFP_Integrated_System_Modular_v2.0.3_Agentic/app/`。主程序 `AFP_Integrated_System_Modular.exe` 保持原 SHA-256。因为 helper 传输与 DPAPI 配置代码位于独立打包边界，使用仓库既有构建脚本仅重建 `local_helper/AFP_Local_Capture_Helper.exe`，记录旧新 SHA-256、构建命令和依赖清单。

选择分层发布是为了缩小回归面。不得因修改外置 Web 或 Python 文件而顺带重建主程序；也不得只改 helper 源码却继续交付旧 helper EXE。

### 7. 验证证据按等级输出

验证分为四级：单元测试、进程内集成测试、本机经公网域名端到端测试、第二台电脑现场验收。前三级由开发机完成；第四级提供可执行清单并在用户实际运行后记录结果。若 `release-regression-harness` 尚未实现，则直接运行其规格涵盖的现有测试和启动检查，不因工具尚未就绪跳过回归。

### 8. 用户反馈回归：会话停止、接口边界和 MySQL 一致性

局域网或客户端实验室实际模拟的启动、停止和导出仍使用自身模拟会话。真实硬件控制租约仅约束真实硬件操作；授权用户停止自己模拟会话时不依赖该租约，但不得影响其他会话或真实采集。前端使用当前采集模式判断是否需要本地导出，不再读取未维护的状态字段；停止过程显示持久进度，超时后查询同一会话状态确认最终保存结果。公网预计算演示只操作当前浏览器内存中的播放状态，不调用服务器停止或保存接口，也不产生可导出的“实采”文件。

五类物理接口的驱动、端点和通道来源仍以原有 `SENSOR_INTERFACE_PROFILES` 与 `default_capture_interfaces()` 为准。模拟界面保留五类逻辑卡片而不分配真实物理接口；授权远程模拟后端保留用户提交的五类元数据、通道映射及额外自定义卡片（如有），但剥离物理绑定字段；模拟数据驱动由采集模式单独选择，不连接硬件。访客仍使用受限的单一内部模拟驱动，避免扩大其配置权限。

目标 MySQL 在局域网或客户端实验室实际模拟时仍由服务器执行既有写入流程，必须保留已启用配置并显示结果。helper 本地回放时，本机 CSV 与本机 MySQL 由 helper 使用同一 `capture_uuid` 和铺层身份保存；服务器将 helper 批次持久记录后再 ACK，并在终态后保存目标库。任一数据库失败不得中断本机 CSV 或另一数据库的状态报告。本机配置轮询不覆盖未提交输入；修改既有配置后若密码留空，预检明确要求重新输入，避免静默测试旧档案。公网预计算演示不显示或执行上述保存链路。

### 9. 公网复测回归：模拟门禁和 helper 连接交接

模拟启动先冻结当前模式。只有真实模式才获取真实控制租约、等待正在执行的硬件检查或触发新硬件检查；模拟模式的“检查”只比较模拟源通道与五类逻辑接口的通道归属，不访问物理驱动。这样同时消除错误阻塞和由串行硬件超时造成的表观启动延迟。

helper WebSocket 连接以具体发送器实例作为所有权标识。新连接已替换旧连接后，旧处理器的 `finally` 清理只能清理自身，不得清除新发送器。服务器对同一 helper 连接的命令、心跳确认、结果确认和采样确认统一经过连接级发送锁，避免多个请求线程交错写入帧导致客户端解码失败和重连。HTTP 轮询降级、单在途批次、五类驱动和采样解析保持不变。

### 10. 使用 Windows Sandbox 建立隔离客户端验收实验室

在宿主机 `F:\AFP_Client_Validation_Lab` 中暂存经过 SHA-256 固定的真实 helper、模拟 CSV、无既有数据目录的 MySQL 运行文件和验收脚本。Windows Sandbox 只读映射输入目录，只允许向独立的 `results` 目录写入脱敏证据；Sandbox 自身的系统盘仍由 Windows 管理，不能指定到 F 盘。测试结束后按用户要求保持 Sandbox 运行，但证据必须持续写回 F 盘，因为误关、崩溃或主机重启都会清除 Sandbox 内部状态。

干净 Sandbox 不保证预装 MySQL 所需的 Visual C++ 运行库。暂存阶段只接受 Authenticode 状态有效且签发者为 Microsoft Corporation 的 x64 Redistributable，并在 Sandbox 内静默安装，不安装到宿主机。MySQL 首次账号建立不得通过 `root@127.0.0.1` 登录：在 `skip-name-resolve=1` 下，`--initialize-insecure` 生成的是 `root@localhost`。初始化脚本必须用仅存于 Sandbox 内的 `--init-file` 创建 `afp_app@127.0.0.1`，按上述数据库级权限完成真实空库初始化，并在验证后立即删除引导 SQL；导出结果不得包含密码。Sandbox 不保证 Store 版记事本或 PATH 中存在 Edge，因此凭据只在 Sandbox PowerShell 窗口显示，浏览器使用已验证的 Edge 绝对路径启动。

Sandbox 用于验证与宿主不同的 Windows 用户、DPAPI 保护范围、公网浏览器上传、真实 `AFP_Local_Capture_Helper.exe`、helper-local MySQL 和一个仅绑定回环地址的 TCP JSON 合成源。真实 helper 的环回测试只新增会话级自定义接口，不覆盖或改写 PLC、ABB、热电偶、薄膜压力和 UVC 五类内置接口。另设协议级虚拟 helper，以确定性虚拟时钟验证 50 Hz、单在途 ACK、断线重传和 30,000 行完整性；虚拟 helper 不导入物理驱动，也不作为真实设备证据。

证据分为 `passed`、`failed`、`not_covered`。沙盒成功可以证明公网浏览器、helper 传输、本机 MySQL、目标库服务端链路和诊断降级的隔离客户端行为，但不能证明另一台物理电脑的网络策略，也不能替代供应商特定 USB/HID、串口、UVC、PLC 或 ABB 设备验收。真实第二台电脑、真实目标库行数和五类物理设备仍须保持待现场确认，除非取得对应现场记录。

### 11. 局域网地址和实时传输按可用路径选择

`discover_lan_urls` 不再只枚举并按 IP 字符串排序。Windows 环境优先使用具有 IPv4 默认网关、状态为 Up 且不是虚拟/隧道类型的物理以太网或 Wi-Fi 地址；APIPA、回环、Hyper-V、WSL、Docker、Tailscale、代理隧道和测试网段不得成为推荐地址。状态 API 同时返回 `recommended_url` 与带网卡名称、类型和优先级的候选地址，保留旧 `urls` 字段用于兼容。前端显示 `recommended_url`；若页面本身通过私有 IPv4 打开，则当前 origin 是已验证可达路径并优先显示。DHCP 变化后现有十秒状态刷新更新显示，不把 `192.168.101.31` 等现场地址写入代码。

实时浏览器链路不再按“公网 HTTPS/其它”分裂：只要浏览器支持 WebSocket，公网使用 `wss://`、局域网和回环使用 `ws://`，均订阅现有会话隔离的实时端点。握手失败才进入 HTTP 轮询；轮询采用不低于 500 ms 的有界间隔和单在途请求，恢复后重新尝试 WebSocket。该修改只替换传输调度，不改变实时载荷、预测计算或权限检查。

### 12. helper 硬件检查与采集控制使用独立生命周期

硬件检查是可阻塞供应商 DLL/API 的不可信工作负载，不能与 `start_capture`、`stop_capture`、`status`、心跳和采样 ACK 共用单线程 FIFO。helper 为检查任务维护独立状态和唯一活动任务；重复检查返回现有任务状态或明确 busy，不形成无界队列。真实采集开始前请求取消旧检查，检查必须在独立可终止进程中运行并受总时限约束；超过时限或取消后终止该进程并返回 `timed_out`/`cancelled`，不得继续占用采集控制通道。模拟采集仍不创建任何物理检查任务。

helper 握手增加不含凭据的协议版本、构建标识和能力字段。网页分别显示连接在线、活动检查、检查超时和版本不兼容，不能把命令超时描述成 helper 离线。旧 helper 仍可连接，但缺少最低协议能力时 MUST 在真实采集前提示更新，不得静默进入可能阻塞的旧命令路径。

诊断本地快照和结果 API 继续由服务器独立执行，不等待 helper 检查、采集控制或实时轮询。局域网改用 WebSocket 后，诊断请求不再与 100 ms 实时短连接竞争；模型增强仍遵守既有一次调用、90 秒服务端总时限和 120 秒浏览器上限，不通过放宽时限解决加载失败。

### 13. 诊断工具规划必须服从已确认接口类型

`check_network_path` 继续只接受 PLC/ABB 且 `physical_interface_kind=ethernet` 的事件，不通过接口名称推断或放宽安全校验。确定性规划器在 PLC/ABB 同时异常但 helper 未返回物理接口类型时，保留跨接口时间线，并改用 `inspect_interface_mapping` 收集安全证据；它不得先计划一个必然被校验器拒绝的工具。缺少网络工具证据时，本地结论只表述为“网络接口绑定信息缺失”，不得宣称端点或链路已经故障。

默认快速模型路径仍只进行一次外部调用。请求中显式传递 `required_interface_ids`、`known_evidence_ids_by_interface` 和符合验证器的嵌套 JSON 样例；模型只能引用对应接口的已知证据。模型仍不合规或供应商失败时保持既有本地降级，不放宽证据校验、不增加重试次数。

### 14. 局域网和客户端实验室实际模拟由 helper 本地十赫兹回放

局域网或客户端实验室浏览器仍是会话和数据源选择的控制面，但兼容 helper 是实际模拟的默认数据面。服务器先将会话绑定模拟源以有界分块和 SHA-256 交付 helper，再下发包含配置采样率、通道映射、保存选项和会话身份的启动命令。helper 使用单调时钟的绝对期限 `start + sample_index / sample_rate` 调度 10 Hz 回放，不使用“处理完再等待 100 ms”的累积漂移模型。公网预计算演示不进入本决策的数据面。

模拟驱动只读已校验文件并产生与真实驱动相同的样本字典，然后复用 helper 现有本地 CSV/MySQL、增量待发队列、单在途 ACK 和服务器完整日志。采集频率与网页发布频率解耦：浏览器可以只渲染最新帧，但不得反向阻塞 helper 生成和保存样本。helper 每个批次从增量队列取数，不再为取得未发送行而复制全部历史。

执行端只能在启动前决定：兼容 helper 在线则使用 helper；否则明示回退服务器模拟。会话运行后 helper 掉线时保持本地采集与待发队列，不将同一会话静默迁移到服务器重新开始；连接恢复后按原 `capture_uuid` 和序号补传。旧 helper 未声明文件交付和本地模拟能力时不得静默下发新命令。

### 15. 模拟源显式预下载和固定配对链路低延迟回放

局域网或客户端实验室的模拟数据区增加两个相互独立的入口。主入口“下载到本机辅助程序并校验”把文件准备、内容校验和缓存复用提前到开始采集之前；辅助入口“另存示例 CSV 到电脑”用于人工检查或离线选择。页面至少列出一个约 240 点、约 24 秒的快速合成数据包和一个 6000 点、600 秒的耐久合成数据包，显示 synthetic 标识、采样率、点数、通道、大小和 SHA-256。批准目录只包含专门生成或审核过的合成文件，不向浏览器暴露服务器路径、生产数据或任意目录浏览能力。公网访客和已授权用户都只获得浏览器演示包，不获得 helper 预下载能力。

模拟源使用 `not_selected → uploading → preparing → ready/failed` 的显式状态机。服务器收到上传后先校验文件数、大小、相对路径和 SHA-256，再校验非空 CSV、表头、有效数值行和逻辑通道；helper 收到内容后重复关键校验并以内容哈希建立缓存。只有当前会话身份、通道映射和已验证哈希都匹配时才返回 ready。开始命令只引用 ready 缓存，不再一边传大文件一边等待首批样本。零字节文件、无有效行、通道不匹配或 helper `ok=false` 直接结束开始流程，避免进入误导性的十五秒等待。

helper 的服务端地址仍是配对时保存的显式配置。LAN 实际模拟或真实采集测试由用户把 helper 配对实际 LAN URL，公网真实采集测试配对公网 HTTPS URL。页面显示浏览器路径、helper 配对路径、RTT 和不一致警告，提供重新配对入口，但不自动切换地址、不探测后改写配置，也不实现“局域网优先、公网回退”。公网预计算演示不依赖 helper 地址。这样实际采集链路保持可重复、可审计的网络边界，同时演示播放不受网络往返延迟支配。

源交付不再对每个 256 KiB 块建立独立 JSON/Base64 请求；实现阶段应采用受限二进制流或更大的连续分块，保留会话绑定、总量限制、断点清理和最终哈希。helper 读取 CSV 时采用流式或分块迭代，不将整个大文件一次性转换为字典列表。缓存按内容哈希和配额管理，运行引用存在时不得清理，失败的临时内容及时回收。

样本泵改为新样本与 ACK 双事件唤醒，仍保持单个未确认批次和幂等序号。批量策略只根据当前固定配对链路的 RTT、队列和既有吞吐调整，不改变连接目标：LAN 以 100–200 ms 为发送目标，公网按 RTT 合并 2–5 个 10 Hz 样本；ACK 到达后立即尝试发送下一批。开始新 `capture_uuid` 时，旧未确认批次留在旧会话恢复边界，新会话重置自身序号、在途和唤醒状态，避免旧 ACK 状态卡住首批数据。

采样定时、本地 CSV、本机 MySQL、网络上传、服务器持久化、预测和浏览器绘图维持独立队列或调度边界。10 Hz 是真实业务采样时间线，不以提高到更高频率作为优化目标；浏览器可降频合并绘图但必须分别展示本地有效采样率、helper 待发队列、服务器接收延迟、浏览器发布延迟和绘图帧率。首批超时诊断组合本地产生数、队列、在途批次、最后 ACK 和连接状态，区分数据源、上传/ACK 与离线根因。

停止采用两阶段语义。第一阶段由 helper 停止本地生产并立即返回 `local_stopped_at`、`generated_rows`、`queued_rows` 和 `flush_state=flushing/completed`；第二阶段继续通过原单在途链排空停止前队列并发送最终状态。服务器镜像收到旧运行中批次时不得覆盖已经观察到的本地停止事实；页面在 `flushing` 阶段冻结“正在采集”语义，可继续补绘但标为历史同步。只有待传为零、最终状态已确认且保存端进入终态才显示完成。

延迟展示拆为四类：helper 单调 ACK RTT、`queued_rows/sample_rate` 计算的队列年龄、可能含跨电脑时钟偏差的样本端到端年龄，以及浏览器用 `performance.now()` 测得的本机载荷处理耗时。WebSocket 载荷到达次数只称“页面更新频率”，不称“绘图帧率”。

本阶段不修改五类传感器独立驱动及通道映射、真实采集协议、预测模型、MySQL 表结构、诊断安全边界或主程序 EXE。实现源以 `visualization_app/` 为准，只将经验证的外置业务文件同步到交付目录；由于预下载协议、缓存校验和事件驱动样本泵位于 helper，交付时必须重建并重新下载最新版 helper。

### 16. 目标 MySQL 配置标识与采集参数契约保持一致

目标库预检会向当前授权会话返回不含密码的 `mysql_target_config_id`，页面随后在接口检查、工艺参数读取和采集启动中复用该标识。采集配置数据类必须接受并保留该服务器专用字段，服务器据此解析已预检配置；不修改目标库凭据保存方式、数据库结构或任何传感器接口。

helper 边界继续执行显式剥离：服务器转发前删除目标库连接字段和 `mysql_target_config_id`，helper 自身的配置白名单也排除该字段。这样旧 helper、新 helper 和未来重建版本都不会把服务器配置身份误当成本机配置，同时本机 MySQL 字段、模拟数据源和五类接口映射保持不变。

### 17. 采集配置与传输路由元数据必须在服务器边界分离

`execution_host` 和 `simulation_execution_choice` 描述浏览器、服务器与 helper 之间的执行选择，不属于传感器、模拟源或保存配置。服务器所有直接构造 `AcquisitionConfig` 的入口以及服务器采集日志回放入口统一通过一个严格构造边界：只剥离明确列入白名单的路由元数据，再让数据类继续校验其余字段。这样既修复本机管理员/局域网服务器模拟的字段漂移，也避免通过“忽略全部未知字段”掩盖前端拼写错误或意外协议变化。

该边界不改变 `mysql_target_config_id` 的服务器配置身份语义，不进入 helper 的服务器字段仍由 helper 白名单排除；五类接口驱动与通道映射、真实采集协议、MySQL 表结构、预测模型和 LangChain 诊断逻辑均保持不变。

### 18. 公网模拟改为版本化预计算浏览器演示

公网模拟使用版本化、可缓存的静态演示包。演示包只包含专门生成或审核过的 synthetic 样本、五类逻辑接口元数据、预计算预测曲线、健康指标、预警、异常类型、层/试样聚合和演示诊断；清单记录 schema 版本、10 Hz 逻辑采样率、点数、生成模型或规则版本、压缩大小和 SHA-256。发布过程检查其不含凭据、服务器路径、客户端路径或生产采集数据。

页面在进入公网模拟区时预取所选演示包；准备完成前禁用开始并显示下载/校验进度。准备完成后，开始操作只创建浏览器本地播放代次并记录 `performance.now()`，逻辑样本索引按 `floor(elapsed / 100 ms)` 计算；绘图按 2–5 帧/秒合并到最新索引，不逐点补画积压帧。这样 10 Hz 表示演示时间轴和数据点速率，而不是要求浏览器每秒重绘十次完整界面。

停止操作先递增播放代次，再把运行状态设为 false，并取消计时器与动画帧；所有异步回调在提交状态前核对代次。目标是在点击后 100 ms 内冻结状态，且至少五秒内无旧回调继续推进。重新开始创建新代次并从第一个样本开始。浏览器标签页进入后台时暂停可见播放，回到前台后按当前代次恢复，不制造追赶队列。

演示运行期不得调用采集启动/停止、helper 命令、实时 WebSocket、状态轮询、CSV 导出、MySQL、运行时预测模型或 LangChain。界面把“模拟采集”明确标为“预计算合成数据演示”，把预测、预警和诊断标为预计算结果，并隐藏或禁用文件上传、helper、硬件检查、保存和数据库控制。公网真实采集继续使用原 helper、五类真实接口、保存、预测和诊断链路；局域网与客户端实验室实际模拟继续使用第 14、15 节链路。

本阶段的实现位于外置 Python/HTML/JavaScript 和演示资产，不要求重建主程序或 helper EXE。只有后续实际采集协议发生变化时才需要重新发布 helper。

### 19. 浏览器导出句柄与执行端直接保存路径分离

服务器本机和 helper 本地采集由实际执行端使用原生目录选择器取得绝对路径，并在同一进程内执行存在性、目录类型和临时文件写入检查。浏览器 `FileSystemDirectoryHandle` 只保存在当前页面内存中，用于服务器模拟停止后的会话文件导出；其 `name` 仅用于显示，不写入保存路径输入框，也不序列化为 `save_root`。

页面按执行端显示单一保存入口：`local_admin` 和 helper-local 会话显示直接保存目录，远程明确选择服务器模拟时显示浏览器导出授权，公网预计算演示隐藏两者。直接保存目录必须是已存在的绝对路径；相对路径以独立错误码拒绝，原生选择器不再允许选择尚未创建的目录。这样权限错误只表示实际 ACL/共享写入失败，不再把路径归属错误伪装成权限不足。

## Risks / Trade-offs

- [浏览器上传大文件夹增加内存和等待] → 设置单文件、文件数、总量限制，逐文件校验并展示明确进度；本变更不支持无限目录。
- [单在途批次限制极端高延迟链路吞吐] → 使用自适应有界批量并监控积压；若验收显示目标采样率仍不足，再以独立变更评估多在途滑动窗口。
- [helper 本机 MySQL 写入使双端状态更复杂] → 用明确命令、作用域字段、幂等记录标识和状态指标隔离两条执行链，数据库失败不反向终止采集。
- [诊断缓存可能返回过时解释] → 证据指纹包含采集版本、告警和配置，TTL 短且结果显示缓存命中；证据变化立即失效。
- [local helper 重建带来杀毒软件或 Windows 兼容风险] → 使用既有工具链和依赖，不新增第三方依赖；在干净目录启动、校验签名或哈希并进行第二台电脑现场测试。
- [本机公网测试无法覆盖异机网络和权限差异] → 最终报告明确证据等级，异机项在用户验收前保持“待确认”。
- [Sandbox 环回设备可能被误解为真实硬件] → 所有环回数据和结果标记为 synthetic client lab，五类物理设备统一记为 `not_covered`，不形成真实缺陷结论。
- [网卡优先级在不同 Windows 环境差异较大] → 推荐地址使用可注入的候选元数据和确定性排序测试，保留全部候选及当前 origin 回退，不硬编码适配器名称或现场 IP。
- [终止硬件检查可能使供应商驱动未正常释放] → 检查放在独立子进程，终止只回收检查进程；真实采集管理器留在 helper 主进程并在检查结束后独占设备，不在线程中强制杀驱动。
- [旧 helper 缺少版本字段] → 兼容显示其在线状态，但真实采集前明确要求更新；模拟、文件上传和服务器诊断不因旧 helper 被阻断。
- [模拟文件中继增加启动等待和磁盘占用] → 传输前展示进度，使用有界分块、内容哈希复用和配额清理；只在完整校验后启动回放。
- [helper 本地模拟使执行端选择更复杂] → 在启动前冻结 `execution_host` 和能力快照，运行期间禁止静默切换；页面始终显示 helper/server 实际执行端。
- [预下载缓存增加访问电脑磁盘占用] → 以内容哈希去重、设置单文件/总量/有效期配额、运行引用保护和失败临时文件清理，并在页面显示占用与清理结果。
- [固定配对地址可能使 LAN 页面仍经公网上传] → 显示浏览器与 helper 路径不一致及 RTT，要求用户主动重新配对；为保证验收可重复性，不自动改写或切换连接。
- [事件驱动发送可能提高服务器处理频率] → 保留单在途、100–200 ms LAN 目标和公网有界合批，预测与浏览器绘图按版本/频率合并，不把每个网络事件变成重复预测。
- [可下载数据包可能泄露现场数据] → 目录只纳入明确生成或审核的 synthetic 数据，发布前固定哈希并检查敏感字段；真实采集文件不自动进入下载目录。
- [公网演示包首次下载仍受网络带宽影响] → 页面提前预取、压缩并使用版本化强缓存；未准备完成前不进入播放状态，准备完成后运行期不再依赖 RTT。
- [2–5 帧/秒绘图可能被误认为采样率降低] → 同时显示“逻辑数据 10 Hz”和“页面绘图帧率”，曲线按最新逻辑索引合并更新，不虚报实际采集。
- [预计算预测和诊断可能被误解为实时结论] → 所有结果显式标记 synthetic/precomputed，不写数据库、不导出为实采文件，也不形成真实缺陷或设备状态证据。

## Migration Plan

1. 先为四项行为补充失败测试和受控性能测试，固定当前缺陷表现。
2. 在 `visualization_app/` 依次实现 helper 数据泵与指标、WebSocket/Bootstrap 调度、远程上传、MySQL 作用域和诊断异步化；每一步运行对应测试及核心回归。
3. 使用既有构建脚本重建 local helper，记录构建环境、命令、旧新 SHA-256，并验证无新增运行时依赖。
4. 将经过验证的外置业务文件和新 helper EXE 同步到交付目录，更新交付哈希清单；确认主程序 EXE 哈希未变化。
5. 在开发机执行完整测试、启动检查、模拟采集、远程 helper 回环、MySQL 预检和公网域名端到端测试，保存机器可读结果和必要日志。
6. 输出第二台电脑验收清单，覆盖 helper 配对、50 Hz 持续采集、浏览器文件/文件夹、该电脑本机 MySQL 初始化以及诊断快速路径。用户现场结果返回后再更新异机结论。
7. 为局域网网卡排序、LAN/Public WebSocket 一致性、阻塞检查取消与控制优先级补失败测试，再实现最小改动；重建 helper 并在本机 LAN、公网和隔离客户端分别验证后，保留真实第二台电脑/真实设备为现场验收。
8. 为 helper 模拟源交付、10 Hz 单调回放、本机 MySQL、服务器回退、断线补传和显示解耦补先失败后成功测试；仅重建 helper 与同步外置业务文件，不重建主程序 EXE。
9. 在本机、局域网、公网域名和隔离客户端执行 10 Hz × 600 秒验收，分别记录生成、本地 CSV/本地 MySQL、服务器接受、目标 MySQL、队列和浏览器新鲜度；真实第二台电脑结果在用户验收前保持待确认。
10. 为零字节/无有效行拒绝、双下载入口、helper 预缓存、固定配对地址、旧在途状态隔离和事件驱动上传先补失败测试；再仅修改 `visualization_app/` 外置业务代码并重建 helper，不修改主程序 EXE、五类驱动、模型或 MySQL 结构。
11. 以约 240 点快速包执行首批样本验收，以 6000 点耐久包执行 10 Hz × 600 秒验收；本机、实际 LAN、公网和隔离客户端分别记录开始到首样本、本地采样率、队列、ACK、端到端 P95、保存行数及浏览器绘图率。真实第二台电脑和五类物理设备仍由用户现场验收。
12. 为公网预计算演示补角色路由、演示包校验、本地单调时钟、合并绘图、播放代次停止和运行期零采集/零保存请求的失败测试；实现后仅同步外置业务文件与演示资产，并确认两个 EXE 哈希不变。在 1200 ms 受控 RTT 下验证准备完成后首帧不超过 200 ms、停止冻结不超过 100 ms、停止后五秒无变化，以及 600 秒逻辑时钟误差不超过 0.5 秒。

回滚时恢复交付目录外置文件与旧 helper EXE，并恢复对应哈希清单；主程序 EXE 始终保持不变。DPAPI 新配置使用独立版本字段，旧 helper 遇到未知字段时忽略，回滚不得删除用户原有配置。

### 17. 公网模拟稳定渲染与真实界面状态隔离

公网预计算演示继续使用 10 Hz 逻辑时钟和 2–5 帧/秒合并绘图，但绘图周期不再调用会重建全部卡片的完整页面渲染。演示包首次显示时建立通道卡片，后续只更新数值节点与现有 Canvas；每个通道从完整 synthetic 包预先计算固定显示范围，避免滚动窗口极值导致纵轴周期性缩放。窗口概率和层汇总只在窗口边界变化时更新。

公网模拟状态使用独立的只读逻辑结果：五类接口、17 个通道和预计算诊断均显示成功，并明确标注未连接物理设备、未调用运行时模型或 LangChain。进入模拟前保存真实硬件检查状态，退出后恢复；模拟态接口发现不得写入真实接口快照。该改动仅涉及公网模拟前端、测试、OpenSpec 和交付静态副本，不修改服务器采集、helper、MySQL、真实驱动、模型或诊断后端。
