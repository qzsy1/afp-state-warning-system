## Why

当前公网访问把浏览器、服务器和访问电脑三处资源混用：本地辅助程序以固定一秒批次上传数据，授权用户选择模拟文件时却打开服务器文件选择器，访问电脑本机 MySQL 凭据没有可移植的机器级作用域，模型增强诊断又以多次串行外部调用阻塞结果显示。这些问题在服务器本机访问时会被同机文件系统、同机 MySQL 和既有登录状态掩盖，但换到另一台电脑后会直接表现为采集滞后、路径不存在、数据库认证失败和诊断等待过长。

本变更需要在不改变现有传感器驱动、预测模型、预警算法、CSV/MySQL 数据结构和稳定启动器 EXE 的前提下，修正远程边界并提供可重复的本机与异机验收证据。

2026-09-22 本机复测新增反馈：远程模拟“停止并保存”会因真实硬件租约过期、前端误用主采集导出入口和不可见的保存进度而失败；远程模拟会话还静默丢弃目标 MySQL 开关，helper 状态轮询会覆盖尚未提交的本机 MySQL 输入；五类传感器接口在模拟界面被折叠成同一个物理映射。该反馈属于本变更的回归修复，不授权改变五类原有硬件协议与解析。

2026-09-23 公网复测新增反馈：授权模拟采集会被后台真实接口检查阻塞，页面表现为启动失败和高延迟；helper 重连过程中还可能被旧 WebSocket 处理器误标离线。该反馈继续属于远程采集边界修复：模拟模式必须只校验模拟源，helper 新旧连接必须按连接身份交接，且服务端并发命令与采样确认不得交错写入同一 WebSocket 帧。

2026-09-23 隔离客户端复测新增反馈：访问电脑本机 MySQL 与服务器目标 MySQL 均不能保存。证据表明两条链路根因不同：服务器重启后其独立 MySQL 进程未启动，目标配置因此在 TCP 连接阶段失败；Sandbox 本机数据库和账号已创建，但 AFP 关系表为空，现有“检查 MySQL”又承诺不初始化表，导致首次新电脑无法进入可保存状态。本轮只补齐 helper-local 的显式首次表初始化和服务未启动诊断/验收，不把服务器目标密码或写入职责下放给 helper。

2026-09-24 空库真实 helper 验收进一步发现客户端实验室与旧授权示例缺少外键和视图重试所需的数据库级权限：`REFERENCES`、`CREATE VIEW`、`SHOW VIEW` 和 `DROP`。缺少前者会在建立外键时报 1142；首次初始化中断后，`CREATE OR REPLACE VIEW` 重试还会因缺少 `DROP` 再次报 1142。修复只统一最小权限模板、诊断建议和验收说明，不改变表结构或五类采集接口。

## What Changes

- 将 helper 样本上传从固定一秒节流改为有界、ACK 驱动的数据泵，保持现有批次序号、重复确认和断线重试语义，并暴露积压与端到端延迟指标。
- 公网实时推送仅在采集版本变化时重新生成业务载荷；远程 Bootstrap 不再执行随后会被丢弃的服务器本机网络探测。
- 远程模拟 CSV/文件夹统一通过浏览器选择并上传到会话隔离的服务器暂存区；只有 `local_admin` 保留服务器本机原生文件选择器。
- 明确“访问电脑本机 MySQL”和“服务器/目标 MySQL”两种作用域；本机凭据由 local helper 使用 Windows DPAPI 按当前 Windows 用户加密保存，浏览器和服务器只读取不含明文密码的安全元数据。
- 保持 PLC、ABB、热电偶、薄膜压力、UVC 热像仪五类独立接口及真实模式映射；模拟模式只替换数据来源，不把五类卡片绑定到同一物理接口。
- 修复远程模拟停止和本地导出始终使用同一会话；保存进度、失败和超时恢复可见，目标 MySQL 开关不得在服务端被静默关闭。
- 扩充 MySQL 错误分类，使 1045 同时提示密码和 `用户@来源主机` 授权问题，并保持 CSV 保存与待补传能力不受数据库失败影响。
- 让访问电脑 helper 在用户显式执行首次“保存并检查”时，仅在已存在的本机数据库内创建缺失 AFP 表并完成回滚写测试；服务器目标库仍只检查既有结构，服务器 MySQL 进程生命周期仍由服务器运维负责。
- 统一新电脑本机库的数据库级最小权限为 `SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES, CREATE VIEW, SHOW VIEW, DROP`；其中 `DROP` 仅服务于中断后的视图重建重试，不授予全局权限。
- 模型增强诊断先立即返回本地事实结果，再异步补充模型结果；默认快速路径减少外部模型往返，限制分阶段超时，并对相同异常指纹短期复用已完成结果。
- 为四条修复链路增加单元、集成、同机公网和第二台电脑人工验收矩阵；最终结论明确区分自动化、本机集成和现场异机验证。
- 主程序的普通 Python/HTML/JavaScript/配置修改继续复用当前稳定 `AFP_Integrated_System_Modular.exe`；local helper 的传输和凭据逻辑位于其打包边界内，因此仅重建 `AFP_Local_Capture_Helper.exe`，并单独记录重建原因与 SHA-256。

## Capabilities

### New Capabilities

- `remote-acquisition-transport`: 规定 helper 到服务器、服务器到浏览器的低延迟、有序、可恢复数据传输及延迟观测要求。
- `remote-simulation-source`: 规定不同访问角色选择、上传、隔离和解析访问电脑模拟 CSV/文件夹的行为。
- `mysql-scope-portability`: 规定访问电脑本机 MySQL 与服务器/目标 MySQL 的作用域、凭据保护、错误诊断和换机初始化行为。
- `responsive-agent-diagnosis`: 规定本地诊断即时可用、模型增强异步执行、超时降级和重复结果复用行为。

### Modified Capabilities

无。仓库当前尚无对应主规格；本变更新增行为规格，并使用 `release-regression-harness` change 中的核心回归基线作为最终验收约束。

## Impact

- 主要影响 `visualization_app/` 中的 helper 传输、远程采集镜像、Web API、前端模拟数据源、MySQL配置和 Agent 诊断调度代码。
- 同步更新既定交付目录 `delivery/AFP_Integrated_System_Modular_v2.0.3_Agentic/app/` 的外部业务文件；保持 `AFP_Integrated_System_Modular.exe` 二进制及其 SHA-256 不变，只重建并替换受本变更直接影响的 `local_helper/AFP_Local_Capture_Helper.exe`。
- 增加针对远程角色、批次积压、会话文件隔离、DPAPI凭据元数据、诊断超时/缓存和回归边界的测试；不引入新的第三方运行时依赖。
- 不改变传感器协议解析、17通道模型输入、M3232薄膜压力通道、健康指标、预警阈值、CSV目录结构或数据库表结构。
