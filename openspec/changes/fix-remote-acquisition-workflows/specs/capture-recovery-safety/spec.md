## Purpose

定义上一采集持久化收尾阻塞的保留、重试、显式丢弃和状态刷新边界，确保普通启动、重试与检查不会隐式删除可恢复数据。

## ADDED Requirements

### Requirement: 恢复门禁默认保留全部阻塞证据
系统 SHALL 在发现 MySQL 待补传记录或未终结 `.partial` 文件时阻止新正式采集，并 MUST 默认保留原文件。状态查询、启动、重启、接口检查和 MySQL 重试失败 MUST NOT 删除、截断、覆盖或改名任何阻塞文件。

#### Scenario: 上一采集存在待补传和未完成文件
- **WHEN** 采集根目录同时存在 MySQL pending 记录和 `.partial` 文件
- **THEN** 新正式采集 MUST 被阻止，状态 MUST 返回脱敏计数和稳定条目标识，所有阻塞文件 MUST 保持不变

#### Scenario: MySQL 重试仍然失败
- **WHEN** 操作员对待补传记录执行 MySQL 重试且目标数据库仍不可用
- **THEN** 待补传记录及其层 CSV MUST 保留，未完成文件 MUST 不受影响，恢复门禁 MUST 继续阻止新正式采集

### Requirement: 丢弃恢复证据必须显式确认并精确限域
系统 SHALL 仅允许本机管理角色通过专用恢复动作丢弃阻塞证据。请求 MUST 同时包含布尔确认、固定确认短语、当前扫描指纹和逐条稳定标识；缺少任一确认、扫描已变化或条目不匹配时 MUST 拒绝。普通采集控制及检查接口 MUST NOT 继承该授权。

#### Scenario: 未确认的恢复请求
- **WHEN** 请求未同时提供确认布尔值、确认短语、当前扫描指纹和所选条目标识
- **THEN** 系统 MUST 拒绝请求且所有文件保持不变

#### Scenario: 精确丢弃已确认条目
- **WHEN** 本机管理员确认当前扫描中的指定 pending 或 `.partial` 条目
- **THEN** 系统 MUST 只处理这些条目，返回逐条结果和审计标识，不得处理完成 CSV、会话配置、摘要、模型、凭据或其它文件

### Requirement: 恢复动作必须拒绝活动采集和路径边界异常
系统 SHALL 在任何采集仍活动时拒绝丢弃恢复证据。目标 MUST 是采集根目录内当前扫描到的普通文件，且文件名必须匹配 MySQL pending 或 `.partial` 允许类型；符号链接、重解析点、越界目标、未知标识和扫描后发生变化的条目 MUST 被拒绝。

#### Scenario: 采集仍在运行
- **WHEN** 任一采集线程仍活动且管理员提交丢弃请求
- **THEN** 请求 MUST 被拒绝且阻塞文件保持不变

#### Scenario: 符号链接或越界目标
- **WHEN** 恢复扫描遇到符号链接、重解析点或解析后位于采集根目录外的候选
- **THEN** 系统 MUST 将其报告为不可安全处理并保持门禁，MUST NOT 读取、移动或删除目标内容

### Requirement: 恢复完成后必须即时刷新权威状态
成功重试或显式恢复动作 SHALL 在同一请求内重新扫描采集根目录并更新内存中的权威门禁状态，不得要求重启应用。若仍有未处理或不安全条目，门禁 MUST 保持；若全部阻塞已安全处理且没有活动采集，下一次状态查询和新采集检查 MUST 立即反映门禁解除。

#### Scenario: 最后一个阻塞条目已处理
- **WHEN** 成功重试或确认恢复处理了当前扫描中的最后一个阻塞条目
- **THEN** 同一响应和后续状态查询 MUST 显示计数为零且无需重启即可解除上一采集恢复门禁

#### Scenario: 完成数据与配置共存
- **WHEN** 阻塞条目所在目录还包含完成 CSV、时间戳 CSV、采集摘要和配置 JSON
- **THEN** 恢复动作 MUST 保持这些完成文件内容及名称不变，并在审计结果中只列出实际处理的阻塞条目标识
