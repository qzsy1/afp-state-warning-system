## Why

现有采集系统只覆盖五类逻辑接口和 17 个采集通道，未包含 ESR1001-A 四通道应变采集仪，因而应变数据不能进入统一采集、CSV、MySQL、接口诊断和发布验收链路。需要新增一类独立的 RS485 接口和四个规范应变通道，同时保持现有预测模型的输入合同不变。

## What Changes

- 增加第六类逻辑接口 `esr1001_strain`，通过独立串口上的两线制 RS485 接入 ESR1001-A，驱动协议固定为 Modbus RTU。
- 增加 `应变1`、`应变2`、`应变3`、`应变4` 四个 `με` 浮点采集通道，使新采集方案的完整通道数从 17 增加为 21。
- 按设备手册实现 `9600-8-N-1`、默认从站地址 `0x01`、FC04、起始寄存器 `0x0030`、8 个寄存器、CRC16/MODBUS 校验以及 `CH4、CH1、CH2、CH3` 返回顺序到规范通道顺序的解码。
- 将新接口纳入本机直连、远程 helper、串口发现与物理端口绑定、模拟映射、接口健康检查、诊断和重连隔离。
- 将四个应变通道加入采集宽表、逐层 CSV、完整试样 CSV、时间戳/质量证据和 MySQL `sensor_json`，并保证 CSV 与 MySQL 行数及通道值可对账。
- 保持现有模型声明的输入通道不变；只有显式声明应变输入且具备匹配元数据的模型才能消费新增通道。
- 扩展配置模板、运行时发布合同、自动化回归和真实设备现场验收，阻止未通过协议、完整性和持久化验证的构建进入正式采集。

## Capabilities

### New Capabilities

- `esr1001-strain-acquisition`: 定义 ESR1001-A 的接口、Modbus RTU 帧、四通道解码、统一采集映射、CSV/MySQL 持久化、诊断及验收行为。

### Modified Capabilities

无。

## Impact

- 采集核心：`visualization_app/acquisition.py`、接口发现/传输目录、本机 helper 与远程 helper 配置投影。
- 展示与诊断：Web/桌面采集界面、接口卡、通道表、连接检查、诊断工具及数量合同。
- 持久化与数据使用：CSV 列定义、MySQL JSON 通道、导出/回放/训练数据兼容性和模型输入校验。
- 交付与验证：`pre_sensor` 配置/发布合同、harness 矩阵、协议夹具、集成测试、打包依赖和现场验收清单。
- 硬件前提：ESR1001-A、独立 USB-RS485 转换器或原生 RS485 串口、正确的 A/B 接线与端口独占；不新增 Python 运行时依赖，驱动基于现有 `pyserial` 实现。
