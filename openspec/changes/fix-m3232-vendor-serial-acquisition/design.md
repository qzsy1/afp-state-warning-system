# Design

## Context

动机见 [proposal.md](proposal.md)。本设计依据商家文件和固定源码目录中的当前代码；协议资料不等于当前设备已通过检查。

### 现有软件的对应位置

| 当前有效代码/配置 | 观察到的行为与需解决的差异 |
| --- | --- |

| `_extract_frames` / `read_sample` | 支持裸数组和对象封装、分片与连续 JSON；尚不按商家完整帧合同限制尺寸、有限值、缓冲上限和帧完成时刻。UTF-8 忽略错误可能掩盖串口异常 |

| `real_acquisition.py` 的原始串口捕获 | 已有不发命令的 COM 原始字节、时间和 SHA256 捕获；不负责启停或协议确认，可复用存证格式 |
| 单设备检查、共享采集缓存、Helper 和预检配置 | 已有统一就绪、独立设备线程、身份字段与保存链路；M3232 缺少专属新帧证据、模式语义及完整配置往返 |

`harden-real-acquisition-pipeline` 已要求规范 `薄膜压力` 和实物协议；其任务勾选与当前上述代码表现不一致的部分，以真实代码和专项回归为准，不把该差异写成业务规则。该变更中“JSON 模拟不能证明实物”的证据边界仍有效；商家已经声明明文矩阵，因此不能因实物帧可用 JSON 解析就拒绝它。旧文档“厂家未公开帧格式”的描述须在实施时原位更新。

## Goals / Non-Goals

**Goals:**

- 复用现有接口和共享就绪架构，明确物理归属、当前协议档及有效新矩阵；无标定资料也能在正常方案中采集、显示和保存原始响应。
- 保留完整矩阵与原始字节，可从任一标量追溯到来源帧、设备绑定、协议和算法版本；设备数据率与统一 10 Hz 数据行分别计量。
- M3232 接入后，当前已正常工作的其他接口、规范通道、保存目标和模型输入合同继续成立。

**Non-Goals:**

- 不把 XCOM 包入交付、不依赖自动操作其窗口；不逆向破解受保护程序，不安装或替换系统串口驱动。
- 不编造物理压力公式、设备标识命令或校准指令；不训练新的薄膜压力模型，不把原始响应加入已有模型。
- 本方案不启动实物、不修改业务实现或正式运行目录；实施后仍按独立发布授权和设备验收条件执行。

## Decisions

### 1. 使用明确协议档并保护已有配置

独立模块 `visualization_app/m3232_serial.py` 承载协议档、流解析、驱动和诊断；`acquisition.py` 保留兼容入口并在单驱动、多接口两条路径注入同一配置。商家档命名 `m3232_uart_text_v1`，新配置默认 230400/8N1、32×32、无流控，身份未绑定时端点留空。明确保存的波特率和端点不被默认值覆盖；不在其他 COM 上发送命令或遍历波特率试写。115200 可作为用户明确选择、待实物证实的配置值，不能自动获认证。

配置包含协议档、行列、数据模式、超时、设备身份、标定摘要和算法参数。顶层单驱动配置、接口数组、桌面/Web、本机/Helper、预检 schema、序列化及就绪指纹均覆盖这些字段。协议档或帧形状修改使检测证据失效；旧 Helper 缺少能力时明确报不兼容，不能忽略参数。

### 2. 串口存在、归属确认和协议数据分层判定

复用 USB 拓扑保存 VID/PID、可用序列号、位置/容器和当前 COM。CH340 是串口桥信息，不能唯一证明 M3232；以操作员确认接线、拔插对应关系及有效矩阵加载响应完成首次绑定。没有稳定序列号时记录限制，不把接口位置当设备唯一号。

发现只枚举；用户对已选接口执行检查时，在独占串口且 XCOM 已关闭的条件下受控发送一次 `begin\n`，等待完整有效矩阵。文档未定义 ACK，因此有效矩阵是数据流启动依据。检查结束/取消/失败统一尝试一次 `end\n` 并释放端口；停止命令未证明设备已停时记录结果，不伪造 ACK。新一轮启动、重连重置解析缓冲、来源会话和滤波窗口；已确认身份迁移到新 COM 按现有合同再次确认。

复用现有阶段表达端点、绑定、协议、通道和新鲜度，并增加 M3232 诊断字段。无串口、占用、绑定未确认、无字节、只有坏帧、形状不符、等待首帧、断流、标定缺失和保存失败可区分。只有结构完整的有限矩阵推进协议和原始数据状态。矩阵语法不是唯一身份认证；不声称取得了协议未提供的型号应答。

### 3. 以完整矩阵及帧尾为边界，保留有界恢复能力

以原始字节保留诊断，合法数值帧按 ASCII 解码，非法编码可计数拒绝；不使用静默忽略错误掩盖损坏。流解析同时检查数组嵌套完成与结束换行，兼容 LF/CRLF、分片、一次多帧和数组内部格式化空白。默认只接收 32×32 裸数值数组；需要其他 M×N 时使用明确确认的设备档。对象包装及其他格式仅在显式仿真/已有兼容档开放，不从默认档自动回退以掩盖配置错误。

严格拒绝布尔值、数值字符串、NaN、Infinity、空矩阵、不规则行和尺寸漂移。零值矩阵是有效新观测，不能按非零像素比例判故障。设置默认接收缓冲上限 256 KiB、未完成帧超时 2 秒、首个有效矩阵期限 5 秒、新鲜度 2 秒；均为软件保护默认值，不是厂家性能承诺。超限丢弃不完整候选并在后续明确的顶层数组边界恢复，计数并保留有界错误样例；过期和被拒绝数据不能刷新有效帧时钟。

首帧期限与驱动 `open_timeout_seconds`、多接口打开预算及接口检查的整体期限同步；现有通用探测循环最长 1.5 秒，不能继续截断 M3232 的 5 秒首帧窗口。取消仍能立即终止等待，其他设备沿用自己的预算，不因 M3232 扩大全局阻塞时间。

文档未定义 CRC，因此质量字段明确“结构校验，未定义传输校验和”。原始抓帧 SHA256 仅用于保存完整性。若实物出现文档外引号、双重编码、提示语或帧格式，先记录真实字节及摘要，按有依据的显式协议档扩展，不能对任意字符串递归解码后认定成功。

### 4. 有效新帧拥有来源时间，统一采样只消费真实观测

采用支持批量新帧及来源记录的驱动接口（复用现有 `read_samples` 消费方式）。每个有效接收帧记录主机单调时间、墙钟、会话内序号、矩阵形状、原始字节偏移和质量；没有设备时钟/序号时明确为空，主机序号不是设备序号。内容相同的连续零帧仍是多个真实观测；空读、半帧、坏帧均不产生新观测。

完整帧时间与最后字节时间分别计量。统一帧装配可在新鲜窗口内沿用最新值，但质量为 `held` 且保留来源时间；失效后为 stale/missing，绝不每次轮询刷新来源时间。首帧期限和持续断流进入有界恢复，不能因循环返回 None 永久卡住。停止不阻塞其他设备，重连只针对原绑定，不能选择邻近 COM。

230400/8N1 的理论净字节上限约为 23040 B/s；32×32 紧凑整数全零帧含 LF 为 2114 B，忽略其他开销时已只有约 10.9 帧/秒的上限，值位数增加会更慢。验收记录实际字节率、有效矩阵率、统一行率和 held 比例，不承诺每个 10 Hz 数据行均有新矩阵，也不因 200 次/秒轮询宣称设备有 200 Hz。

### 5. 原始采集与 N 力值分别建模

接口配置 `data_mode=raw_matrix|calibrated_force`，两者共用 `m3232_pressure`，不增加设备数量：

| 模式 | 正常采集通道及语义 | 标定条件 |
| --- | --- | --- |
| `raw_matrix` | 新增 `薄膜压力原始响应`，单位 `raw`，定义为完整矩阵有限像素的直接合计；原始矩阵逐帧侧车保存 | 不要求物理量系数，明确显示“原始响应，未标定” |
| `calibrated_force` | 保留既有 `薄膜压力`，单位 N；原始矩阵及换算来源仍可追溯 | 有效的设备绑定、矩阵尺寸、零点、换算公式/系数、适用范围、校准证据与版本摘要 |

默认新接口使用原始模式。缺少标定不得强制全接口离线：原始模式可以与其他设备正常联采；用户若选择 N 通道但标定缺失，则阻断该物理量请求并提示切换原始模式或提供标定，不静默替换字段。旧采集文件、历史 N 列和历史模拟数据按原 schema 回放，不批量重写、重命名或声称已补标定；新会话保存模式与单位。

既有 >5、去最高约 10%、9 点中值不是本协议定义。原始响应不隐式套用该算法；可选诊断阈值及滤波需显式配置和版本化，保存原始与派生数据，不修改原始矩阵。非零像素比例、阈值像素数和原始峰值为诊断元数据；没有像素面积不输出 mm²，没有标定不称 N/kPa。N 转换支持载入有依据的标定档，不预置通用线性系数或默认零点校准命令。

当前模型未声明上述新增原始通道或薄膜压力输入时，两模式均仅采集保存。按模式生成预期通道集合及 metadata，贯通 schema、通道选择、CSV/MySQL、Helper 与就绪，不能通过空填 N 列冒充采集成功。PLC `压力` 的来源、单位及路由保持独立。

### 6. 保存原始证据并落实专项检查矩阵

采集会话在 `D:\AFP_Capture` 或用户明确选择的可写 D 盘目录落地，启动前检查目录可写。复用原始抓帧/质量存证结构，扩展为带收发方向和命令字节的受控会话记录；被动抓帧仍保持不发命令。完整矩阵、来源记录和标量通过会话 ID、来源序号、偏移及摘要关联；矩阵侧车按大小轮转、有界队列，写失败显式失败或降级，不能无声丢弃并宣布保存成功。MySQL 保存启用的标量模式及来源关联，完整矩阵放侧车，避免把 1024 像素逐一加入既有模型列。

| 检查层 | 执行内容 | 通过依据 |
| --- | --- | --- |
| 协议夹具 | 文档零帧、加载变化的脱敏实物帧；分片/连续帧/内部换行/CRLF/坏字符/尺寸/超限/超时/零帧 | 接收边界、1024 值、拒绝计数、新帧与恢复行为可重复；合成与实物来源分开 |
| 路由与就绪 | 单驱动到多接口、原始/N 模式、PLC 同采、空读及陈旧状态、配置变更 | 预期通道唯一正确，坏数据和旧检测不能判成功，标定缺失有明确模式边界 |
| 配置与交付合同 | 桌面/Web、本机/Helper、预检、指纹、模块清单、无 XCOM 依赖 | 参数往返一致，旧 Helper 拒绝不支持能力，正式页显示实际运行修订 |
| 单设备实物 | XCOM 与 AFP 顺序独占相同端口/参数，LF 启停、全零、按压及卸载，AFP 连续至少 600 秒 | 身份明确，持续有效矩阵、实际速率及来源时间可查，无未解释丢失；启动、停止、再启动正常 |
| 联合与故障 | 冻结当前正常通道及保存基线，加入 M3232 至少 600 秒，拔插、占用、坏帧、断流 | 全部基线通道及指标保留，M3232 故障隔离，重连确认后取得新帧；所有启用保存目标对账 |
| 标定与加载 | 卸载基线、已知参考载荷、不同位置及至少三次重复加载/卸载 | 原始模式证明数据响应与坐标关系；N 模式依据已记录计量范围和允差单独判定，无允差不能判精度通过 |
| 正式发布 | 获发布授权后按单运行目录流程装配更新、从固定目录启动上述软件复验 | 源修订、清单/文件摘要、实际进程路径、运行修订和页面资源一致；不能用源码/临时程序代替 |

## Risks / Trade-offs

- [通用矩阵协议不能证明型号] → 物理绑定与人工接线确认加协议及按压响应，明确身份依据，不伪造唯一设备查询。
- [不同批次固件串口参数可能不同] → 新档按本 PDF，已有显式参数保留；现场记录实际生效参数，不全局强制迁移。
- [仅结构校验无法检出一切传输误码] → 保留原始字节、矩阵与拒绝统计，报告无 CRC 限制，不宣称链路有未定义的校验能力。
- [矩阵体积与输出带宽限制] → 来源级持久化、轮转、有界缓冲和队列背压；区分矩阵率与统一采样率，记录任何丢弃及原因。
- [原始/N 模式影响通道目录] → 按会话持久化数据模式、单位和 schema，端到端测试；旧文件只读兼容，已正常通道和模型映射不得受影响。
- [XCOM 与 AFP 争用串口] → 对照使用顺序独占；占用报告为端口问题，不重发开始命令或误判设备故障。

## Migration Plan

1. 在本机任务分支实现协议和模式合同，先通过协议夹具、配置往返、采集路由及各正常设备回归；原位更新既有 M3232 集成文档，不另建过程报告。
2. 使用明确选定实物完成 XCOM 对照，冻结该设备实际身份、波特率、帧形状和响应证据；不修改用户已有其他接口配置。实物差异通过有依据的配置档处理。
3. 验证单设备及全基线联采、全部启用保存目标和故障恢复。无标定时只判原始采集，物理量精度保持待验收。
4. 获发布授权后复用既有单运行目录流程：构建中间产物只在 `D:\AFP_Runtime\.afp-staging`，发布至 `D:\AFP_Runtime\AFP_Integrated_System_Modular` 并从该处启动复验；完成或失败后清理 staging，不保留第二套完整程序。
5. 更新失败走现有单目录回滚机制恢复已授权版本并核对运行身份；不得创建额外大体积备份。未授权发布时正式目录不更新，软件交付与实物验收各自报告。

## Open Questions

- 目标实物的 VID/PID、序列号是否稳定、实际工作波特率、是否裸矩阵/帧内换行和持续输出频率：由首次定向对照填写设备档；不影响默认档、身份确认和拒绝策略。
- 像素含义、坐标方向、物理面积、零点方式、力值公式/有效范围和可接受精度：由商家资料或有依据的标定档提供；缺少时原始模式照常工作，N/精度验收保持未通过。
