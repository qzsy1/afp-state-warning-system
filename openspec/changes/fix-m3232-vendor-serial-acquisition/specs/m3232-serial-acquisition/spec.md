# Spec Delta

## Purpose

定义 M3232 薄膜压力设备按商家串口协议完成接口归属确认、完整矩阵接收、原始响应或已标定力值采集及持久化的行为。通过可验证的新帧、来源质量和正式软件验收，避免串口可见、初始零值或像素合计被误认为设备识别及物理压力测量成功。

## ADDED Requirements

### Requirement: 商家协议档和用户配置一致生效

系统 MUST 提供明确的 M3232 明文矩阵协议档，新配置默认 230400 波特率、8N1、32×32 及 LF 帧尾。系统 MUST 保留用户显式保存的端点和串口参数，展示实际生效参数；不得按固定 COM 认定设备或自动遍历其他端口发送命令。

#### Scenario: 新增与恢复已有接口

- **WHEN** 用户新增商家协议接口或恢复已有显式 115200 配置
- **THEN** 新接口 MUST 使用 230400 默认值并要求绑定；已有配置 MUST 保持其值且根据实际有效帧判定通信，不能仅因配置存在宣称通过

### Requirement: 端点发现和设备归属分别确认

系统 SHALL 区分串口存在、物理绑定、协议有效及采集可用。通用串口桥型号、VID/PID、COM 号和开口成功 MUST NOT 单独构成 M3232 识别成功；首次绑定 MUST 记录接线/拔插对应确认及有效矩阵证据，无法唯一识别时明确限制。

#### Scenario: 发现 CH340 或蓝牙 COM

- **WHEN** 候选只有通用串口信息，尚未确认其连接 M3232
- **THEN** 系统 MUST 保持未绑定，不自动认定或向其发送采集命令

#### Scenario: 已绑定设备端点变化

- **WHEN** 重新连接后 COM 号变化或设备身份不再匹配
- **THEN** 系统 MUST 使旧检查失效并要求确认当前归属，不能选取其他可用 COM 顶替

### Requirement: 启停采用文档命令和独占有界生命周期

针对用户明确选择的已绑定接口，系统 MUST 独占串口并以 ASCII `begin` 加单个 LF 启动、`end` 加单个 LF 停止。启动 MUST 等待有效首帧；检查结束、取消、失败和正常停止 MUST 有界释放端口。文档未定义 ACK，系统 MUST NOT 等待虚构应答或自动发送未知校准/配置命令。

#### Scenario: XCOM 占用目标串口

- **WHEN** 用户检查的串口被商家工具占用
- **THEN** 系统 MUST 报告端口占用，不切换端口、不将其判为已采集成功

#### Scenario: 检查结束及再次启动

- **WHEN** 一次检查完成或取消，随后用户重新启动采集
- **THEN** 检查 MUST 释放串口；新会话 MUST 重新取得有效矩阵，旧缓存和旧滤波值不能满足首帧条件

### Requirement: 完整且数值有效的矩阵才能成为观测

系统 MUST 支持流式分片、多帧、内部格式化换行及 LF/CRLF 帧尾，按已确认尺寸接受完整裸数值矩阵。系统 MUST 拒绝不规则形状、空矩阵、布尔值、数值字符串及非有限值，并对缓冲大小和不完整帧等待设置上限。坏帧、无关文字及半帧 MUST NOT 刷新有效帧时间。

#### Scenario: 分片与多帧连续到达

- **WHEN** 两个 32×32 数值矩阵在任意字节处分片，或一次读取收到多个带帧尾的完整矩阵
- **THEN** 系统 MUST 按来源顺序各产生一次完整观测，不在行内换行处分割成错误帧，不重复消费

#### Scenario: 全零矩阵与无数据

- **WHEN** 接收完整全零矩阵，或仅收到无关文字、半帧、空读
- **THEN** 前者 MUST 成为有效零响应观测；后者 MUST 保持等待或无有效数据，不能产生初值零观测

#### Scenario: 损坏流恢复

- **WHEN** 输入形状错误、NaN/Infinity、非法字符或超限不完整帧，随后到达完整合法帧
- **THEN** 系统 MUST 记录拒绝原因并在有界资源内恢复，只有后续合法完整帧能恢复数据可用状态

### Requirement: 协议校验与证据等级准确表达

系统 MUST 如实声明本协议仅提供结构校验，不能补造 CRC、型号应答、设备序号或设备时间戳。语法兼容的真实矩阵和模拟矩阵 MUST 按来源、物理绑定和实物证据区分；合成帧及文件摘要 MUST NOT 替代实物验收或线上协议校验。

#### Scenario: JSON 矩阵来源不同

- **WHEN** 同样形状的矩阵分别来自合成夹具和明确绑定的真实串口
- **THEN** 合成来源 MUST 保持仿真证据；真实来源 MUST 根据实际协议和现场证据判定，不因 JSON 语法被一概拒绝或一概判为实物通过

### Requirement: 新鲜度基于完整来源帧

每个有效新矩阵 MUST 记录主机接收时间、来源会话及主机序号。无新帧时不得刷新来源时间；统一采样沿用旧值 MUST 标为 held，超过新鲜度后 MUST 标 stale/missing。系统 MUST 分别报告字节率、矩阵率及统一数据行率，首帧超时或断流 MUST 产生明确状态和有界恢复。

#### Scenario: 空读和相同内容新帧

- **WHEN** 多次轮询没有新字节，或设备连续发送内容相同的零矩阵
- **THEN** 空读 MUST 不生成新观测；每个重新接收的完整零矩阵 MUST 各有新的来源序号和接收时间

#### Scenario: 设备低于统一采样频率或断流

- **WHEN** 矩阵到达率低于统一行率，随后数据流停止超过新鲜度
- **THEN** 系统 MUST 区分新值、沿用和陈旧；不能以轮询频率、行数或重复旧值声称矩阵连续新到达

### Requirement: 未标定原始响应可以独立正常采集

系统 MUST 提供原始矩阵模式，在正常采集方案中输出 `薄膜压力原始响应`，单位 raw，定义为完整矩阵有限像素的直接合计，并保存完整矩阵。缺少物理量标定不得阻断该模式与其他设备联合采集；系统 MUST 明确显示未标定，不能将原始响应、峰值或像素个数标成 N、kPa 或物理面积。

#### Scenario: 没有厂家换算系数

- **WHEN** 已绑定设备能持续输出有效矩阵，但没有有效力值标定档
- **THEN** 原始模式 MUST 能完成检查、显示和保存，N 力值状态 MUST 保持未标定，不能用空填或像素合计声称力值采集成功

### Requirement: 标定力值和算法可追溯

以 N 输出的规范通道 MUST 为 `薄膜压力`，且必须具有与设备、尺寸匹配的有效标定档、换算依据和摘要。原始数据 MUST 保留；任何阈值、裁剪、零点和滤波 SHALL 明确版本与参数，不得将未确认算法作为厂商规则。加载精度 SHALL 依据记录的范围和允差单独验收。

#### Scenario: 请求 N 但标定不匹配

- **WHEN** 用户选择力值模式但标定缺失、过期或绑定/尺寸不匹配
- **THEN** 系统 MUST 阻断该力值请求，明确原因并提供原始模式选择，不能静默换单位或使用默认系数

#### Scenario: 已知载荷验证

- **WHEN** 有效标定档在卸载、已知参考载荷及至少三次重复加载/卸载中接受验证
- **THEN** 系统 MUST 保存换算来源和误差，按已记录允差判定；没有计量依据或允差 MUST NOT 标为精度通过

### Requirement: 通道映射和已有采集能力保持一致

系统 MUST 按原始/力值模式声明预期通道并贯通单接口、多接口、API、页面、CSV、MySQL和Helper。PLC `压力` MUST 与 M3232 通道独立，不能被覆盖、过滤或混用。现有已正常接口及其数据和保存能力 MUST 保留；未声明 M3232 输入的模型不得隐式使用其原始或力值通道。

#### Scenario: PLC 与 M3232 联合采集

- **WHEN** 同时启用 PLC 压力及任一 M3232 数据模式
- **THEN** 每个选定通道 MUST 保持正确来源、单位及保存列，M3232 数据不得因错误名称被丢弃，PLC 压力不得被 M3232 替换

#### Scenario: 历史文件与当前模型

- **WHEN** 回放历史采集文件或使用未声明薄膜压力输入的模型
- **THEN** 系统 MUST 按原 schema 读取历史文件并保留模型输入合同，不重写历史单位、不把原始响应伪造成旧 N 列或模型输入

### Requirement: 配置和就绪证据跨入口一致

桌面、Web、本机和Helper MUST 一致传递协议档、有效串口参数、尺寸、数据模式、身份和标定摘要。任何影响数据语义或绑定的配置变化 MUST 使旧就绪证据失效；不支持该合同的Helper MUST 明确拒绝，不能丢弃字段或回退协议并宣称成功。

#### Scenario: 修改尺寸或标定后启动

- **WHEN** 检查通过后修改矩阵尺寸、模式、标定档或绑定，再从另一入口启动
- **THEN** 系统 MUST 要求与当前配置一致的新检查，页面与实际驱动参数 MUST 一致

### Requirement: 原始矩阵与保存结果可对账

系统 MUST 在存在且可写的采集目录保存完整矩阵及来源关联，默认 `D:\AFP_Capture`。启用的 CSV/MySQL 标量和原始矩阵侧车 MUST 通过会话和来源记录关联，包含参数、单位、时间、算法及摘要。缓冲、轮转和写失败 MUST 可见；不得无声丢弃并报告保存成功。

#### Scenario: 对账和写入失败

- **WHEN** 用户停止一次采集，或任一启用保存目标出现故障
- **THEN** 系统 MUST 提供接收、解析、拒绝、保存矩阵数及统一行数的对应关系，并解释 held/丢弃；失败目标 MUST 显式显示失败或降级，保留可追溯证据

### Requirement: 正式软件与实物分别完成可重复验收

识别和正常采集验收 MUST 覆盖实际绑定、商家工具顺序对照、至少 600 秒单设备和全基线正常接口联合采集、加载/卸载、断流/占用/拔插恢复及所有启用保存目标对账。获发布授权的版本 MUST 更新固定运行目录并从该目录复验；软件交付、原始采集和计量精度 MUST 分别报告，未验证不得标为通过。

#### Scenario: 原始采集通过但精度或发布条件未满足

- **WHEN** 原始模式实物测试通过，但缺少标定依据或尚未获得发布授权
- **THEN** 系统 MUST 分别报告原始采集结果、精度待验收及正式目录未更新，不能宣称全部设备验收或正式软件交付完成

#### Scenario: 加入 M3232 后联合验收

- **WHEN** 正式授权版本从 `D:\AFP_Runtime\AFP_Integrated_System_Modular` 启动并加入 M3232 采集
- **THEN** 实际进程路径、文件摘要、运行修订及页面资源 MUST 一致，600 秒联合采集 MUST 保留全部基线正常通道及保存能力，并能隔离 M3232 故障
