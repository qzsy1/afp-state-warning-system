功能基线：`delivery\AFP_Integrated_System_M3232_v2.0.6\AFP_Integrated_System_Modular.exe`

## 1. 目标与边界

在不改动 v2.0.6 可执行程序及现有采集、预测、训练和预警链路的前提下，新增一个可独立启动、独立测试的接口状态监控 Demo。Demo 展示确定性监控程序如何发现接口或传感器异常，并在 API Key 与模型名称均已填写时，触发本地 LangChain 诊断流程模拟。

本 Demo 不连接外部模型服务，不发送 API Key，不读取真实硬件，也不把模拟结论表述为真实设备诊断。它用于确认前端布局、事件结构、Agent 工具边界和完整诊断流程。

不在本次范围内：

- 修改或重新打包 v2.0.6；
- 接管真实采集线程；
- 自动重启设备、写 PLC、修改机器人参数或创建维修工单；
- 使用模拟结果证明真实硬件、故障定位准确率或现场可靠性；
- 将新增的“薄膜压力”通道直接送入现有 16 输入模型。该操作需要重新训练和独立验证。

## 2. 已确认的系统基线

当前磁盘中确认的最新交付为 v2.0.6，版本清单功能标记为 `separate-process-and-film-pressure-channels`。Demo 必须保留以下五个默认接口：

| 接口 | 驱动/端点 | 数据通道 | 说明 |
|---|---|---|---|
| 八通道热电偶 | SMRF USB HID / `SMRFCT08B` | `温度1`～`温度8` | 八个独立温度通道 |
| 松下 PLC | Modbus TCP / `192.168.125.5:502` | `温度`、`压力`、`张力` | `压力`是 PLC 过程压力 |
| BSV UVC 热像仪 | UVC / WinUSB | `ROI平均温度` | 温度矩阵 ROI 均值 |
| ABB 机器人 | RWS / `192.168.125.1` | `ABB_X`、`ABB_Y`、`ABB_Z`、`线速度` | 位姿和派生线速度 |
| M3232 薄膜压力 | 专用串口 / `COM8`、115200 | `薄膜压力` | 第五个独立接口和独立通道 |

`压力`与`薄膜压力`不得合并、互相接管或共用展示标签。

## 3. 方案选择

采用“源码工程内新增独立 Demo 子目录”的方案。建议目录为：

```text
F:\AFP_Integrated_Modular_v2\interface_monitor_demo\
```

选择理由：

- v2.0.6 交付包保持只读，便于核对文件哈希和回退；
- Demo 有独立端口、依赖、页面和测试，不干扰现有模块加载器；
- 后续接入真实 `/api/acquisition/status` 时，只需替换事件适配器；
- 可先验证交互和数据契约，再决定是否集成到主界面。

不采用直接修改现有界面的方案，因为这会立即扩大回归范围；不采用纯静态页面，因为它不能证明 LangChain 编排代码实际执行。

## 4. 架构与组件

```text
前端故障场景按钮
        |
        v
本地模拟数据源 -> 确定性状态监控器 -> 标准故障事件
                                      |
                         API Key/模型名门控
                                      |
                                      v
                         LangChain 本地编排流程
                         | 读取接口配置
                         | 检查最近观测
                         | 查询诊断规则
                         | 生成结构化报告
                                      |
                                      v
                         前端诊断时间线与结论
```

### 4.1 模拟数据源

为五个接口维护内存状态，不读取实际串口、USB、PLC 或 RWS。用户可注入以下场景：

- 正常；
- 接口未发现或无法打开；
- 超时/持续无数据；
- 数据过期；
- 非数值或不可解析数据；
- 部分通道缺失。

M3232 另提供串口端点不可用、矩阵帧不可解析和薄膜压力值无效场景。所有场景都标记为模拟。

### 4.2 确定性状态监控器

监控器负责异常发现，Agent 不轮询传感器。监控器将模拟观测转换为统一事件：

```json
{
  "event_id": "evt-...",
  "occurred_at": "ISO-8601",
  "interface_id": "m3232_pressure",
  "sensor_name": "M3232薄膜压力",
  "channels": ["薄膜压力"],
  "state": "invalid_data",
  "severity": "warning",
  "summary": "矩阵帧无法解析",
  "evidence": {
    "endpoint": "COM8",
    "baudrate": 115200,
    "received_samples": 0,
    "invalid_samples": 3,
    "last_sample_age_ms": 420
  },
  "simulated": true
}
```

事件字段采用白名单，避免把密码、API Key 或大段原始数据带入诊断上下文。

### 4.3 LangChain 本地诊断流程

使用 `langchain-core` 的 Tool 与 Runnable 组合实现本地、确定性的 Agent 流程模拟。采用 `@tool` 定义工具，并以 `RunnableLambda`/Runnable sequence 编排。该流程展示生产 Agent 的工具边界和调用轨迹，但不冒充会自主推理的外部 LLM Agent。

工具固定为：

1. `get_interface_config`：读取接口类型、端点、驱动和通道；
2. `inspect_latest_observation`：读取计数、时延、缺失通道和解析状态；
3. `lookup_fault_rule`：按接口类型与状态匹配本地规则；
4. `compose_diagnostic_report`：生成结构化诊断结果和建议。

输出包括：问题接口、问题传感器、问题通道、故障类型、证据、可能原因、建议动作、置信等级、流程步骤和 `simulated=true`。置信等级只表示规则匹配完整程度，不表示真实故障概率。

### 4.4 API Key 与模型名称门控

前端提供密码类型的 API Key 输入框和模型名称输入框，位置与接口状态区相邻。

- 任一字段为空：Agent 按钮禁用，后端流程不执行；
- 两者均填写且存在异常事件：允许启动本地模拟；
- API Key 只在浏览器中检查非空，实际值绝不进入请求；
- 请求只发送 `api_key_present: true`、模型名称和事件编号；
- 后端若收到 `api_key`、`token` 或同类秘密字段，拒绝请求；
- 模型名称只作为界面展示和模拟配置，不加载、不联网；
- 页面刷新后不保留 API Key。

## 5. 前端设计

页面分为四个区域：

1. **接口状态总览**：五张接口卡，显示接口、端点、通道、状态、采样计数和最近时延；PLC 压力与 M3232 薄膜压力分别显示。
2. **Agent 配置**：API Key、模型名称、本地模拟标识和启用状态。
3. **故障场景控制**：选择接口和异常类型，支持注入、恢复单接口及全部恢复。
4. **诊断流程**：按顺序显示触发事件、四个工具调用、证据摘要和最终建议。

页面必须直接呈现一张始终可见的“LangChain 诊断思路”流程图，而不是只在 README 中解释。流程图包含“确定性监控发现异常 → 形成标准事件 → API Key/模型门控 → LangChain 工具编排 → 结构化诊断”五个节点；执行诊断时，各节点和四个工具调用按实际顺序逐步点亮。

状态颜色只辅助识别，文本标签必须同时显示，避免仅依赖颜色。移动窗口下卡片自动换行。所有诊断结果持续显示“本地模拟，不代表真实硬件诊断”。

## 6. 本地 API

Demo 使用独立的本地 HTTP 服务和独立端口，建议默认 `127.0.0.1:8770`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/bootstrap` | 返回接口目录、场景目录和当前状态 |
| GET | `/api/status` | 返回接口状态和最近事件 |
| POST | `/api/scenario` | 注入或恢复模拟场景 |
| POST | `/api/diagnose` | 在门控通过后运行 LangChain 本地流程 |
| POST | `/api/reset` | 恢复全部接口并清空诊断轨迹 |

未知接口、未知场景、无异常事件或门控未通过均返回明确的 4xx JSON 错误；内部异常返回已脱敏的 5xx 错误，不返回堆栈和本地秘密。

## 8. 测试与验收

### 8.1 自动化测试

- 五接口目录和通道映射正确；
- `压力`与`薄膜压力`始终为两个独立通道；
- 每种模拟观测生成预期状态和标准事件；
- 正常状态不触发诊断；
- API Key 或模型名为空时不运行流程；
- 请求体不包含 API Key 原文，后端拒绝秘密字段；
- LangChain 四个工具按预期执行并产生可展示轨迹；
- 输出结构完整且始终包含模拟标识；
- API 状态码和错误消息符合契约；
- JavaScript 通过语法检查，关键 DOM 元素与事件绑定存在。

### 8.2 手工验收

1. 独立启动 Demo，打开本地页面；
2. 空配置时确认 Agent 禁用；
3. 填写任意非空测试 Key 和模型名称，确认不产生网络请求；
4. 分别向五个接口注入异常并查看状态变化；
5. 对 M3232 注入帧解析异常，确认结果指向“薄膜压力”而非 PLC“压力”；
6. 查看完整工具调用时间线和结构化建议；
7. 恢复接口并确认异常和诊断状态清除；
8. 核对 v2.0.6 EXE 的 SHA-256 仍为 `FE42C67E5B38710BE182B8E5898341500EE7CAF2A668CFB619429C7E491DEC0C`；
9. 运行现有相关接口测试，确认未产生回归。
10. 使用浏览器实际渲染页面并保存截图，确认五张接口卡、Agent 配置区、LangChain 流程图、故障控制区和诊断结果在同一页面清晰可见。
