# AFP 集成系统公网访问、模拟访客与永久授权设计

日期：2026-09-14  
目标分支：`feature/original-ui-langchain-agent`

## 1. 目标与已确认边界

在现有局域网版和原前端基础上增加一个 HTTPS 公网网址。任何访问者点击网址后直接进入“访客模拟模式”；输入由本机 EXE 设置的密码后，当前浏览器原地解锁真实采集、完整设备控制和服务器保存的硅基流动 API Key 使用权。

已确认的产品边界：

- 公网访客无需登录即可打开完整前端，并使用模拟采集、预测、预警、本地规则诊断、报告和模拟结果保存功能。
- 公网访客可以读取 SMRF 热电偶、PLC、BSV UVC、ABB、M3232 薄膜压力传感器及其串口、USB、网口的真实在线状态和错误状态，但不能读取真实生产测量值、启动真实采集或修改真实接口配置。
- 密码登录后获得与本机软件一致的真实采集和控制权限，并可以使用本机保存的硅基流动 API Key；任何浏览器都不能读取、复制或导出 API Key 明文。
- 登录会话没有时间有效期。只有手动退出、本机撤销授权、修改密码或重置安全配置时才失效。
- 继续只维护当前 Git 仓库、现有交付目录和同名 EXE；不复制工程，不为每次修改创建版本文件夹或重复 EXE。

## 2. 推荐架构

采用“单域名渐进解锁”架构：

```text
公网浏览器
  -> Cloudflare HTTPS/WAF/限流
  -> Cloudflare Tunnel
  -> 采集电脑 http://127.0.0.1:8770
  -> 公网 Web 服务
       -> 访客模拟会话
       -> 脱敏后的真实接口状态
       -> 密码认证与永久会话
       -> 已授权真实采集控制
       -> 后端代调用硅基流动模型

本机 EXE
  -> 仅本机安全设置界面
       -> 设置/修改密码
       -> 加密保存 API Key 与模型名
       -> 查看和撤销已授权浏览器
       -> 启停/查看 Tunnel
       -> 强制收回真实采集控制权
```

Cloudflare Tunnel 只负责建立公网 HTTPS 入口和将流量转发到本机服务，不承担应用业务权限。软件后端是模拟/真实模式和 API Key 权限的最终判定者。

不采用整站 Cloudflare Access 登录，因为它会阻止访客直接进入模拟页面。Cloudflare 可对登录和受保护 API 路径增加限流或额外策略，但不得用它替代软件后端权限校验。

## 3. 权限矩阵

| 功能 | 未登录访客 | 密码登录后 |
|---|---:|---:|
| 打开网页、查看图表和说明 | 允许 | 允许 |
| 独立模拟采集、预测和三级预警 | 允许 | 允许 |
| 保存、查看和下载本会话模拟结果 | 允许 | 允许 |
| 本地规则接口诊断 | 允许 | 允许 |
| 查看真实设备在线/离线、最后响应和错误类型 | 允许 | 允许 |
| 查看完整 COM、USB 序列号、设备 IP 等标识 | 脱敏 | 允许 |
| 查看真实温度、压力、速度等生产数据 | 禁止 | 允许 |
| 自动检查真实接口 | 仅查看最近结果 | 允许重新检查 |
| 启动、停止真实采集 | 禁止 | 允许 |
| 修改传感器、协议和接口映射 | 禁止 | 允许 |
| 训练或导入真实数据 | 禁止 | 允许 |
| 使用硅基流动 API Key 调用模型 | 禁止 | 允许 |

所有权限必须在服务端执行。前端隐藏或禁用按钮只用于提示，不能作为安全边界。任何未授权真实操作直接返回 `403 real_access_required`，不进入硬件驱动、数据库或模型调用流程。

## 4. 访客模拟会话与文件保存

现有真实采集管理器继续作为全局唯一硬件会话。公网访客的模拟采集不得复用这个全局会话，否则多个浏览器会互相覆盖数据或影响真实采集。

每个浏览器获得独立模拟会话编号，模拟采集、曲线、诊断结果和保存目录相互隔离。模拟数据来源只允许：

- 软件内置演示数据；
- 软件管理员在本机批准的模拟 CSV/文件夹；
- 管理员预先配置的只读 MySQL 数据源。

访客不能打开采集电脑上的系统文件选择框、输入任意 Windows 路径或提交任意 MySQL 凭据/SQL。模拟结果由后端保存到：

```text
captured_data/public_simulation/<session-id>/<date>/<specimen>/
```

前端提供结果下载。软件设置中提供单会话磁盘配额、总目录配额和清理按钮；达到配额或磁盘空间不足时停止继续写入并给出明确提示，不能静默丢失数据。

## 5. 真实接口状态公开规则

访客状态接口从真实硬件管理器读取最近一次状态快照，不直接触发端口占用、摄像头打开、PLC/ABB 写操作或长时间探测。公开内容包括：

- 传感器和接口类型；
- 已发现/未发现、在线/离线、可读/不可读；
- 最后成功响应时间；
- 超时、驱动缺失、权限不足、协议不匹配等错误分类；
- 当前是否正在真实采集。

未登录时隐藏完整 IP、端口映射、USB 序列号、数据库地址、文件路径和驱动绝对路径；登录后复用原界面显示完整信息。真实接口的自动检查仍由本机启动或授权用户手动触发，匿名访客只能读取最近结果，避免公网访问反复打开硬件。

## 6. 密码、永久会话与撤销

新增仅本机可用的“公网访问与授权”设置。该设置不能通过 Tunnel 转发，采用独立的回环管理入口或桌面侧设置窗口；公网 Web 服务不能修改密码和 API Key。

密码使用带随机盐的强密码哈希保存，不保存明文。API Key 使用 Windows 当前用户/本机加密机制保存，不写入 HTML、JavaScript、普通配置、日志、诊断结果或 Git。

登录成功后：

1. 后端生成高强度随机会话令牌；
2. 浏览器仅保存 `Secure`、`HttpOnly`、`SameSite` 持久 Cookie；
3. 服务端只保存令牌哈希、浏览器标识、创建时间、最后使用时间和撤销状态；
4. 令牌不设置按时间过期；
5. 手动退出、单设备撤销、撤销全部设备、修改密码或安全配置重置时立即失效；
6. 本机界面列出已授权浏览器，允许逐个撤销。

“登录永久有效”不等于“永久占有真实控制权”。登录身份一直有效，但真实采集控制采用独立的单控制者租约；连接中断时释放控制租约，用户恢复连接后无需重新输入密码即可再次申请控制。

密码登录接口必须具备应用内限流、连续失败退避和审计记录。Cloudflare 限流是额外保护，不作为唯一防线。

## 7. 真实采集并发和断线行为

- 任意数量的浏览器可以查看状态和实时结果。
- 同一时间只允许一个授权会话修改接口配置或控制真实采集。
- 第二个授权会话申请控制时显示当前控制者和“只读查看”状态，不重复打开硬件。
- 本机 EXE 始终具有最高优先级，可以收回远程控制权和停止采集。
- 浏览器刷新或公网断线不自动停止采集；采集继续由本机服务运行，重新连接后从服务端恢复状态。
- Tunnel 中断不影响本机 EXE、局域网访问、硬件采集和本地保存。
- 控制命令带请求编号并实现幂等处理，网络重试不能重复执行启动或停止。

## 8. 硅基流动与 LangChain 调用

未登录访客只运行现有本地规则诊断，不消耗 API Key。授权用户点击模型诊断后执行：

```text
当前异常事件
  -> Agent 选择只读诊断工具
  -> 查询接口配置、最近状态、错误日志和采集摘要
  -> 脱敏主机路径、凭据和不必要标识
  -> 后端解密 API Key
  -> 调用配置的硅基流动模型
  -> 校验结构化诊断
  -> 合并本地规则和模型建议
  -> 返回结果，不返回 API Key
```

模型访问限制为单会话受控并发和可配置频率；审计日志记录会话、时间、模型名、成功/失败、耗时和估算用量，不记录 API Key。模型连接失败、超时或结构化结果不完整时保留本地规则结果，不覆盖硬件检查，也不阻塞采集。

由于旧 API Key 曾在对话中以明文出现，公网部署前必须在硅基流动后台撤销旧 Key，并在本机设置界面录入新 Key。

## 9. Cloudflare Tunnel 与域名配置

部署前提是用户提供一个已接入 Cloudflare 的有效域名或子域名。建议使用固定子域名，例如 `afp.<用户域名>`。

实施步骤：

1. 在 Cloudflare 创建固定命名 Tunnel，不使用临时 Quick Tunnel。
2. 在采集电脑安装 `cloudflared` 并注册为 Windows 自动启动服务。
3. 将公网主机名路由到 `http://127.0.0.1:8770`。
4. Tunnel 规则最后增加不匹配请求返回 `404` 的兜底项。
5. 软件 Host 白名单加入配置的公网域名，同时保留 `127.0.0.1` 和有效局域网地址。
6. Cloudflare 强制 HTTPS；`/api/*`、HTML 和实时状态响应禁止缓存。
7. 对 `/api/auth/login`、模型诊断、模拟启动/保存和大文件下载设置限流；应用内部同时限流。
8. Windows 防火墙不开放公网入站 8770；Tunnel 只通过出站连接访问 Cloudflare。
9. EXE 界面显示 Tunnel 运行状态、公网网址、最近连接时间和复制网址按钮。
10. Tunnel 凭据存放在 Cloudflare 服务配置中，不进入 Git 或交付校验清单的公开内容。

Cloudflare 官方说明表明 Tunnel 由 `cloudflared` 建立出站连接，可把本机 HTTP 服务发布为公共主机名，无需公网可路由 IP 或路由器端口映射：

- <https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/>
- <https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/>
- <https://developers.cloudflare.com/waf/rate-limiting-rules/>

## 10. API 和组件边界

实施时新增独立组件，避免继续扩大现有 `app.py`：

- `auth_service`：密码验证、令牌签发和撤销。
- `session_store`：持久授权会话和安全版本管理。
- `permission_policy`：统一判断访客、授权和本机管理权限。
- `guest_simulation_manager`：隔离访客模拟任务、结果和配额。
- `public_device_status`：生成真实硬件的脱敏状态快照。
- `secure_secret_store`：保存密码哈希、API Key 和模型配置。
- `tunnel_status`：读取 Tunnel 状态并提供本机显示。
- `audit_log`：记录登录、撤销、控制、模型调用和安全拒绝事件。

建议的新增接口：

- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/session`
- `GET /api/public/device-status`
- `POST /api/simulation/start`
- `POST /api/simulation/stop`
- `GET /api/simulation/status`
- `GET /api/simulation/download`
- `POST /api/real/control/acquire`
- 原真实采集、配置、诊断和模型接口继续保留路径，但统一经过权限策略。

本机管理接口使用独立回环入口，不暴露在 Tunnel 的 8770 公网路由中。

## 11. 前端交互

保持原界面布局，只增加必要状态和操作：

- 顶部状态显示“访客模拟模式”或“真实模式已解锁”。
- 默认选择模拟采集；访客点击真实采集、真实配置或模型增强时打开密码窗口。
- 登录成功后不刷新整页，原地显示完整功能和真实数据。
- 提供“锁定并返回模拟模式”按钮，但不因时间自动锁定。
- 接口状态区未登录时显示真实状态和脱敏详情；登录后展开完整物理映射。
- 模型区未登录时显示“本地规则；登录后可使用服务器模型”，不得显示 Key 占位值或长度。
- 保存区明确区分“服务器模拟目录”和“真实采集目录”。
- 多浏览器控制冲突、Tunnel 断线、磁盘不足、模型失败和权限不足都有独立且可恢复的提示。

## 12. 安全和故障处理

- 所有状态修改请求继续要求同源、JSON 和 CSRF 防护。
- 只信任来自本机 Tunnel 连接的代理头；不直接信任任意 `X-Forwarded-*`。
- 公网响应不返回密码哈希、令牌、API Key、数据库密码、内部路径或完整环境变量。
- 文件保存和下载使用固定根目录、规范化路径和大小限制，拒绝路径穿越。
- 访客 MySQL 只允许管理员预设只读数据源，不能提交任意查询。
- Agent 工具保持只读诊断边界，模型不能直接启动/停止硬件或修改配置。
- 密码错误、令牌撤销、权限拒绝、模型调用、真实控制和本机强制接管均写入审计日志。
- EXE、Tunnel 或模型任一部分异常时，硬件采集的本机安全边界不改变。

## 13. 测试和验收

自动测试至少覆盖：

- 密码哈希、正确/错误登录、永久会话持久化和全部撤销。
- 未登录真实接口全部返回 `403`，且不会进入硬件驱动。
- 访客可读取脱敏真实状态，不会获得内部标识和路径。
- 多个访客模拟会话数据、曲线、结果目录互不影响。
- 模拟保存配额、磁盘不足、路径穿越和下载边界。
- 登录后真实采集、配置、诊断和模型调用保持原功能。
- API Key 不出现在 HTML、JavaScript、Bootstrap、状态响应、错误响应和日志中。
- 模型失败后保留本地规则，硬件检查和采集不中断。
- 多浏览器真实控制互斥、断线释放控制和本机强制接管。
- Host、Origin、CSRF、Cookie、安全代理头和应用限流。
- 现有采集、预测、预警、诊断、保存和训练回归测试全部通过。

现场验收顺序：

1. 本机与局域网回归现有功能。
2. 公网未登录访问，验证默认模拟和真实状态只读。
3. 用手机移动网络验证 HTTPS 域名。
4. 验证访客不能通过直接 API 请求启动真实采集。
5. 输入密码后验证真实接口、采集、保存和模型诊断。
6. 关闭浏览器和重启 EXE，验证登录仍有效。
7. 在本机撤销该浏览器，验证公网请求立即失效。
8. 中断 Tunnel，验证本机采集继续；恢复后网页同步状态。
9. 搜索交付目录、网络响应和日志，确认不存在明文密钥。

## 14. Git 和交付原则

- 在当前仓库和分支上实现，每个逻辑阶段独立提交。
- 实施前记录当前基线提交；关键阶段使用可读标签，回退优先使用 `git revert` 或从标签建立恢复分支。
- 用户密码、API Key、登录会话、Cloudflare 凭据和运行日志不进入 Git。
- 继续原位更新 `delivery/AFP_Integrated_System_Modular_v2.0.3_Agentic/AFP_Integrated_System_Modular.exe`，不创建新的版本目录或重复 EXE。
- 公网改造完成后必须同时保留本机和局域网访问，公网失败不能阻断现场使用。

## 15. 实施阶段划分

1. 安全基础：本机设置、密钥存储、认证、永久会话和撤销。
2. 权限隔离：服务端权限策略、脱敏真实状态和真实 API 拦截。
3. 模拟隔离：独立访客模拟会话、保存目录、配额和下载。
4. 真实控制：单控制者、幂等命令、断线恢复和本机接管。
5. 模型授权：服务器端 Key 调用、频率限制、审计和本地回退。
6. 公网接入：固定 Tunnel、域名、HTTPS、Host/代理配置和限流。
7. 全量验证：自动测试、EXE 自检、局域网和外网现场验收。
8. 原位交付：更新同名 EXE、提交 Git、记录校验值和回退点。

域名和 Cloudflare 账户是公网现场验收的外部前提；在用户提供域名并完成必要授权前，代码、权限和本机模拟可完成，但不能宣称公网网址已经正式交付。
