# 公网采集与诊断可靠任务层设计

## 背景

公网模式比局域网多经过 Cloudflare Tunnel、HTTPS 会话、授权控制权和访问者电脑本地辅助程序。当前表现为辅助程序失联后仍显示在线、命令进入无人读取的队列、硬件检查超时，进而没有诊断事件；同时 LangChain 采用一次长连接，网页状态变化可能取消或丢弃已完成的模型结果。

## 目标

1. 访问者电脑上的辅助程序必须有可验证的在线状态；失联命令立即返回明确错误，不再等待固定超时。
2. 硬件检查完成后形成不可变异常快照，本地诊断和模型诊断都使用同一快照。
3. LangChain 诊断改为后台任务和短轮询，公网连接中断不丢失结果。
4. 目标 MySQL 的只读关系刷新不依赖真实采集独占控制权。
5. 公网、局域网和本地辅助程序的行为边界保持清晰；模拟模式不读取物理硬件。
6. 所有变更通过现有 Git 分支管理，不创建重复版本目录或重复 EXE。

## 非目标

- 不改变传感器驱动协议、通道定义、CSV 命名层级或 MySQL 表结构。
- 不让模型直接执行系统命令、任意网络扫描、设备控制或文件写入。
- 不把端口枚举、设备枚举或 TCP 可达性描述为传感器已经接入。

## 设计

### 1. 辅助程序可靠性

`HelperRegistry` 为每个配对会话保存最后心跳时间，默认心跳有效期为 15 秒。 `status()` 和 `command()` 均先判断有效期；失效时返回 `paired=true, online=false`，命令返回 `helper_offline`，不再入队。

辅助程序轮询成功后刷新心跳。收到 `helper_authentication_failed` 时停止当前连接循环并提示重新配对；其他网络错误使用有限退避重试，并在窗口或日志中保留最近错误。

命令协议固定包含：

```json
{
  "type": "command",
  "request_id": "...",
  "command": "check_capture",
  "payload": {}
}
```

辅助程序无论成功还是已知执行异常，都返回同一个 `request_id` 的 `type=result`。网页收到结果后结束轮询，已知异常显示具体错误。

### 2. 硬件检查快照

服务器或辅助程序完成检查后，网页将完整 `hardware_result` 转换为异常事件列表，并生成当前检查指纹。诊断任务携带该快照的副本；后续接口识别、配置刷新或下一次检查不得修改正在运行任务的输入。

本地规则诊断在服务器端同步完成，始终对全部异常接口和通道返回结果。没有异常时返回明确的 `no_anomaly` 状态。

### 3. LangChain 后台任务

保留现有 `/api/agent/diagnose` 兼容接口，同时增加任务接口：

- `POST /api/agent/diagnose/start`：校验权限、异常快照和模型配置，创建任务并立即返回 `job_id`。
- `GET /api/agent/diagnose/result?job_id=...`：返回 `pending`、`running`、`success` 或 `failed`；成功结果只读保存到任务记录中。

后台任务复用现有 `run_interface_diagnoses`、工具白名单和结果校验。每个任务绑定会话、异常指纹和创建时间；同一会话的重复提交按指纹去重，模型限流仍按会话执行。任务结果在有限时间内保留，网页刷新后可以继续读取。

前端流程为：

```text
硬件检查完成
  -> 固化异常快照
  -> 本地诊断立即显示
  -> 创建模型任务
  -> 每秒读取任务状态
  -> 显示模型结果或明确失败原因
```

任何新检查只标记旧任务为“历史结果”，不得调用 `AbortController` 删除服务器任务。

### 4. MySQL 权限边界

`/api/mysql/test` 和 `/api/mysql/relation-map` 都是数据库访问操作。目标关系表刷新是只读操作，不申请真实采集控制权；只有开始、停止和真实硬件采集等改变设备状态的操作才要求控制租约。

访问者电脑的本地 MySQL 仍通过已配对辅助程序执行，目标 MySQL 仍由采集服务器执行。两者在界面上分别显示执行位置和错误原因。

### 5. 接口识别函数

保留一个 `discoverInterfaces()` 实现：

- 访客模拟模式只使用模拟数据通道；
- 公网授权真实模式通过辅助程序读取访问者电脑接口；
- 局域网管理员模式由服务器本机读取接口。

删除或合并重复定义，避免后定义函数覆盖公网分支。

## 错误处理

- 辅助程序未配对：禁止真实检查，提示配对。
- 辅助程序已配对但心跳过期：显示离线，命令不入队。
- 命令执行异常：在原请求中返回错误，不显示无意义的“响应超时”。
- 模型任务超时或 provider 错误：保留本地诊断，显示模型错误和任务编号。
- 浏览器刷新或 Tunnel 短暂断线：重新读取任务状态，不重复提交同一异常快照。

## 验证标准

1. 辅助程序正常轮询时，发现、MySQL 预检和硬件检查均能在同一请求中返回结果。
2. 停止辅助程序超过心跳有效期后，网页显示离线，命令立即得到 `helper_offline`。
3. 硬件检查形成的每个异常接口均同时出现在本地诊断和模型诊断结果中。
4. 模型执行超过 30 秒时，网页仍能通过任务轮询获取成功结果。
5. 刷新网页或重新检查接口不会清除已完成或运行中的诊断任务。
6. 公网目标 MySQL 关系刷新成功，且不需要先启动真实采集。
7. 局域网原有启动、采集、保存和诊断流程回归通过。
8. 自动化测试、EXE 启动、局域网 URL、公网 URL 和 Git 工作区检查全部通过后才交付。
