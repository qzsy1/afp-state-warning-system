# AFP 集成系统局域网网页版设计

日期：2026-09-14
目标分支：`feature/original-ui-langchain-agent`

## 1. 目标与范围

在不改变现有传感器采集、预测、三级预警和 LangChain 诊断逻辑的前提下，使现有 `AFP_Integrated_System_Modular.exe` 同时提供：

- 采集电脑上的原桌面窗口；
- 同一局域网内电脑、平板或手机通过固定网址访问的完整前端。

第一阶段只支持可信实验室局域网，不部署到公网。仍只维护当前 Git 仓库、现有交付目录和同名 EXE，不复制工程、不创建新的版本文件夹。

## 2. 总体架构

采集电脑是唯一硬件服务器，负责连接 SMRF 八通道热电偶、PLC、BSV UVC、ABB 和 M3232 薄膜压力传感器，并负责数据解析、预测、预警、保存和诊断。

局域网浏览器只是远程界面，不直接访问访问者电脑上的 USB、串口、网卡或摄像头。所有访问者看到的是同一个采集进程、同一份实时状态和同一次诊断结果。

数据路径为：

`实际传感器 → 采集电脑上的 EXE → HTTP 接口与原前端 → 局域网浏览器`

当前基于 HTTP 轮询和 `fetch` 的前端继续复用，不在第一阶段引入 WebSocket、云服务器或第二套前端，以降低对现有功能的影响。

## 3. 启动与固定网址

正式 EXE 从外部 `config/runtime.json` 读取唯一的局域网配置：

```json
{
  "lan_web": {
    "enabled": true,
    "bind_host": "0.0.0.0",
    "port": 8770,
    "open_desktop_window": true
  }
}
```

行为约定：

- `enabled=true` 时服务绑定 `0.0.0.0:8770`，允许局域网访问。
- 本机桌面窗口始终打开 `http://127.0.0.1:8770/`，界面外观不变。
- 其他设备访问 `http://采集电脑局域网IPv4地址:8770/`，例如 `http://192.168.1.20:8770/`。
- 软件自动识别可用的局域网 IPv4 地址，在界面中显示可访问网址和服务状态，但不把虚拟网卡、回环地址或 `169.254.*.*` 地址作为首选网址。
- 固定端口被占用时不得静默换成随机端口；启动窗口给出“8770 端口被占用”的明确错误和处理建议。
- `enabled=false` 时恢复为仅本机访问，仍使用固定端口 8770。

固定网址能否长期不变取决于采集电脑的局域网 IP。交付说明要求在路由器中为采集电脑设置 DHCP 地址保留，或为其设置合适的静态 IP。

## 4. 前端调整

保持原系统布局和所有功能模块，只增加一处紧凑的“局域网访问”状态，不另做管理后台：

- 显示“局域网服务：已开启 / 仅本机 / 启动失败”；
- 显示当前访问网址；
- 提供复制网址按钮；
- 多网卡时列出有效候选网址；
- 网络暂时断开时显示“采集仍在服务器运行，正在重新连接”，恢复后继续刷新。

页面使用相对 API 地址，因此本机窗口和远程浏览器共用完全相同的 HTML、CSS、JavaScript 和诊断界面。

## 5. 多客户端与操作互斥

局域网内多个浏览器可能同时打开系统。服务端必须统一管理状态，不能让每个浏览器各自启动一套采集任务。

- 查看实时数据、预测、预警和诊断结果允许多个客户端同时进行。
- 启动/停止采集、立即检查、重置检查、LangChain 诊断和配置保存等修改状态的操作使用服务端互斥锁。
- 同类操作已经执行时，第二个请求返回 `409 operation_in_progress`，前端提示“操作正在另一窗口执行”，不得重复打开硬件接口。
- 浏览器关闭、刷新或网络中断不停止服务器上的采集任务。
- 新浏览器打开后从服务器读取当前状态，不创建新的本地状态副本。

第一阶段允许可信实验室局域网中的访问者操作完整界面。不得将 8770 端口映射到公网；公网访问和多用户权限控制另行设计。

## 6. API Key 与诊断安全

- 硅基流动 API Key 只在诊断请求中由浏览器提交给采集电脑，或由采集电脑本机的安全存储读取。
- API Key 不写入 HTML、前端脚本、`runtime.json`、状态接口、日志或诊断结果。
- `/api/network/status` 只返回运行模式、端口、候选局域网网址和启动时间，不返回传感器配置详情或任何密钥。
- 后端继续执行“无有效 Key/模型或调用失败时使用本地规则”的现有降级逻辑。
- 模型调用仍由采集电脑发出，不由远程浏览器直接访问硅基流动。

## 7. 局域网安全边界

第一阶段增加以下最低保护：

- 只接受目标为本机回环地址、本机实际局域网地址或本机名称的 `Host`；拒绝异常 Host，降低 DNS 重绑定风险。
- 修改状态的接口只接受 `application/json`，并校验 `Origin` 与当前服务地址一致。
- 不启用跨域访问，不返回 `Access-Control-Allow-Origin: *`。
- 接口参数继续按现有白名单校验，浏览器访问不能扩大 Agent 工具和硬件操作权限。
- Windows 防火墙只为专用网络配置文件放行 TCP 8770，不为公用网络放行。

软件不静默申请管理员权限或自动修改防火墙。若防火墙未放行，界面显示检测说明，交付文档给出一次性的 Windows 操作步骤。

## 8. 代码修改边界

实施只修改现有文件并增加必要测试：

- `modular_runtime/app/bootstrap.py`：读取局域网配置、固定端口启动、保留本机桌面窗口、处理端口占用。
- `modular_runtime/config/runtime.json`：增加 `lan_web` 默认配置。
- `visualization_app/app.py`：局域网状态接口、Host/Origin 校验和状态修改操作互斥。
- `visualization_app/static/index.html`、`app.js`、`styles.css`：显示局域网地址与重连状态。
- 现有测试目录：补充启动、网络状态、安全校验、并发操作与断线恢复测试。
- 现有交付目录的 `config/runtime.json` 和同名 EXE：完成验证后原位更新。

功能测试仍可使用 `127.0.0.1` 和临时端口，避免并行测试争抢 8770；只有正式启动路径强制使用配置的固定端口。

## 9. 实施顺序

1. 为当前提交建立局域网改造前的 Git 基线标签。
2. 先编写启动配置、固定端口和网络安全测试。
3. 修改正式启动路径，使同一服务同时服务本机窗口和局域网浏览器。
4. 增加网络状态接口、操作互斥和前端连接状态。
5. 在本机分别使用 `127.0.0.1` 与采集电脑局域网 IP 验证。
6. 用同一局域网的第二台设备访问并验证显示、操作互斥和断线恢复。
7. 运行现有全部测试和 EXE 自检，确认传感器、预测、预警、诊断与保存功能未回归。
8. 只覆盖现有交付目录中的同名 EXE 和配置，更新校验文件并提交 Git。

## 10. 验收标准

- 运行一个 EXE 后，本机原桌面界面正常打开。
- 同一局域网第二台电脑或手机可通过 `http://<采集电脑IP>:8770/` 打开相同界面。
- 五类传感器仍只由采集电脑识别和采集，远程浏览器不会扫描访问者设备。
- 多个客户端显示同一采集状态、实时数据、报警和 LangChain/本地规则诊断结果。
- 远程浏览器断开不会停止采集；重新连接后能恢复当前状态。
- 并发启动、停止、检查和诊断不会重复占用硬件，冲突请求有明确提示。
- API Key 不出现在页面源代码、启动数据、网络状态接口、日志和 Git 文件中。
- 端口占用、无有效局域网地址或防火墙阻断均有明确提示，不停在无反馈状态。
- 原有源代码测试、模块自检、打包验证和校验文件检查全部通过。
- Git 中只有一套源代码和一个现有交付目录，可以按提交或标签回退；不生成重复工程、重复文档或多个 EXE。

## 11. 暂不包含

- 公网、云服务器、域名和 HTTPS 部署。
- 通过互联网远程控制设备。
- 多用户账号、角色权限和审计系统。
- 把传感器驱动安装到浏览器访问设备。
- 新建第二套网页版项目或重新设计现有界面。

这些内容只有在局域网版本现场验收稳定后再单独评估。
