# AFP 接口自主取证与离线验收诊断设计

日期：2026-09-13  
目标分支：`feature/original-ui-langchain-agent`

## 1. 目标

将当前“本地规则先给出答案、云端模型补充文字”的流程改为受控的工具调用诊断流程：模型先看到实际检查现象，再自主选择只读工具补充证据，最后给出有证据引用的判断和建议。

当前没有连接真实传感器，因此第一阶段增加一个明确标注的“离线测试诊断器”，用相同的工具协议和结果格式验证流程、界面和安全边界。离线测试诊断器不是大语言模型，不得在界面或文档中冒充 GPT、DeepSeek 或现场硬件结论。配置有效 API Key 且模型支持工具调用时，使用硅基流动在线 Agent；否则使用离线测试诊断器和本地规则完成开发验收。

现有 I-ModernTCN 等时序预测模型不用于接口故障诊断。它们需要有效采集数据，不能判断 USB、串口、网口或驱动是否连接。

## 2. 无传感器条件下的事实真值

“电脑发现网卡、COM 口、USB 控制器、普通摄像头或厂商 DLL”不等于目标传感器已经连接。只有目标身份匹配且收到符合协议的有效数据，才能报告接口正常。

在用户明确未连接任何目标传感器时，五个接口应得到以下结果：

| 接口 | 物理类型与协议 | 无传感器时应报告 | 受影响通道 |
|---|---|---|---|
| SMRF 八通道热电偶 | USB HID / SMRF HID | 未识别到匹配 SMRFCT08B 设备，或接口无法打开；不得把临时占位绑定报告为已连接 | 温度1～温度8均无有效数据 |
| 松下 PLC | 与 ABB 共用电脑网卡 / Modbus TCP | 电脑网卡可存在，但 `192.168.125.5:502` 不可达或未返回有效 Modbus 数据；不得直接判断 PLC 损坏 | 温度、压力、张力均无有效数据 |
| BSV UVC 热像仪 | USB UVC / 厂商驱动 | 未识别到可产生 BSV 温度帧的设备；只有 DLL 时应报告“驱动存在、设备/数据未确认” | ROI平均温度无有效数据 |
| ABB 机器人 | 与 PLC 共用电脑网卡 / ABB RWS | 电脑网卡可存在，但 `192.168.125.1` 不可达或未返回有效 RWS 数据；不得直接判断机器人损坏 | ABB_X、ABB_Y、ABB_Z、线速度均无有效数据 |
| M3232 薄膜压力 | 独立串口 / M3232 串口协议 | COM8 不存在、无法打开，或端口可打开但未收到 M3232 有效帧；不得把其他串口设备认作 M3232 | 薄膜压力无有效数据 |

顶层结果应为“检查未通过：0/5 个目标传感器接口已由有效数据确认，0/17 个通道正常”。若电脑环境中某接口恰好可打开，接口数量仍不得因为占位接口或无协议数据而增加。

状态要区分：

- `physical_missing`：所需物理接口不存在。
- `identity_unconfirmed`：存在相同类型物理接口，但未确认是目标设备。
- `endpoint_unreachable`：目标网络地址或端口不可达。
- `open_failed`：目标接口存在但无法打开。
- `no_data`：接口打开但观察期内没有数据。
- `invalid_protocol`：收到数据但不符合预期协议。
- `partial_data`：只收到部分通道有效数据。
- `ok`：目标身份、协议和至少一个有效样本均通过；对要求完整性的接口还需覆盖全部必需通道。

“传感器损坏”不属于自动检查可以直接确认的状态，除非后续有独立电气或替换件证据。

## 3. 诊断架构

一次用户点击创建一个不可被定时任务覆盖的诊断任务：

1. 原采集模块执行一次硬件检查，形成五接口和 17 通道事实快照。
2. 本地规则并行生成兜底结果，但不作为在线模型的预设答案。
3. Agent 接收事实快照、可用工具定义和安全约束。
4. Agent 根据当前现象选择工具；工具执行器审核目标、参数、次数和超时。
5. 工具返回带 `evidence_id` 的结构化事实，追加到同一诊断上下文。
6. Agent 可继续选择工具，或输出最终诊断。
7. 后置校验器检查每项结论是否引用现有证据；无证据的确定性结论降级为“推测”。
8. 界面在原硬件结果区域合并显示硬件事实、Agent 判断、证据来源、建议和未确认事项。

限制为最多 5 轮、8 次工具调用和 90 秒总时长。用户可以取消当前任务。没有自动周期性重诊断。

## 4. 只读工具合同

第一阶段提供以下工具：

1. `inspect_interface_mapping(interface_id)`：返回传感器类型、逻辑接口、实际物理绑定、协议、驱动及是否为临时占位。
2. `recheck_interface(interface_id, duration_seconds)`：在不与正在采集的驱动争用端口的前提下，复查目标接口；最长 3 秒。
3. `get_recent_channel_stats(channel_names, window_seconds)`：返回数据新鲜度、有效/无效/缺失计数、范围、跳变和趋势摘要。
4. `get_cross_interface_timeline(interface_ids, window_seconds)`：返回异常、恢复和重连时间，用于发现共因。
5. `inspect_protocol_frame(interface_id)`：返回受限的帧长度、帧头摘要、字段或矩阵维度和解析错误；不向模型发送整段大数据。
6. `check_network_path(interface_id)`：只允许检查当前配置中的 PLC 和 ABB 地址、对应电脑网卡、子网和目标端口，不允许任意网络扫描。
7. `lookup_device_knowledge(device_type, symptom)`：查询随软件发布的本地协议说明和已确认案例。
8. `compare_related_signals(channel_names, window_seconds)`：由确定性代码计算多个通道的同步、滞后和变化关系，模型只解释结果。

所有工具必须通过接口 ID 访问已配置对象，不能让模型传入任意文件路径、命令、IP、串口或数据库语句。

## 5. 离线测试诊断器

离线测试诊断器用于当前无硬件阶段，作用是验证“不同现象选择不同工具”的完整软件流程。它采用可测试的决策策略：

- 无目标身份时，先调用接口映射；USB/串口再进行一次目标接口复查。
- PLC 与 ABB 同时异常时，调用跨接口时间线和网络路径检查。
- 接口打开但无数据时，调用接口复查和近期通道统计。
- 有数据但解析失败时，调用协议帧检查和设备知识查询。
- 单通道异常时，调用近期通道统计；存在相关工艺通道时再调用信号比较。

诊断器输出与在线 Agent 完全相同的工具调用请求和最终结果结构，使前端、工具执行器、后置校验器和测试代码可以复用。界面必须显示“离线测试诊断”，不能显示“硅基流动模型增强成功”。

离线测试器的判断只用于验证已知场景是否按设计工作；它不能证明大模型质量，也不能作为真实设备故障结论。

## 6. 在线模型工具调用

配置有效 API Key、模型名称且模型能力检查通过时，使用硅基流动 Chat Completions 的 Function Calling：

- 请求提供 `tools` 和自动工具选择。
- 模型返回工具名和参数，由本地执行器审核后调用 LangChain `@tool`。
- 工具结果作为 `tool` 消息返回模型，直到模型形成最终结果或达到限制。
- 不支持工具调用的模型不得伪装成 Agent，自动回退离线测试诊断器和本地规则。

默认 Agent 模型应改为硅基流动当前明确标注支持工具调用的型号；实施时先通过能力探测和模拟响应测试确认具体模型 ID，不继续假设旧 `deepseek-ai/DeepSeek-V3` 一定支持稳定工具调用。

## 7. 最终结果格式

每个诊断结论包含：

- `case_id`：本次诊断任务标识。
- `mode`：`offline_test`、`siliconflow_agent` 或 `local_rules`。
- `affected_interfaces`、`affected_sensors`、`affected_channels`。
- `observed_facts`：只放工具返回的事实，包含证据编号。
- `hypotheses`：原因、置信度和支持/反对证据编号。
- `cross_interface_findings`：跨接口共同现象。
- `recommended_actions`：按优先级排列，注明理由和是否需要停机。
- `unknowns`：当前无法确认的内容。
- `evidence_sources`：只显示简洁来源标签，不恢复完整 LangChain 调用轨迹。
- `local_fallback`：在线模型失败时使用的本地结果。

## 8. 安全边界

Agent 只能诊断和建议，不能：

- 写 PLC 寄存器或更改 PLC 参数。
- 向 ABB 下发动作或控制命令。
- 修改、保存或自动替换传感器映射。
- 终止占用接口的进程。
- 重启设备或服务。
- 扫描未配置的网络、串口和文件。
- 把临时串口、普通摄像头或已安装 DLL当成目标传感器已连接。

如果采集正在运行，工具只能读取采集管理器已有缓存和状态，不能再次打开同一硬件。

## 9. 前端行为

保持原界面布局，仅修改现有接口检查结果区域：

- 点击“立即检查”后显示一次任务的硬件检查和诊断结果。
- “重置并重新检查”先取消旧任务，再开始新任务。
- 显示模式标签：离线测试诊断、硅基流动 Agent 或本地规则。
- 显示已确认事实、综合判断、置信度、建议和未知项。
- 只显示“依据：接口映射、接口复查、网络路径”等摘要，不显示逐步 LangChain 调用轨迹。
- 新结果只能由用户主动发起的同一任务更新，不被定时轮询覆盖。

## 10. 测试与验收

先使用模拟工具结果覆盖：

1. 五个目标传感器均未连接。
2. PLC 与 ABB 因共用网络同时不可达。
3. M3232 串口存在且有字节，但帧结构不匹配。
4. BSV 驱动存在但无目标热像设备或温度帧。
5. 八通道热电偶只有部分通道有效。
6. 单通道数据陈旧或跳变。
7. 模型请求非法工具、非法接口或超出调用次数。
8. 模型超时、响应格式错误或漏掉异常。
9. 用户在诊断中取消并重新开始。

“无传感器”验收必须满足：

- 0/5 个目标接口通过有效数据确认，0/17 个通道正常。
- 每个接口的错误类型符合第 2 节，不出现“已连接”“传感器损坏”等无证据结论。
- 离线测试诊断器按接口现象选择不同工具。
- 每项综合判断引用至少一个真实工具证据。
- 本地规则、离线测试和在线 Agent 失败互不清空原硬件检查结果。
- 不产生任何硬件写操作。

真实硬件接入后另做现场验收。尤其 M3232 必须捕获实际原始帧后，才能确认当前矩阵解析路径与设备协议一致。

## 11. Git 和交付原则

- 在当前 Git 仓库和现有功能分支上继续管理，不复制整套工程。
- 实施前为当前提交建立可识别基线标签。
- 按“测试合同、工具层、Agent 循环、前端集成、交付验证”拆分小提交。
- 不生成多个重复文档或不同名称的 EXE。
- 只有在源代码和测试通过、用户要求更新交付软件时，才覆盖更新既有交付目录中的同名程序，并更新校验文件。
- 回退使用 Git 的标签、`git revert` 或从指定提交恢复文件，不在软件界面增加回退功能。
