## 模块健康范围

通过健康检查的模块为：`drivers`、`acquisition`、`storage`、`data_integration`、`prediction`、`health`、`warning`、`training`、`diagnostics`。驱动模块确认打包目录含 `BsvUvcNative.dll` 和 `libusb-1.0.dll`；存储模块确认软件内包含并实际使用 MySQL Python 驱动；健康指标模块确认新数据方案为 16 个传感器且健康指标工件存在。v2.0.1 同时补齐 `_tkinter.pyd`、Tcl/Tk 8.6 数据文件、openpyxl 3.1.5 和 xlrd 2.0.2。

## 科学与现场验证边界

- 本次完整链路使用模拟采集数据，未连接真实传感器，因此只能确认真实采集驱动、接口映射和错误处理代码已被装入，不能替代设备现场通信验收。
- 采样质量统计已经进入每层摘要，但真实设备的丢包率、接口时钟偏差、长时间漂移和断线重连仍须在实际硬件接入后进行10秒快速检查及连续运行验收。
- MySQL 写入回读使用专门的临时测试库，不把诊断行写入正式实验库；界面仅对正式库执行连接检查。迁移到另一台电脑时仍需确认 MySQL 服务、账户权限和目标数据库配置。
- 一轮训练仅用于证明“导入—整合—训练—保存”链路能够执行，所得验证分数不是论文模型精度，也不能作为真实 AFP 缺陷识别能力结论。
- 当前预警输出属于模型/健康指标证据。没有独立缺陷检测或力学性能证据时，不应把它表述为已确认真实缺陷诊断。
