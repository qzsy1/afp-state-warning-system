# AFP 实时预测、健康指标与状态预警系统

系统提供两种运行方式：

- **模拟采集数据源**：使用 `new_collection_v13_0` 的确定性 64 路热电偶数据验证采集、保存、派生和显示链路；旧 CSV、文件夹和 MySQL 数据仍可用于历史回放。
- **真实传感器采集**：正式热电偶入口为 64 路设备。设备协议及映射资料确认前，真实采集保持阻断；旧 8 路数据只读兼容。

兼容且经过验证的模型方案可启用两种处理模式。`new_collection_v13_0` 当前没有已验证的模型权重，只能保持仅采集状态；旧 8 路模型不会自动接收新方案的 8 组均值。

- **仅采集并保存**：完全跳过模型文件检查、I-ModernTCN前向推理、健康指标和三级预警；适合先检查新传感器链路和积累训练数据。
- **采集＋实时预测与预警**：采集通道累计24点后运行所选I-ModernTCN，48点后形成第一个可评价窗口。

两种模式采用同一条计算链：

`24点历史实测 → I-ModernTCN预测未来24点 → 未来24点实测到达 → 实时构造健康指标特征 → 分类器异常概率 → 窗口CAP聚合 → 层CAP聚合 → 实际铺层数试样CAP聚合`

## 实时刷新与增量计算

实时页以增量方式刷新并计算预测和健康指标：

- 每个已完成的24点窗口只运行一次I-ModernTCN预测、健康指标特征构造和异常分类，后续刷新直接复用该窗口结果；
- 只有采集到新点时才重新计算当前未来预测，同一采样点的重复页面请求直接复用预测；
- 至少获得24点历史后，未来预测立即显示；一个目标时刻的预测值首次显示后即冻结，后续刷新不再覆盖。真实点到达时，同一个冻结值从未来区直接移入历史预测区，因此前后数值完全一致。健康指标仍使用严格的24点整窗预测，不改变预警口径；
- 层级证据仅在新增完整窗口或采集启停状态改变时写入磁盘，避免每次网页刷新重复写文件；
- 采集配置使用原始通道名“压力”，图表使用显示名“压实力”，后端按固定模型通道索引映射，因此勾选压力预测后会正常显示实测、历史预测和未来预测。

前端100 ms刷新代表页面最多每秒请求10次；实际可见更新频率仍受采集频率限制。例如采样率为10 Hz时，正常表现为约每100 ms增加一个新点。

“停止并保存”成功后表示当前物理铺层结束。系统保存本层数据和健康证据后，才允许把层号或独立重复次数增加1；再次点击“开始采集”即采集下一层。铺层数和独立重复次数不设固定上限，试样级健康指标按当前试样实际已经保存的全部铺层动态聚合。该操作保留明确的人工层界，避免在真实AFP连续数据中凭时间间隔误判层号。

“中断采集”和“继续采集”操作同一次、同一层采集。执行端确认中断后停止采样与记录追加，保留已有数据、会话身份、试样、层号和保存目标，不生成最终层文件或提交最终 MySQL 事务；采集配置保持锁定。中断期间可以直接“停止并保存”，保存全部有效采样段。继续前丢弃设备积压及未完成帧，等待新边界后的有效数据；采样时钟重新计时，不追赶暂停期间的计划。时间戳保留实际间隔，预测预警窗口仅使用继续后的连续采样段。保存失败时保持未完成状态，不允许开始覆盖数据的新采集。网页与原生界面均使用执行端确认状态；远程 helper 必须声明 `capture_pause_v1` 能力。

网页中的“连接数据／断开数据”与“开始采集”并列显示，独立于中断和继续操作。本机真实设备连接后显示“断开数据”；采集中或已中断时，须先停止并完成保存，再断开设备。保存失败时保留连接和未完成数据。模拟模式保留入口并禁用；远程 helper 的设备连接由访问电脑辅助程序管理。

隔离模拟验收可在源码根目录执行 `.\.venv\Scripts\python.exe -B visualization_app\preview_acquisition.py --port 0`。该入口使用共享采集核心和专用验收页面，仅监听 `127.0.0.1` 的空闲端口；启动时输出地址，模拟源与采集文件位于 `D:\AFP_Runtime\.afp-staging\acquisition-pause\preview-*`。入口不提供真实设备、MySQL 或正式运行目录操作。

## 已训练预测模型、输入和输出选择

真实采集设置中可以直接选择已训练的`.pth`或`.pt`预测模型。默认模型的元数据内置在程序中；其他模型必须在模型旁提供以下任一元数据文件：

- `checkpoint.pth.json`；
- `checkpoint.json`；
- `model_metadata.json`。

格式参考[prediction_model_metadata.example.json](prediction_model_metadata.example.json)。兼容性规则为：

- 模型结构为I-ModernTCN，`seq_len=24`、`pred_len=24`，`model_columns`数量必须等于`enc_in`；
- 自定义模型必须在元数据中直接提供`scaler_mean/scaler_scale`，或通过`scaler_file`指向包含这两个数组的NPZ；沿用原17列标准化器时可声明`normalization=dashboard_sequences.npz`；
- 模型声明的输入传感器与界面勾选的“模型输入”完全一致，且全部模型输入都必须属于已勾选的“采集保存”通道；允许额外采集不进入模型的通道；
- 界面勾选的“模型输出”必须属于模型元数据声明的可输出通道；
- T-HI至少输出8个温度通道，C-HI至少输出压力，TC-HI至少输出8个温度通道和压力；RFHI、PR-HI及其他全残差对比指标要求输出全部12通道。

开始采集和检查连接之前都会执行上述校验，不一致时拒绝运行并列出缺少或多余的通道。实时健康指标仅采用当前指标所需且已经选为模型输出的传感器；例如TC-HI只采用当前模型输出的8个温度通道和压力，不再默认使用未选择的输出。

### 验证集最佳预测模型覆盖

勾选“使用冻结验证集最佳预测模型覆盖当前模型选择”后，系统忽略上方手动模型路径，在当前数据采集方案的已登记兼容模型中按冻结验证集误差选择模型：

- 新v11.3方案使用验证集标准化MSE选择，当前登记最优值为0.03595；
- 旧方案当前只有一个已登记兼容论文检查点，因此覆盖选项选择该检查点，并明确标记为“唯一登记模型”，不伪造模型间比较；
- 内推测试、外推测试和实时到达后的未来真实值均不参与模型选择；
- 该选项只覆盖预测模型，不改变健康指标、异常分数分类器、阈值或“优化预警”设置。

取消勾选后恢复当前采集方案下的手动模型选择。仅采集模式下该选项自动停用。

## 预测和健康指标是否真正实时

是，但要区分两个层面：

1. 勾选“使用 I-ModernTCN 当前检查点实时计算预测”时，后端确实把当前24点输入现有 I-ModernTCN 检查点，执行一次模型前向推理；不是读取预先保存的预测结果。预测1–24点为一次直接输出，25–600点为递归滚动预测。
2. 每个目标窗口的24个实测点到齐后，系统重新使用该窗口的实测值和当时保存的模型预测值，计算所选健康指标的响应/残差特征，再由所选分类器执行 `predict_proba` 得到异常分数。不是读取预生成健康分数表。

真实采集模式固定使用实时模型预测和实时健康特征。勾选优化预警时，使用v13.9因果在线一致性：只融合当前窗口、当前层已有窗口和此前已完成层，不读取未来层。至少收到当前模型声明的全部输入通道连续24点后可显示未来预测，至少48点后才形成第一个可评价的健康指标窗口。

## 接口状态与本地 LangChain 诊断

"接口与通道检查”包含热电偶、PLC、UVC、ABB、M3232 薄膜压力和 ESR1001-A 四通道应变逻辑接口，并保留原始错误、协议分类、通道计数和本地处理建议。热电偶硬件身份和协议尚未确认时保持发布门禁。

只有同时填写 API Key 和模型名称后才启用诊断按钮；页面只提交“已填写”标志，不提交或保存 Key 原文。诊断链使用 LangChain Core 的本地 Runnable 和规则工具模拟事件接收、接口定位、证据检查、规则匹配与提示组成，不实例化模型、不访问网络、不改变采集配置。接口异常由原确定性检查触发，诊断结果仅作为定位提示，不等同于硬件故障确认。

## 真实采集配置

ESR1001-A 应变接口有两个显式协议：`modbus_rtu_esr1001` 使用独立 RS485、9600-8-N-1 和设备地址；`esr1001_usb_ttl` 使用原生 USB/TTL、115200-8-N-1，不受 RS485 的 FC04 `0x0030` 固件门禁限制。CH340 仅是候选线索，刷新只枚举；USB 协议须对人工选择的当前端口查询确认，不自动认领其他串口或鼠标。

原生 USB 参数查询为 `23 A8 00 00 00 FF`，有效参数响应为 `26` 开头、`FF` 结尾的14字节帧；启停分别为 `23 A1 01 00 00 FF` 和 `23 A1 00 00 00 FF`，要求匹配 `25 A1` 应答。四路数据帧为 `24`、CH4/CH1/CH2/CH3 各3字节大端有符号24位ADC、`FF`。该协议没有 CRC，只能提供固定长度结构及连续三帧同步证据，不能证明检测到所有位错误。正常检查不写采样率、增益、滤波、地址、通信模式或标定。

默认fixed策略在串口打开后保留1秒稳定间隔，参数校验完成后再等待1秒发送启动；检查与断线重连使用fixed。仅同后端有效检测复用、配置/身份匹配、固定参数原文 `26016306040001086800000000ff`、QUERY/START正确应答和稳定源观测齐全时，首次采集打开可使用bounded_response：开口后0.5秒保护，QUERY发送至START发送至少1.3秒，等待可取消，故障与取消使相应证据失效。数据验证窗口从启动应答后计时，至少3秒；端口可开、参数应答或启停应答不能单独使数据就绪。

没有 K/B 时，可选择 `esr1001_raw_adc` 独立诊断方案，或在正常数据方案中同时启用 PLC、ABB 和应变接口；应变使用 USB 协议和 `raw_adc`，处理方式为 `capture_only`，其他未使用设备显式禁用。没有换算依据时，四路曲线和主CSV使用 `CH1_ADC_signed`～`CH4_ADC_signed`、单位 `adc_counts`。启用厂商K/B候选或有效标定后，主CSV按页面显示保存 `应变1～4`（`με`、一位小数），显式清零后的源帧保存相对应变；每行使用自身源帧中的系数和零点。候选换算不代表标定确认，不改变模型和MySQL的准入条件。启动等待及缺测单元格留空，统一采样行保留以对齐其他传感器。独立诊断只保存 CSV。保存目录必须存在且可写，默认 `D:\AFP_Capture`。采集记录目录中的 `ESR1001_USB_*.csv` 逐源帧保存四路ADC、原始帧、换算及零点依据、主机墙钟/单调时间、接收序号和连接代际；同名JSON记录帧数、异常和停止结果。统一采样行数与源帧数分别核算。

正常与诊断方案分别保存接口协议、端点、绑定、启用状态、数据用途和存储选择。本机管理员方案保存到运行目录的 `runtime/interface-plans.json`，本机浏览器与正式 EXE 重开时共用；远程 Helper 继续使用访问端的独立方案。桌面网页缓存位于 `runtime/webview`，保持隐私模式。方案不保存认证秘密或就绪授权，配置恢复后必须重新枚举并检查。原始通信、数据就绪、标定和会话就绪分别判断：未标定不会被报告为 PLC/ABB 通信失败，禁用设备不属于已通过检查。

微应变用途选择 `microstrain` 及匹配的JSON标定档案。档案包含 `version: 1`、`unit: "με"`、可核验的 `source`、与枚举绑定一致的 `device_binding`、`bridge`、`gain_code` 和按CH1～CH4排序的 `channels`（每项 `K`、`B`）。只有有限且非零K、有限B及绑定/桥路/增益匹配时，使用 `με = ADC_signed × K + B` 输出 `应变1～4`。档案内容摘要进入就绪指纹与保存证据；没有合法档案不表示量值采集或精度通过。

界面可选择：

- 采集驱动：模拟器及已确认协议的设备驱动。通用串口/TCP JSON 输入不代表 64 路热电偶设备协议；其真实驱动需在厂商协议和映射确认后接入；
- 要连接和保存的传感器；
- 每个已连接传感器是否显示预测结果；取消后只隐藏该通道预测曲线、预测数值和RMSE，不影响完整模型输出用于健康指标与预警；
- 串口号或 TCP 地址、波特率、采样频率；
- 运行编号、试样编号、工况、独立重复次数、工艺参数和非负整数层号；
- 采集数据保存根目录（可直接输入，也可调用Windows文件夹选择器）；
- 健康指标、异常分数模型、判定阈值、CAP聚合强度和预测步长。

接口卡片中的“设备地址”和“实际物理接口”是两个独立配置。PLC 设备地址是 Modbus TCP 主机与端口，ABB 设备地址是 RWS 主机，BSV UVC 设备地址是已批准设备档端点；选择网卡、USB 端口、重新发现接口、切换模式或 Helper 重连都不得改写这些值。只有串口设备档会把所选 COM 端点写入设备地址。PLC 与 ABB 的“实际物理接口”只保存所选网卡、实际源地址和路由验证，UVC 的“实际物理接口”只保存 Windows 设备身份和 USB 物理端口。

真实采集按以下顺序配置：先确认设备地址，再执行“重新发现接口”，核对 PLC/ABB 显示的目标地址、实际源地址和最佳路由网卡，核对 UVC 的 VID/PID、Windows 服务和 USB 物理端口；需要时人工选择实际物理接口，随后执行“检查连接”。检查后任一设备地址、物理绑定、设备身份或驱动状态变化都会使结果失效，必须重新发现并再次检查。`network_path_invalid` 表示当前 Windows 路由与所选工业网卡不一致，必须修正路由或绑定后才能开始真实采集。

### PLC、ABB 与 BSV UVC Readiness API

真实 PLC 使用 `fibercontrol_plc_v1` 测量档：FC03、默认 Unit ID 255，温度 DT28/29、张力 DT23/24、压力 DT37/38，逐通道读取两个寄存器（低字在前 float32），保留两位小数。仅合法有限压力将舍入后的负值规范为 0 N，温度、张力、模拟和历史文件不截零；没有额外倍率、偏置或实时三点平均。规范压力供曲线、主 CSV、MySQL 与模型使用，模型质量准入和维度保持原有规则。协议错误、通信失败、NaN/Infinity 和过期样本不能成为有效零。

PLC 独立线程按单调截止时间调度 100 ms 目标轮次；配置中的旧周期规范化为 0.1 秒并回显。读完只等待剩余时间，慢轮次跳过过期截止点，不并发重入或突发补读。接口状态回显实测间隔、轮次耗时及跳过数。每通道按实际完成时间和源序号进入统一帧，截止后到达的压力不倒填；暂无新样本时仅在新鲜度内沿用旧来源，过期留空。

时间戳侧车 `channel_source_record_json` 按统一帧保存原始 words、地址、未裁剪值、舍入值、规范值、截零标记、处理档、源时间/序号和帧质量。MySQL 的 `afp_source_evidence.evidence_json` 以 `plc_frame` 和采样行序号保存同一关联；会话清单标明算法。无效浮点保存原始位模式及错误分类，JSON 不写 NaN/Infinity。旧文件缺少这些字段时仍按原值读取，不回填或重写。页面“PLC 压力与来源”区分最近读取与当前通道状态；合法截零不代表零点已校准。helper 必须声明 `plc_measurement_contract=fibercontrol_plc_v1`，不兼容时拒绝真实 PLC 启动。

数值夹具的参考期望来自已核对 C# 源码的复算，不能替代执行参考程序或现场稳定载荷对照。正常正压力持续偏差的根因尚未确认；实物数据一致性须以同工况原始寄存器、实际时间、配置、参考载荷与批准容差验收。

真实 ABB 使用 `fibercontrol_abb_v1` 测量档，读取配置端点的 `/rw/motionsystem/mechunits/ROB_1/robtarget?coordinate=Base&json=1`。ROB_1/Base 的 XYZ 直接解析为毫米，不增加倍率、偏置、坐标变换或滤波。独立线程以主机单调时钟调度 100 ms 目标周期，请求耗时包含在轮次内；慢读跳过截止点，不重入、不积压、不突发补读。接口状态区分目标周期、实际轮次间隔、响应耗时和跳过数，目标不代表实际严格 10 Hz。

线速度为同一连接代次相邻两个有效位置的三维距离除以主机实际单调接收间隔，保留两位小数；没有机器人设备时间。墙钟只用于对账，行时间与源响应时间分开。首点和非正间隔速度未验证，两个相同位置的正间隔才得到有效零。故障、重连或超新鲜度间隔后重新建立两点依据；沿用不更新源序号、不重新差分，过期留空。`zMovespeed` 是工艺速度设定值，不代替位置差分实测速度。

采集主机的来源时间、ABB 调度、缓存年龄、统一帧截止、启动边界和显示传输统一使用 `acquisition_clock.monotonic()`，其底层为 `time.perf_counter()`（Windows QPC）。不与 Python 3.11 的 `GetTickCount64` 读数相减；其他传感器只统一主机时间戳，协议、采样目标、换算与质量规则保持原合同。ABB 等待在截止前复核剩余时间，长等待可被停止事件唤醒，末段使用高精度短等待；慢轮次跳过，不补读。来源声明 `clock_domain=host_perf_counter`；墙钟仅用于离线对照，机器人内部采样时刻与延迟未知。helper 先在自身主机完成帧截止和年龄计算，服务器保留该来源与年龄，不用服务器接收时间重算速度或跨主机单调时差。主机接收到帧可用的耗时、网络传输和浏览器绘制是不同的可测边界，不能称为设备采样延迟。

每个位置来源保存白名单原始 XYZ、解析值、资源身份、收发墙钟/单调时间、源序号、连接代次和处理档；速度附前后位置、距离和实际间隔。来源在统一帧确定时固定，经 WebSocket、helper、CSV 时间戳侧车 `channel_source_record_json` 和 MySQL `afp_source_evidence` 的 `abb_frame` 关联到同一行，异步保存不读取更新后的驱动状态。会话清单记录测量档和算法；旧文件无需迁移，主列、单位及模型质量准入不变。helper 必须声明 `abb_measurement_contract=fibercontrol_abb_v1` 及 `abb_clock_domain=host_perf_counter`，缺少能力或有效来源时拒绝采集，不回退服务器设备。页面显示目标、年龄及速度依据，完整关联仅在授权诊断中查看。

ABB 保持 Digest、nonce 更新、Cookie/连接复用、禁系统代理、工业源地址绑定及核验；退出只释放本客户端会话。认证、资源、解析、数值、会话上限和通信故障保持明确错误，不用旧缓存通过检查。软件轨迹与保存回归不证明实物精度；双方控制器、坐标配置、原始响应、批准运动与容差缺失时，实物一致性及偏差根因均待验证。

管理员页面使用 `POST /api/acquisition/test` 执行当前配置的只读检查，使用 `POST /api/acquisition/start` 启动正式采集，使用 `GET /api/acquisition/status?acquisition_mode=real` 读取运行状态。本机 Helper 对外声明 `plc_abb_uvc_readiness_v1` 和 `unified_device_readiness_v1`；缺少该能力的 Helper 不能启动真实采集。检查响应中的每个接口都保留设备协议端点、独立物理绑定、原始最终状态码和以下显式阶段：`physical_binding`、`device_identity`、`driver`、`network_path`、`usb_binding`、`authentication`、`protocol`、`channels`、`freshness`、`stability`。

`data_ready` 表示设备身份、协议和全部必需通道均已取得有效新鲜数据；`partial_channels` 表示 PLC 或 ABB 只取得部分必需通道；`authentication_failed` 表示 ABB Digest 认证失败；`driver_incompatible`、`device_open_failed` 和 `no_valid_frame` 分别表示 UVC 驱动/API 不兼容、设备无法打开和未取得有效温度帧；`device_profile_incomplete` 表示批准设备档仍缺少正式检查所需事实。未知状态码继续按失败显示，不会转换为 `unchecked` 或通用未连接。

检查快照绑定协议端点、物理接口、非明文凭据标识、设备身份、驱动状态、设备档版本和当前运行修订。任一字段变化都会使旧快照立即失效，`/api/acquisition/start` 必须在当前配置重新检查成功后才可执行。UVC检查可按实时PnP实例、容器和父端口，经隔离子进程读取 `usbvideo` 的XU协议与流类型；`driver_diagnostics` 保留描述符、后端摘要、阶段和HRESULT。接口识别及XU读取成功不等于温度就绪，缺少适用固件的帧结构、换算和新鲜度依据时仍为 `device_profile_incomplete`。原生适配不自动设置量程，拒绝非法ROI和全零矩阵，计算不提前舍入。集成验收使用真实温度矩阵及ROI温度通道；普通视频和原始传输不能替代。无参考温度与允许误差时单独标注“精度未验收”。

本机和 Helper 的真实接口检查均返回 `readiness_snapshot`。同一后端会话内，仍匹配配置、身份及运行修订的有效检测可在正常停止后复用，不因一次成功启动而消耗，也不因空闲时间自动执行完整重检。外部导入凭证首次使用仍校验有效期；配置、标定、设备身份变化、故障、取消及后端重启使相应证据失效，不能从持久化配置恢复检测授权。每次开始仍真实打开设备并验证本轮数据，曲线就绪至少需要两次有效新源观测；同值新帧有效，保持与旧会话数据无效。异步启动提供编号、进度与取消，释放和保存未完成时不能开启下一次正式采集。

ESR1001-A数值分为 `CH1_ADC_signed～CH4_ADC_signed / adc_counts`、有效标定后的 `应变1～4 / με` 与独立的相对变化（ADC模式为 `CH1_ADC_relative～CH4_ADC_relative / adc_counts`，有效标定后为 `相对应变1～4 / με`）。厂商Config.xml通过接口行“只读导入厂商K/B候选”展示来源、SHA256、单位与参数；确认逐路已连接传感器、桥路、阻值、实际增益和标定依据后才能选择档案，随后明确选择微应变并重新检查，不应用厂商增益/速率/滤波等配置。示例K/B不能证明适用；未接、接线损坏或标定条件不全时继续ADC诊断，不以缺少标定判通信失败。

软件相对清零不减小真实波动或漂移。页面各路独立显示相对读数和近60秒新源观测趋势，缺口不连线，重新清零或代次变化重置窗口。软件相对清零默认关闭，显式操作只接受当前采集和连接代次最新有效四路源帧；停止、故障、重连或重启失效。原始ADC与绝对值保留，相对值不进入模型；零点ADC、换算值、源序号、时间、标定摘要和代次进入事件及源档案。CSV、时间戳侧车、MySQL `afp_source_evidence` 和Helper可靠传输保留可复算证据，Helper确认全部源帧后才完成收尾。源CSV回放使用同名JSON中的历史标定快照，不使用当前配置重解释。计算值保留精度，独立数字视图兼容厂商一位小数；未定义实际接线、标定、量程与参考输入时显示“缺少范围依据”，不对真实异常缩放、限幅、减均值、去趋势或自动清零。厂商界面/CSV约20ms刷新读取当前值，其行数不能当作新源帧数；不同时间的截图不能直接计算误差。

运行时每个设备由独立工作线程和通道缓存隔离。`waiting_first_sample` 表示设备已打开但尚未产生首个有效样本，`reconnecting` 表示该设备正在按有限退避重连，`stale` 表示缓存来源已超过设备档新鲜度且统一帧不再输出旧数值，`failed` 表示重连预算耗尽。一个设备断线不会阻塞其他设备的读取、状态查询或保存；恢复后只有带新来源序号的样本恢复为 `measured_new`。`stop_timed_out` 表示设备线程未在停止上限内退出，此时采集不得标记为已完成，也不得开始下一次正式采集。

“检查连接”会打开数据源并实际读取数据，逐通道报告是否收到有限数值。“开始采集”后，状态栏持续显示每个已选通道的接收计数和最近数据时延。保存文件只包含本次勾选并实际采集的传感器列；少选通道时，未勾选列不会以空字段写入。I-ModernTCN 仍只有在模型所需输入通道全部就绪时才运行。

Windows 下接口选择还会读取 USB Hub 拓扑。电脑原生 USB 与拓展坞 USB 2.x/SuperSpeed 伴随通道会规范化为同一个物理端口池；64 路热电偶、UVC 热像仪和 M3232 都显示这套完整 USB 端口，设备通信端点显示在父端口下。只有无法关联 USB 父级的真正主机原生 COM 才在 M3232 中单独分组。系统优先恢复已保存或手动选择，再匹配兼容设备并为三个 USB 角色分配不同空闲端口；PLC 与 ABB 可以共享网卡，但自动推荐只接受与目标同网段、实际源地址属于该接口且由 Windows 最佳路由选中的物理有线网卡。APIPA、WLAN、VPN、TUN、代理和回环接口只保留用于诊断，不会自动成为已验证工业绑定。网卡列表会把已确认的 ASIX 适配器显示为“拓展坞网口”。系统端口编号只用于诊断，不能推导插孔的左右顺序；没有兼容设备验证时不能开始真实采集。热电偶设备身份、协议和端口映射仍须按设备资料确认后才能解除发布门禁。拓扑不可用时保留旧的扁平接口发现结果。

“铺层证据形成进度”对已完成层显示该层预测状态、健康指标和窗口数；正在采集的层显示当前动态预测。新试样、工况或独立重复改变时证据从0层重新开始；证据区域可以整体隐藏并随时恢复。

## 自动保存格式

真实采集时可在界面选择保存根目录；留空时使用短路径 `D:\AFP_Capture`（可用环境变量或界面重新选择）。短路径用于避免新方案较长文件名触发Windows路径长度限制。可见文件夹不使用试样编号，新方案按工况、独立重复和四项工艺参数建立：

`C{工况}_R{独立重复}_F{初始压实力}_V{铺放速度}_A{PID角度}_T{温度设定}/`

旧方案继续使用`C{工况}_R{独立重复}_p{功率}_v{速度}_pr{压实力}/`。系统同时为每个物理试样生成不可重复的`capture_uuid`，写入原始数据、采集清单、摘要和MySQL关系；该编号不增加可见文件名长度。

目录内同时保留：

- `{工况、重复与工艺参数}_第{N}层.CSV`：当前层的独立数据。采集中先写入`.partial`工作文件，停止并关闭接口后再原子替换为正式CSV；
- `{工况、重复与工艺参数}_完整试样.CSV`：每次停止采集后扫描实际存在的层文件并按层号重新合并，通过临时文件校验后原子覆盖，不再假定固定5层；
- `采集记录/`：保存`当前试样会话.json`以及每层时间戳、采集清单和采集摘要。摘要包含实际采样率、最大采样间隔、通道覆盖率、文件大小和SHA-256；
- `历史版本/`：重复采集同一层时归档旧层和旧完整试样快照；相同工况、重复和参数再次从第1层开始时，自动归档整个上一试样，避免旧高层混入新试样；
- `specimen_layer_health.json`：相同试样、工况、独立重复、指标和模型下各层的最新健康证据，用于按实际铺层数构造试样状态。

正式层文件采用事务式替换：重采同一层或从第1层开始新试样时，上一份有效层和完整试样会一直保留到新采集至少产生一个有效数据点。若接口打开失败或停止时仍为0点，系统只归档本次`.partial`工作文件，不生成空层、不更新当前试样身份，也不写入MySQL。崩溃遗留的层文件和带时间戳工作文件会在下次启动时移入`历史版本/中断采集`。

为避免Windows长路径错误，工况文本会保留可读前缀并在超长时自动附加短哈希；如果用户选择的根目录本身过长，系统会在采集前给出明确提示。

原始CSV列顺序为：本次勾选的传感器列（按方案顺序）＋该方案固定的时间/工艺参数/身份字段；未勾选传感器列不会写入。

旧方案的固定字段为`cycle, file, root, p, v, pr, l, 试件`；新方案的固定字段为`时间、4个工艺参数、run_id、specimen_id、condition_id、replicate、layer_id`。

## 12类健康指标和4类模型

系统可实时构造：

- AFP响应指标：T-HI、C-HI、TC-HI；
- 预测残差指标：RFHI、PR-HI；
- 对比指标：PCA-SPE-HI、KECA-SPE-HI、McFS-AVAE-HI、CNN-LSTM-AE-HI、W-HI、RMD-HI及界面目录中的其余已登记指标。

每个指标可搭配逻辑回归、RBF-SVM、随机森林和极端随机树。界面推荐仅依据固定验证集选择分数；测试集结果不参与推荐。

### 新数据集下的12类指标重构

切换到`new_collection_v11_3`时，界面不会继续调用旧12通道候选模型，而是读取`models/new_collection_hi_artifacts.joblib`中的新目录。12类指标按16个实际传感器和4个工艺参数重构；历史工件中若仍包含转速、位移、振动，只作为训练期基线兼容列，不作为采集证据：

- `T-HI`：主温度、ROI平均温度与温度1–8的残差、偏置、均匀性和升降温动态；
- `C-HI`：压力、张力、压力峰值、压力冲量和接触持续比例；
- `TC-HI`：热响应、压实响应、热－压相关性与正常工艺流形距离；
- `RFHI`：实际可用通道按热、压实和运动分组后的预测残差及尾部残差；
- `PR-HI`：四项工艺参数到正常工艺流形的距离，以及热/压实/运动响应偏离；
- `MPRF-HI`：工艺参数、传感器响应和预测残差的多物理融合；
- `PCA-SPE-HI`、`KECA-SPE-HI`：正常训练窗口子空间和核原型距离；
- `McFS-AVAE-HI`、`CNN-LSTM-AE-HI`：多通道空间不一致和时序重构误差对比；
- `W-HI`、`RMD-HI`：健康分布Wasserstein距离和稳健马氏距离。

正常中心、尺度、PCA子空间、核原型、健康分位数和稳健协方差只由训练集正常窗口拟合；四种分类器只使用训练集；阈值及每项指标的推荐模型只使用验证集；内推和外推测试集不参与选择。重新生成48种组合及目录：


输出为`new_collection_hi_artifacts.joblib`、`new_collection_hi_catalog.csv`、`new_collection_hi_metrics.csv`和`new_collection_hi_summary.json`。当前模拟数据结果只用于软件联调；替换为真实采集数据后必须重新运行，不能把模拟准确率作为现场性能。

## MySQL分层保存与关系视图

MySQL为可选的事务同步层，不替代本地CSV/JSON原始档案。每次完成一层并确认本地文件全部保存成功后，系统才把该层数据批量同步到用户指定的数据库；连接或写入失败时生成`mysql_pending.json`，不删除本地数据，也不阻断下一层采集。以后同一数据库恢复且有新层成功停止保存时，程序会先按主机、端口、用户和数据库筛选，再补传最多20条属于当前目标库的历史待同步记录，避免其他数据库的大量待同步文件挤占本次补传名额；成功记录改为`mysql_synced.json`。

基础表包括`afp_condition`、`afp_specimen`、`afp_layer`、`afp_sensor_sample`、`afp_sample_all`和`afp_mysql_upload_log`。外键链为“工况→试样/独立重复→铺层→逐点样本”，常用筛选字段和组合查询字段均已建立索引。`afp_relation_map`用于在界面和Navicat中平面查看工况、试样、独立重复和铺层的对应关系；刷新关系表时使用界面当前选择的数据库，而不是固定数据库名。密码默认留空，只在本次连接内使用，不回传浏览器、不写入采集清单。

MySQL 的 64 路原始写入、派生查询、CSV 导出和训练导入仍需完成并通过值级对账；当前不得将补值或组均值写入原始 `sensor_json`。重试载荷按 `schema_id` 保留原始传感器键。

“预测距离当前时刻”同时支持滑块和数字框。数字框可直接输入1–600，按Enter、失焦或点击上下微调箭头后立即应用；实时轮询在数字框获得焦点时不会覆盖正在输入的值。

“使用优化预警”只对 TC-HI＋随机森林有效：

- 模拟采集模式复现原v13.8完整五层软Potts/CRF结果；
- 真实采集模式使用v13.9因果在线上下文融合；
- 第五层结束后，所有五层均已实际到达，此时因果方法切换到完整v13.8五层后验；
- 关闭选项后采用未经一致性优化的实时分类分数和CAP聚合。

锁定测试集上，v13.9窗口/层/试样平衡准确率分别为97.70%、95.00%和100%，对应七状态准确率为98.12%、91.43%和100%。原v13.8对应平衡准确率为98.85%、96.67%和100%。第一、二层结束时仅有很少证据，七状态准确率为5/7；从第三层开始为7/7，因此界面会把不足五层的试样状态视为动态早期判断，而不是最终结论。

## 数据和结论边界

- 模拟器用于验证采集、保存、预测和预警软件链路，不等同于物理传感器已联网。
- 通用串口/TCP JSON读取能力不能替代具体设备协议；64路热电偶的物理协议、帧校验和通道映射尚待设备资料确认，确认前保持真实采集发布门禁。
- 真实采集中的异常状态是模型对工艺/响应异常的判断；是否形成真实AFP缺陷仍需C扫、力学或其他独立检测证据确认。
- 1–24点预测是模型直接预测；更远步长是递归预测，距离越远误差累积风险越高。
# 原生训练中心

`training_center.py` 提供不依赖浏览器和 Flask 的训练链路：

1. `read_excel_or_folder()` 读取 Excel、CSV 文件或文件夹；`read_mysql()` 读取 MySQL 查询结果。
2. `guess_mapping()` 与 `normalize_frame()` 统一工况、试样、铺层、状态和传感器字段。
3. `validate_frame()` 检查缺失值、非有限值、试样—工况冲突和样本数量。
4. `write_manifest_dataset()` 生成试样隔离的 manifest 和分层数据文件。
5. `TrainingCenter.start_training()` 调用现有 I-ModernTCN 训练入口，再调用完整的 12 指标×4 分类器健康预警训练。
6. `trained_models/<时间戳>/` 保存 checkpoint、元数据、预警 artifact、阈值、数据划分和来源快照。

训练和回放均以 `schema_id` 为准。历史采集文件可完整导入，但预测张量只使用模型元数据声明且通过兼容验证的输入；`new_collection_v13_0` 当前没有兼容验证的预测模型，因此不运行预测，也不把 8 组均值交给旧模型。

命令行预检示例：

```powershell
python training_center_cli.py --demo --prepare-only --output trained_models
```

该模块可直接接入原生 PySide6 界面；训练过程通过回调返回 `data_imported`、`data_validated`、`split_ready`、`prediction_training_finished` 和 `training_finished` 事件。

ESR独立数值面板位于主工作区，聚焦选择只影响展示。四路原始值和诊断始终可展开查看，原始采集与保存不随聚焦选择改变。接口 `channel_settings.esr_context` 可记录现场申报的逐路型号、标称阻值、传感器桥路、连接/安装/加载状态、实际拨码核验状态与聚焦通道；此上下文贯通会话档案、质量侧车、Helper和MySQL源证据，只用于诊断，不作为标定或合理范围依据，不写设备参数。传感器灵敏系数不是ADC换算K，实际拨码未知时保持未核验。
