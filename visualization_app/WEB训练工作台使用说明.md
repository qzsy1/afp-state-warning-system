# AFP Web 模型训练工作台使用说明

访问地址：`http://127.0.0.1:8765/training.html`

## 一、数据模式

- **新数据**：只读取包含新采集方案 16 个传感器通道、4 个工况参数以及试样/铺层元数据的文件或 MySQL 记录；不符合格式的旧文件会被跳过。
- **旧数据**：只读取旧格式 12 个传感器通道、`p,v,pr` 工况列及旧试样字段；新格式文件会被跳过。
- **其它数据**：由用户用逗号填写“工况数据、模型输入数据、模型输出数据”。系统只接受同时包含这些列的数据。首次选择时默认填入新数据格式，可直接修改。

## 二、数据来源

1. **采集保存的 CSV 文件夹**：选择采集根目录或某个试样目录。系统递归读取各铺层文件，忽略完整试样快照、历史版本、时间戳和清单文件，避免重复。
2. **MySQL 数据库**：填写连接参数。切换新/旧数据模式时，查询框会自动换成对应 SQL：新模式从采样工艺 JSON 提取四个新工况参数，旧模式从试样参数 JSON 提取 `p、v、pr`，并分别按 `schema_id` 筛选。
3. **已整合的完整 CSV**：既可以选择先前训练任务输出的 `normalized_training_data.csv`，也可以选择只包含工况、输入和输出列的普通 CSV。普通 CSV 缯失的辅助列会自动生成：来源、模式、时间和样本序号可直接生成，工况编号由工况列组合，状态标签默认为未标注；试样、独立重复和铺层优先从已有别名列或文件名推断。所有补全依据都会显示在预检警告中。

点击“导入并预检”后，页面重点显示数据行数、工况种数、保留文件数和剔除文件数，同时在详细结果中显示试样数、铺层数、异常标签统计、被跳过文件和被剔除的不完整铺层。只有预检通过才能开始训练。

## 三、训练模式

- **只训练预测模型**：训练 I-ModernTCN，多通道输入并预测所选输出通道。
- **训练预测 + 预警模型**：先训练 I-ModernTCN，再以预测残差生成 MAE、RMSE、最大绝对残差、偏差和标准差特征，对比 Logistic、RBF-SVM、Random Forest、Extra Trees，按验证集平衡准确率保存最佳预警模型。数据必须包含 `state_label=0` 和 `state_label=1`。

选择“基于已有模型继续训练”时，必须选择模型文件。系统会读取模型旁的同名 `.json` 元数据，校验模型列、输入列、输出列、历史步长和预测步长；不一致时拒绝加载。

## 四、开始、结束与输出

点击“开始训练”后，按钮变为“结束并保存”。训练期间实时显示：

- 当前阶段；
- Epoch 当前值与总数；
- Patience 已占用值与上限；
- 训练损失、验证损失和最佳验证损失；
- 预测模型和预警模型训练日志。

点击“结束并保存”不会直接杀死进程，而是在当前批次完成后安全停止，并保存当前模型。默认输出位置为 `F:\AFP_Training_Models`，也可选择其它绝对路径。

每个训练任务输出：

- `normalized_training_data.csv`：CSV/MySQL 统一后的完整数据；
- `specimen_split_manifest.csv`：试样级数据划分，防止同一试样跨集合；
- `prediction_model_best.pth` 及同名 `.json`：最佳预测模型与通道/标准化元数据；
- `prediction_training_resume.pth`：包含当前模型和优化器状态的继续训练检查点；
- `training_history.csv`：逐 Epoch 损失与 Patience；
- `training_config.json`：本次数据定义与训练参数；
- `data_validation_report.json`：导入预检报告；
- `warning_model.joblib`、`warning_metrics.json`：选择预测预警模式时生成。

## 五、重要边界

- 没有正常/异常标签的真实采集数据可以训练预测模型，但不能据此监督训练预警分类器。
- `specimen_id、replicate、layer_id` 虽然不进入模型张量，但用于窗口分组和防止同一试样跨训练/验证集。缺失时系统只做保守推断；如果最终只有一个独立试样，仍需增加数据后才能训练。
- 预警模型的验证平衡准确率只代表当前数据划分上的模型选择结果，不等同于真实缺陷诊断准确率。
- 采集中断且不足“历史步长 + 预测步长”的铺层会被剔除并明确报告，不进入训练。

## 六、MySQL工况与试样身份

新采集数据不再使用界面显示用的 `LIVE/H06` 作为数据库唯一身份。工况键和试样主键由实际工艺参数生成：

- 旧数据工况键：`legacy_original|p功率_v速度_pr压实力`；
- 新数据工况键：`new_collection_v11_3|F初始压实力_V铺放速度_A角度_T设定温度`；
- 试样主键：`工况键|试样名|R独立重复数`。

因此，只要实际工况、试样名或独立重复数任一不同，MySQL 就会保存成不同试样。同一主键、同一铺层再次保存时，会先删除旧采样点再写入完整新序列，避免较短的新记录留下旧记录尾部。
