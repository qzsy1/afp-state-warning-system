# AFP 采集数据 MySQL 保存说明

## 保存时机

系统先将当前铺层完整写入本地 CSV、时间戳文件和采集摘要；停止并保存成功后，才执行一次 MySQL 事务写入。数据库异常不会中断采集。

同一物理试样使用系统生成的`capture_uuid`，再结合工艺参数条件和独立重复构造稳定主键。相同试样的各层共用同一个`capture_uuid`；从第1层开始采集新试样时自动生成新编号。再次保存同一层时使用主键幂等更新，不会产生重复采样点。后续层会更新试样的层数和完整试样文件路径。

## 界面设置

在“真实采集与保存”中填写主机、端口、用户名、密码和数据库名称，然后点击“测试远程连接”。主机既可填写本机 `127.0.0.1`，也可填写数据库电脑的固定局域网 IP、VPN 地址或域名。测试只检查连接和既有表结构，不会自动执行建库、建表或修改权限；首次使用空数据库时，应使用有建库建表权限的管理员账号点击一次“初始化表结构”，完成后切换为权限较小的日常账号。数据库名称只能包含字母、数字和下划线，且必须以字母开头。

界面提供两个互相独立的保存开关：“保存到打开软件这台电脑的 MySQL”和“保存到目标电脑 MySQL”。可以只启用其中一个，也可以同时启用；同时启用时，同一份完整铺层会分别用事务写入两个数据库，一个目标失败不会阻止另一个目标保存。本机默认地址为 `127.0.0.1`，目标电脑默认地址为当前统一服务器 `192.168.101.31`，两组地址、账号和数据库名称都可以修改。

目标数据库参数同时用于 MySQL 模拟采集、关系查看、远程 CSV 导出和模型训练读取。只有真实密码不写入源码，而是从软件目录的 `runtime/mysql.local.json` 读取本机专属默认值；该文件不进入 Git 或模块更新包。只有勾选对应保存开关才会在停止并保存铺层时上传；查看、导出和训练读取不要求勾选保存开关。

## 另一台电脑作为统一数据库

推荐把一台电脑作为固定 MySQL 服务器，采集电脑仅作为客户端：

1. 数据库电脑使用固定局域网 IP；跨网络时优先使用组网 VPN，不要把 3306 直接暴露到公网。
2. MySQL 的 `bind-address` 不能只绑定 `127.0.0.1`，应由数据库管理员改为服务器局域网地址或合适的监听范围并重启 MySQL。
3. Windows 防火墙仅允许采集电脑或 VPN 网段访问 TCP 3306。
4. 先以管理员账号初始化表结构，再创建 `afp_app` 日常写入账号和 `afp_reader` 只读查看账号。参考同目录的 `REMOTE_MYSQL_SETUP.sql.example`，替换其中的客户端地址和强密码后由管理员执行。
5. 采集电脑在“主机”中填写数据库电脑 IP，点击“测试远程连接”；成功后再开始正式采集。

原生软件的“目标电脑 MySQL”区域还提供“生成目标授权 SQL”按钮。填写目标数据库、日常用户名、密码和允许客户端主机后，先在数据库服务器上执行该脚本，再由采集电脑测试连接。数据库名称、账号和密码不是同一个概念；本机 `root` 不能替代远程 `afp_app`。

软件仍采用“本地 CSV 优先、完整铺层结束后事务上传”的策略，不会逐采样点依赖网络。网络中断时采集继续，本地生成 `mysql_pending.json`；恢复后可点击“立即补传待同步数据”。因此另一台电脑看到的是已经完整保存的铺层，不是尚未完成铺层的每个实时采样点。

## 远程查看、复制与下载

- “查看工况—试样—铺层”按工况、试样、独立重复和铺层显示关系，可自动刷新并按当前条件导出。
- “导出远程数据 CSV”从数据库数据重建可训练 CSV，不依赖数据库电脑能否访问采集电脑保存的 `F:\...` 本地路径。
- 网页版的“远程数据查看与下载”只允许单条 `SELECT` 或 `WITH ... SELECT` 查询，禁止删除、更新、建表、写服务器文件和多条 SQL；预览可复制到 Excel，也可下载 CSV。
- 日常账号仍应依靠 MySQL 权限限制为最终安全边界，不应把管理员账号长期留在采集软件中。

## 数据表

- `afp_condition`：工况和工艺参数；
- `afp_specimen`：试样、工况、独立重复和工艺参数；
- `afp_layer`：每个铺层的文件路径、采样点数和采集摘要；
- `afp_sensor_sample`：每个采样点的传感器 JSON 和工艺参数 JSON；
- `afp_sample_all`：保留全部采样点的总表，便于统一分析；
- `afp_mysql_upload_log`：每次写入的结果和错误信息。

系统同时创建 `afp_view_condition`、`afp_view_specimen` 和 `afp_view_layer`，用于按工况、试样/独立重复和铺层快速查询。

## Navicat 查看方法

1. 新建 MySQL 连接：本机数据库填写 `127.0.0.1`；远程数据库填写数据库电脑 IP，端口通常为 `3306`，用户名和密码使用数据库管理员创建的账号。
2. 打开连接后刷新数据库，展开 `afp_state_warning`。
3. 在“表”中查看 `afp_condition`、`afp_specimen`、`afp_layer` 和 `afp_sample_all`。
4. 在“视图”中查看 `afp_view_condition`、`afp_view_specimen` 和 `afp_view_layer`。
5. 右键表或视图，选择“打开表”即可查看数据；也可以打开查询窗口执行：

```sql
SELECT * FROM afp_view_condition;
SELECT * FROM afp_view_specimen;
SELECT * FROM afp_view_layer
WHERE condition_id = 'H01' AND replicate_no = 1
ORDER BY layer_no;
SELECT * FROM afp_sample_all
WHERE specimen_key = '数据方案|试样名|H01|1|H01'
  AND layer_no = 1
ORDER BY sample_index;
```

系统会自动建立工况、试样、铺层、时间和同步日志索引；数据库初始化可重复执行，不会重复创建索引。

`afp_flat_all` 是面向查看和分析的平面视图，每一行同时显示工况、方案、试样、独立重复、铺层、采样点和传感器数据。它不复制数据，只是通过外键关系实时组合查询。

系统维护以下外键关系：

```text
afp_condition.condition_id
        ↓
afp_specimen.condition_id
        ↓ specimen_key
afp_layer.specimen_key
        ↓ specimen_key + layer_no
afp_sample_all / afp_sensor_sample
```

在 Navicat 中可以打开“设计表”或“对象关系图”查看这些外键。打开 `afp_flat_all` 则无需手动 JOIN 即可直接查看完整关系数据。

原始 CSV 仍然保留，MySQL 用于实时查询、状态分析和后续统计，不替代原始文件。

## 依赖

安装 `requirements.txt` 中的 `mysql-connector-python`。如果数据库暂时不可用，系统会在采集记录目录生成`mysql_pending.json`，同时保留全部本地数据。以后同一主机、端口、用户和数据库恢复且完成新一层保存时，程序先排除其他目标数据库的待同步文件，再补传最多20条属于当前数据库的记录；补传成功后改为`mysql_synced.json`，其中保留补传时间和写入结果。0点或没有有效传感器数据的采集不会生成待同步记录。
