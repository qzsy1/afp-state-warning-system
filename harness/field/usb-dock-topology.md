# USB 设备归属与拓展坞拓扑现场验收

该项只接受当前提交、当前 v2.0.4 发行目录、真实 Windows 电脑、普通 USB Hub 和真实拓展坞的现场结果。模拟数据、静态夹具或服务器电脑接口不能代替实物证据。

## 准备

- 连接目标拓展坞，确认实物规格为三个 USB 3.0 外部接口和一个网口。
- 网口使用 ASIX AX88179B/AX88179 系列控制器时，保持网线连接或至少保持适配器在 Windows 中启用。
- 准备一个 Windows 能稳定识别的 USB 2.0 或 USB 3.x 设备，用于依次插入三个外部接口。
- 准备一个只有 Hub 功能的普通外接 USB Hub；若现场没有该设备，结果必须保持待验证。
- 准备另一台主机控制器或主板型号不同的 Windows 电脑，用于验证分类不依赖第一台电脑的 Root Hub 和 Location Path；若现场没有第二台电脑，结果必须保持待验证。
- 记录 Git commit、v2.0.4 `VERSION.json`、主程序/helper 哈希、两台电脑的型号和 Windows 版本。

## 验收步骤

1. 运行 `harness\checks\usb-dock-topology-contracts.cmd`，确认自动拓扑、设备归属与界面契约通过。
2. 启动 v2.0.4，进入真实采集接口配置并刷新接口。
3. 确认“电脑本机 USB-A”只显示两个空闲端口；不得把两个 Type-C、Root Hub 中未布线或预留的空逻辑端口计入该分组。
4. 确认连接拓展坞的 Type-C 仅保留为拓扑中的 `dock_upstream`，不出现在三个 USB 传感器的候选列表；拓展坞下游三个 USB-A 另行显示在拓展坞分组中。
5. 确认两个空闲 USB-A 分别来自系统提供的 USB2/SuperSpeed 伴随连接器组；没有历史观察记录时 `confirmation=connector_metadata`。插入再拔出测试设备后，同一端口 ID 可使用 `observed_current`/`observed_history` 保持可见。
6. 确认页面只显示一个逻辑拓展坞，拓展坞分组内恰好显示三个用户可连接 USB 端口。
7. 确认 USB 2.x 与 SuperSpeed 伴随 Hub 没有把三个物理接口重复显示成六个。
8. 确认 ASIX 适配器显示为“拓展坞网口”，并且其内部连接没有显示为第四个外部 USB 口。
9. 为 USB HID 和 UVC 类型分别打开实际接口选择，确认三个 USB 端口全部出现，并显示空闲、占用、设备名称或异常状态。
10. 分别打开热电偶、UVC 和 M3232 的接口选择，确认三者显示相同的完整 USB 物理端口集合，包含两个电脑原生接口和三个拓展坞接口。
11. 若 USB 转串口设备生成 COM 端点，确认它显示在所属 USB 物理端口下；只有无法关联 USB 父级的真正主机原生 COM 才显示在独立串口组。
12. 确认热电偶、UVC 和 M3232 已默认选择不同 USB 端口；PLC 与 ABB 已默认选择网卡且允许共享。
13. 手动更换一个 USB 角色的端口后刷新，确认选择不迁移；拔出设备时保留端口并清除实时端点与验证状态。
14. 选择空闲 USB 端口，确认页面显示“端口存在，未检测到兼容设备”，并且真实采集不能通过接口检查。
15. 在所选物理端口尚未验证时点击“立即检查”，确认软件仍逐项打开热电偶、UVC、M3232、PLC 和 ABB 的原驱动并读取所选通道；若驱动收到数据但端口关联未确认，应显示“数据已读，物理端口未验证”并继续阻止真实采集。
16. 将测试 USB 设备依次插入三个拓展坞接口，每次刷新并记录系统端口号、状态和所接设备；三个物理位置必须分别映射为三个稳定逻辑端口。
17. 拔出测试设备，确认端口恢复空闲、实时设备验证被清除，但端口预选仍保留。
18. 断开并重新连接拓展坞到电脑原 USB 位置，确认三个端口 ID 恢复且没有自动绑定到其他拓展坞。
19. 在已配对 helper 的授权远程真实模式中重复刷新，确认展示的是访问电脑拓展坞；断开 helper 后不得回退显示服务器硬件。
20. 进入访客预计算模拟模式，确认响应和页面不显示拓展坞实例、设备标识或底层位置路径。
21. 在未连接任何外接 Hub 或拓展坞时刷新接口，确认电脑内部的非 Root Hub 不生成 `docks[]` 记录；经过物理证据确认的机身接口归入 `owner_kind=host`。
22. 连接只有 Hub 功能的普通外接 USB Hub，确认其显示为“USB 集线器”或“USB 扩展设备”，端口仍可选择，但页面、接口响应和网卡标签均不得把它称为拓展坞。
23. 分别保存电脑本体、普通 Hub 和目标拓展坞的 `classification_evidence`；已确认拓展坞必须同时包含外接性证据与拓展坞角色证据，VID/PID、名称或端口数量不得单独作为结论。
24. 在第二台 Windows 电脑上重复无外设、普通 Hub 和目标拓展坞检查；主机控制器、Root Hub 与 Location Path 可以变化，但 `host`、`hub`、`dock` 分类结论必须一致。

## 必须保存的证据

- 两台电脑接口发现响应中去敏后的 `usb_topology`，包含 schema v2、`docks[]`、`hubs[]`、端口归属、分类证据、目标拓展坞三个外部端口和内部网卡关系。
- 页面中拓展坞 USB 分组、三个端口状态及拓展坞网口的截图。
- 无外设与普通 Hub 场景的页面截图，证明电脑内部 Hub 和普通外接 Hub 均未使用拓展坞标签。
- 两个电脑本机 USB-A 端口、Type-C 拓展坞上游排除结果，以及端口物理证据和 `confirmation` 的对照结果。
- 三个 USB 口逐口插拔前后的端口 ID 对照表。
- 拓展坞断开、重连和 helper 断开时的状态结果。
- 两台电脑之间分类结论对照表；主机相关路径只保存去敏摘要。
- 自动检查日志、当前 commit 和 v2.0.4 哈希结果。

不得在证据中保存 Token、数据库密码、内核设备符号链接或未经去敏的设备路径。
